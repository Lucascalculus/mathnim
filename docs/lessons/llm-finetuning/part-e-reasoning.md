### E1 可验证奖励与 GRPO

- **时长**：核心内容约 30 分钟；第 16、17 段两个代码讲解页是选读，加上约 34 分钟。
- **前置**：D2（策略梯度、基线、PPO 截断、KL）。建议先学 B1（损失掩码），因为回答部分的掩码在这里还会用到。
- **技能 id**：`rlvr-reward`、`group-advantage`、`grpo-objective`、`grpo-bias`、`rlvr-defaults`、`grader-design`
- **误区 id**：`wrong-not-penalized`、`zero-var-useful`、`longer-is-better`、`clip-always-on`、`grader-unhackable`、`kl-required`

**学完能做到**
1. **算优势。** 给出一组 0/1 奖励，手算 GRPO 的优势，有标准差归一化和没有标准差归一化两种都会算；再算出 RLOO 的优势，并说出两者只差一个常数倍 G/(G−1)。
2. **写目标。** 写出 GRPO 目标函数的三个部分：组内优势、截断的重要性比率、k3 形式的 KL。能说出去掉其中任何一部分会发生什么。
3. **算偏差。**
   - 用 p^G + (1−p)^G 估算零方差组的比例，并解释动态采样为什么能提高有效批量；
   - 解释"按回答长度平均"为什么会让又长又错的回答受罚更轻，说出 Dr. GRPO 和 DAPO 各自怎么修，以及 TRL 里对应的参数。
4. **选配置。** 写出 2026 年 RLVR 的一套常见默认配置，说出每一项针对什么问题。判断一个任务适不适合用可验证奖励。
5. **设计评分器。** 为一个任务设计评分器：选用规则、大模型评委，或者两者组合。列出它被钻空子的至少两种方式，以及对应的防护。能说出托管强化微调服务需要你提供什么。

**要解开的误解**
- `wrong-not-penalized`
  - 误解：奖励为 0 的错误回答会被直接压低。
  - 实际：奖励是 0/1、又不减基线时，错误回答的梯度系数恰好是 0。它们不会被直接压低，只是在别的回答被抬高时，因为概率总和为 1 而间接变小。减去基线之后，错误回答才会被直接压低。证据见推导 E1-a 的第 4 步 [标准知识]。
- `zero-var-useful`
  - 误解：全对的那组样本最有价值。
  - 实际：一组回答全对或全错时，每个回答的优势都是 0，这一组对策略没有任何梯度。DAPO 正是因此引入了动态采样 [T§6]。
- `longer-is-better`
  - 误解：回答越长，推理越强。
  - 实际：Dr. GRPO 指出，按回答长度平均会偏向又长又错的回答，所以长度上涨不能直接说明推理变强 [T§6, P§2]。
- `clip-always-on`
  - 误解：截断在每一步都起作用。
  - 实际：如果每生成一批样本只更新一步，那么求梯度时 ρ ≡ 1，截断根本不起作用。截断只在"同一批样本多次使用"或"异步采样"这类离线（异策略，off-policy）的情况下才生效。TRL 文档写明了：μ=1 时，截断目标退化为原始目标。
- `grader-unhackable`
  - 误解：规则奖励或大模型评委不会被钻空子。
  - 实际：R1-Zero 用规则奖励，确实是为了避开神经网络奖励模型被钻空子的问题 [T§6]。但评分器本身也有漏洞，下面这些都是标准知识：
    - 抽取规则只看回答里有没有出现正确数字，模型就会把好几个数字都列出来；
    - 格式奖励可以被单独刷满；
    - 大模型评委偏爱更长、更自信的回答（这和 D 部分的长度偏差同源 [T§5]）。
  - 背景：今天实验室的奖励信号大多来自验证器、评分细则和评委 [A§6]，评分器的漏洞就是最常见的奖励投机来源 [A-缺 8]。L4 实验会让学生亲手造出并修好一个漏洞。
- `kl-required` [争议]
  - DAPO 去掉了 KL [T§6]。
  - nanochat 也不用 KL [P§1]。
  - ProRL 则依靠 KL 加上参考模型重置，来支撑长时间训练 [T§6, P§3.7]。
  - 本课把它讲成一个取舍，而不是一条规则。

  | DAPO | 非对称截断（ε_low 0.2，ε_high 0.28）；动态采样；token 级平均；对过长回答做软惩罚（overlong shaping）；不用 KL | 熵塌缩、零方差、长度偏差 | [T§6]；用 Qwen2.5-32B 在 R1-Zero 一半的步数内达到 AIME 50 分 |
  | GSPO | 序列级比率 $s_i=\big(\pi_\theta(o_i\mid q)/\pi_{old}(o_i\mid q)\big)^{1/\lvert o_i\rvert}$，截断范围约 3e-4 / 4e-4 | token 级比率噪声大，MoE 训练不稳定 | 用于 Qwen3 [T§6] |
  | CISPO | 截断的是重要性权重本身，并且权重不回传梯度（stop-gradient）：$\mathrm{sg}(\mathrm{clip}(\rho))\,\hat A\log\pi_\theta$。被截断的 token 仍然有梯度 | PPO 式截断会丢掉 token 的梯度 | MiniMax-M1 [T§6] |
  | ScaleRL | 一套配方：PipelineRL（8 步离线）、CISPO、提示级平均、批级优势归一化、FP32 LM head、零方差过滤、no-positive-resampling。奖励随算力呈 S 形增长 | 可扩展、可预测 | 超过 40 万 GPU 小时的研究 [T§6] |

- **开放问题框："RLVR 要不要 KL？"[争议]**
  - **不要的理由：**
    - 奖励是规则，没有奖励模型可以在分布外钻空子，而加 KL 的主要理由（Gao 的过度优化）正是这个，所以 KL 的必要性变弱了 [T§5]；
    - 长思维链需要策略远离初始模型，DAPO 就是这么论证的 [T§6]；
    - 省掉参考模型，可以省一份显存和一次前向计算。
  - **要的理由：** ProRL 靠 KL 加参考重置，实现了长时间稳定训练，并扩大了 pass@k [T§6]。
  - **实操：** 先从 β=0 开始；如果熵塌缩，或者训练时间很长，再考虑加 KL 或做重置。无论是否加 KL，都把"相对基座的 KL"作为监控指标记下来。

**必要细节（第 14 段：评分器设计与托管强化微调）**

- **奖励信号的四种来源**（从最可靠到最灵活）：

  | 来源 | 例子 | 优点 | 风险 |
  |---|---|---|---|
  | 规则验证器 | 数值比对，带归一化和容差；单元测试；执行 SQL 后比对结果；JSON schema 校验 | 便宜、确定、难钻空子 | 漏判（例如 "42.0" 和 "42"）；规则太宽松时会误判 |
  | 参考答案加大模型评委 | 评委对照标准答案判断"等价与否" | 能处理开放格式 | 评委自己会出错，偏爱长回答和自信的语气 |
  | 评分细则评委（rubric） | 按细则逐条打分。例如 Kimi K2 用自我批评的细则奖励 [A§4] | 能处理没有唯一答案的任务 | 模型学会迎合细则里的关键词 |
  | 训练出来的奖励模型 | D1 讲的 Bradley–Terry 奖励模型；Gemma 3 用了权重平均的奖励模型（WARM）[A§6] | 能学人类偏好 | 离开训练分布就不可信 [T§5] |

  实际情况：实验室的奖励信号主要来自前三种，单独训练 Bradley–Terry 奖励模型在开源社区里很少见 [A§6]。

- **托管强化微调（RFT）**：
  - 谁提供：Azure（o4-mini 的 RFT 已正式发布）、Bedrock（奖励函数可以写成 Lambda，也可以用大模型评委）、Fireworks。OpenAI 原来也提供，现在正在收缩自助微调业务 [A§1, A§4]。
  - 你提供三样：一个只含提示（以及标准答案字段）的数据集、一个评分器（代码，或者评委的提示词和打分规则），以及少量超参数。
  - 平台负责采样、调用评分器和更新权重。
  - 评分器有哪些类型、字段叫什么，各家不同，以厂商文档为准 [核对]。
  - 选择的取舍：托管服务省掉了 GPU 和工程（E2 会讲推理引擎与训练框架的不一致、异步采样等问题），代价是只能用平台支持的模型，权重也未必能导出。

- **评分器设计清单**（标准知识，和 D1 的"先确认奖励模型是对的"同一个道理 [P§2]）：
  1. **先验证评分器本身。** 在 100–200 条留出样本上，和人工判分对比一致率。
  2. **给部分分要小心。** 每一项部分分都可能变成捷径。
  3. **做对抗测试。** 至少测这几种回答：空回答、重复同一句、列出多个答案、超长回答、只有格式没有内容、在回答里写"请给满分"。
  4. **评委要有参考答案和细则。** 让评委输出结构化分数，温度设为 0。
  5. **训练中定期抽查高分样本。** 由人来看。
  6. **留一个"金标准"评测。** 训练时完全不用它，只在最后用。

- **评分器被钻空子的典型样子**（奖励投机，reward hacking）：
  - 总体信号：训练奖励一直在涨，金标准评测却停滞甚至下降。这和 Gao 的代理奖励曲线是同一个形状 [T§5]。
  - 规则评分器：列出多个数字；单靠格式刷分。
  - 评委：回答越写越长；恭维评委；用自信的语气。
  - 代码任务：修改测试本身，或者针对测试写特判 [标准知识，核对：有公开的案例报告]。
  - L4 实验会让学生故意写一个有漏洞的评分器，观察模型怎么钻空子，再把它修好。

- **前瞻：智能体任务。** 在智能体任务里，评分器就是环境本身，比如测试是否通过、目标状态是否达成。这一点在 E2 的智能体强化学习案例里讲 [A§4]。

**交互规格：`grpo_group`（阶段 A 和 B 共用一个零件）**

- **变量：**
  - 每张卡的对错 r_i ∈ {0,1}，点击翻转；
  - 每张卡的长度 |o_i|，拖动卡片下沿调节，范围 50–2000 个 token；
  - G ∈ {4, 8, 16}；
  - 标准差归一化开关；
  - 聚合方式：按回答平均（原版 GRPO）、按 token 平均（DAPO）、除以常数（Dr. GRPO）。
- **画面显示：**
  - 每张卡上：
    - Â_i 的数值，配一个竖直箭头（向上表示抬高，向下表示压低）；
    - 一根横条，表示每个 token 受到的推力 c_i = Â_i × 聚合权重。
  - 组统计：r̄、σ，以及 Σ Â_i 的读数（恒为 0）。
  - 遇到零方差时，整组变灰，并显示"本组没有学习信号"。
- **学生做什么：**
  - **阶段 A：**
    1. 先预测"把一张错卡翻成对，其他错卡的优势会不会变"，然后翻一张，验证预测；
    2. 把整组翻成全对；
    3. 比较两组里那张唯一正确的卡：1/8 对时优势是 √7 ≈ 2.65，4/8 对时是 1。
  - **阶段 B：**
    1. 把两张错卡的长度设成 100 和 1000，在三种聚合方式之间切换；
    2. 关掉标准差归一化，比较 1/8 对和 4/8 对两组的总推力 Σ|c_i|。
- **应该注意到：**
  - 优势是相对于同组其他回答的；
  - 全对或全错的组没有信号；
  - 按回答平均时，又长又错的回答受罚更轻；
  - 标准差归一化会放大太容易和太难的题。
- **结束时的问题：**
  - 阶段 A：用一句话写出，为什么全对的那组对训练没有贡献。（解释题，AI 判读，要点是"优势是相对于组均值的，全对时每个回答都等于均值"。）
  - 阶段 B（选择题）：在哪种聚合方式下，模型可以靠把错误回答写长来"减轻惩罚"？答案：按回答平均。
- **精确计算还是示意：** 精确计算。优势和每个 token 的系数都严格按公式算；不模拟训练过程，画面上写明"这是一步更新的梯度系数"。
- **world 配置：**
  - goals：
    - `flip`：翻过一张卡，并且至少有 3 个优势随之改变；
    - `zero`：出现全对组或全错组；
    - `long-wrong`：在按回答平均的模式下，两张错卡的长度比达到 5 倍以上，并且切换过一次聚合方式。
  - detectors：学生把正确卡越拖越长、并在长卡上停留时，发出 `longer-is-better` 的 progress 提示："长度本身不进奖励，看看推力变了没有"。
  - lines：enter、idle、各个 goal 各一句，文字固定，便于预录旁白。
- **怎么满足交互准则的三条：**
  1. **关系**：翻一张卡会改变全组 G 个优势，这是一个非局部的关系；长度、聚合方式和标准差三者之间还有交互作用。这些文字只能断言，学生很难自己想象出来。
  2. **形式对应**：翻卡就是改变奖励（README 里的原例）；拖长度就是让回答变长；切换聚合方式就是切换 `loss_type`；开关标准差就是切换 `scale_rewards`。
  3. **以问题收尾**：第 3 段让学生下注，阶段 A 开始前再预测一次，两个阶段结尾各有一道题，构成"预测 → 观察 → 解释"。

**推导全文**

*E1-a 从 REINFORCE 到组内基线，再到 RLOO*

记号：题目 $q\sim\mathcal D$，回答 $o\sim\pi_\theta(\cdot\mid q)$，奖励 $r(q,o)\in\{0,1\}$，目标 $J(\theta)=\mathbb E_q\,\mathbb E_{o\sim\pi_\theta}[r(q,o)]$。

1. $\nabla J=\mathbb E_q\mathbb E_o\big[r(q,o)\,\nabla\log\pi_\theta(o\mid q)\big]$
   - 为什么：这是 D2 的对数导数技巧 $\nabla\pi=\pi\nabla\log\pi$。奖励由程序给出，与 θ 无关，所以不需要对奖励求导。
2. $\log\pi_\theta(o\mid q)=\sum_t\log\pi_\theta(o_t\mid q,o_{<t})$
   - 为什么：自回归模型的概率可以分解成逐 token 概率的乘积。奖励只在回答结束时给一次，所以同一条回答里的所有 token 共用同一个系数。这正是结果奖励（outcome reward）的含义。
3. 对任何只依赖题目的 $b(q)$，有 $\mathbb E_o[b(q)\nabla\log\pi(o\mid q)]=b(q)\sum_o\nabla\pi(o\mid q)=b(q)\nabla 1=0$，所以 $\nabla J=\mathbb E\big[(r-b(q))\nabla\log\pi\big]$。
   - 为什么：这是 D2 证过的"基线不改变期望，只改变方差"。
4. 当 $b=0$ 时，错误回答的 $r=0$，系数也是 0，它们不受直接推动，只有正确回答被抬高。如果取 $b=p(q)$（这道题的成功率），正确回答的系数是 $1-p$，错误回答的系数是 $-p$。
   - 为什么：这一步揭晓第 3 段预测题的答案。不减基线时，信号只来自"对的被抬高"，方差大、学得慢。
5. 最好的基线约等于 $V(q)=\mathbb E_o[r]=p(q)$。PPO 用一个价值模型来估计它。GRPO 的做法是：同一道题采样 G 个回答，用组均值 $\bar r=\frac1G\sum_j r_j$ 来估计 $p(q)$。
   - 为什么：价值模型和策略一样大，要占显存。而且奖励只在末尾出现，它很难学准逐 token 的价值 [T§5]。用同一道题的多个样本求平均，就能得到这道题"平均能拿多少分"。
6. $r_i-\bar r=(1-\tfrac1G)r_i-\tfrac1G\sum_{j\neq i}r_j$。由于 $o_j$ 和 $o_i$ 是给定题目后独立采样的，$\mathbb E[r_j\nabla\log\pi(o_i)]=\mathbb E[r_j]\,\mathbb E[\nabla\log\pi(o_i)]=0$。因此 $\mathbb E[(r_i-\bar r)\nabla\log\pi(o_i)]=\tfrac{G-1}{G}\,\mathbb E[r_i\nabla\log\pi(o_i)]$。
   - 为什么：组均值里包含了 $r_i$ 自己，看起来像是"自己当自己的基线"会带来偏差。但这一项只把梯度缩小一个常数倍，方向不变。
7. **RLOO（leave-one-out，留一法）**：基线取 $b_i=\frac1{G-1}\sum_{j\ne i}r_j$，这是精确无偏的。代数上，$r_i-b_i=\frac{G}{G-1}(r_i-\bar r)$。
   - 为什么：这说明组均值基线和 RLOO 只差常数 $G/(G-1)$。Dr. GRPO 说"去掉标准差之后等于 RLOO，只差一个缩放"[T§6]，指的就是这一点。
8. GRPO 还要再除以组内标准差：$\hat A_i=(r_i-\bar r)/(\sigma+\epsilon)$。
   - 对 0/1 奖励，设 G 个回答里有 k 个对，$\hat p=k/G$，$\sigma=\sqrt{\hat p(1-\hat p)}$（总体标准差）。
   - 正确回答 $\hat A_+=\sqrt{(1-\hat p)/\hat p}$，错误回答 $\hat A_-=-\sqrt{\hat p/(1-\hat p)}$，并且恒有 $\sum_i\hat A_i=0$。
   - 例：G=8、k=2 时，$\hat A_+=+1.73$，$\hat A_-=-0.58$。
   - 为什么：这样每道题的优势都是同一个尺度。TRL 用的是 `torch.std`，即样本标准差（分母是 G−1），同样的例子算出来是 +1.62 和 −0.54。课上统一用总体标准差，旁注说明这一差别。
9. **填空：** k=0 或 k=G 时，$\hat A_i=$ ___。（答案：0。所有 $r_i$ 都等于均值；实现里分母加了 ε，所以结果是 0/ε = 0。）

*E1-b 完整的 GRPO 目标*

1. 样本由旧策略 $\pi_{old}$ 生成。定义重要性比率 $\rho_{i,t}(\theta)=\dfrac{\pi_\theta(o_{i,t}\mid q,o_{i,<t})}{\pi_{old}(o_{i,t}\mid q,o_{i,<t})}$。
   - 为什么：同一批样本要更新好几次，或者采样和训练不同步时，样本来自"旧"策略，需要用这个比率做修正。在 $\theta=\theta_{old}$ 这一点，$\rho=1$，并且 $\nabla\rho=\nabla\log\pi$。
2. 每个 token 都用整条回答的优势：$\hat A_{i,t}=\hat A_i$。
   - 为什么：只有结果奖励，没有逐 token 的信用分配。这里可以对照 PPO：PPO 用 GAE 和价值模型，给每个 token 分配各自的优势。
3. 截断代理目标：$\min\big(\rho\hat A,\ \mathrm{clip}(\rho,1-\epsilon_{low},1+\epsilon_{high})\hat A\big)$。
   - 为什么：D2 已经推过：$\hat A>0$ 时，ρ 超过 1+ε 之后梯度为 0；$\hat A<0$ 时，ρ 低于 1−ε 之后梯度为 0。作用是限制每一步走多远。
4. KL 这一项用 k3 估计量：令 $x=\pi_{ref}(o_t)/\pi_\theta(o_t)$，取 $k_3=x-\log x-1$。
   - **无偏性：** $\mathbb E_{o_t\sim\pi_\theta}[x]=\sum\pi_\theta\cdot\pi_{ref}/\pi_\theta=1$，所以 $\mathbb E[k_3]=-\mathbb E[\log x]=\mathrm{KL}(\pi_\theta\Vert\pi_{ref})$。
   - **非负：** 因为 $\log x\le x-1$，所以 $k_3\ge0$ 对每个样本都成立。
   - 为什么：D2 第 16 段已经给过这个公式卡，这里补上证明。对比最直接的单样本估计 $k_1=-\log x$。它同样无偏，但单个样本可以是负数，这正是 D 部分讲过的"KL 读数为负"。k3 每个样本都不为负，方差也更小（Schulman 2020，"Approximating KL Divergence"）[标准知识]。另外注意：GRPO 的样本来自 $\pi_{old}$，所以严格说只是近似无偏。
5. 整体目标：
   $$J_{GRPO}=\mathbb E_{q,\{o_i\}\sim\pi_{old}}\Big[\tfrac1G\sum_i\tfrac1{\lvert o_i\rvert}\sum_t\big(\min(\rho_{i,t}\hat A_i,\ \mathrm{clip}(\rho_{i,t})\hat A_i)-\beta\,k_{3,i,t}\big)\Big]$$
   - DeepSeekMath 的设置：G=64，β=0.04，学习率 1e-6 [T§6]。
   - 为什么：注意 KL 是直接加在损失里的，而不是像 PPO 那样折算进每个 token 的奖励 [T§5]。
6. 当 μ=1（每批样本只更新一步）并且不切分小批量时，求梯度那一刻 $\rho\equiv1$，于是
   $$\nabla J=\tfrac1G\sum_i\tfrac{\hat A_i}{\lvert o_i\rvert}\sum_t\nabla\log\pi_\theta(o_{i,t})$$
   截断不起作用。只有在以下情况，后面几步才是离线（异策略）的，截断才真正生效：
   - 一批样本被拆成多个小批量（TRL 的 `steps_per_generation > 1`）；
   - 同一批样本训练多轮（`num_iterations > 1`）；
   - 异步采样。

   - 为什么：在 ρ=1 处，min 和 clip 取到的都是 ρÂ。这一步解开误区 `clip-always-on`。
7. **填空：** β=0 且 μ=1 时，GRPO 的梯度就是带 ___ 基线的 REINFORCE 乘上一个常数，再加上标准差和长度这两个权重。（答案：组均值，也就是留一法乘常数。）

*E1-c 长度偏差与难度偏差*

1. 由 E1-b 第 6 步，回答 $o_i$ 的整段 log 概率梯度前面的系数是 $c_i=\hat A_i/\lvert o_i\rvert$。
   - 为什么：先在一条回答内部平均，等于给每条回答除以它自己的长度。
2. 同一组里所有错误回答的 $\hat A_-$ 都相同，所以 $\lvert c_i\rvert\propto1/\lvert o_i\rvert$。1000 个 token 的错误回答，被压低的力度只有 100 个 token 的错误回答的十分之一，而且是每个 token 都是十分之一。正确回答则越短，被抬得越多。
   - 为什么：结果就是"对的偏短、错的偏长"。训练中回答长度可能因此上涨，准确率却不涨（Dr. GRPO [T§6, P§2]）。
3. 两种修法：
   - DAPO 按 token 平均，系数变成 $c_i=\hat A_i/\sum_j\lvert o_j\rvert$；
   - Dr. GRPO 除以常数 $L_{max}\cdot G$。

   两种做法下，同一组里每个 token 的权重都相同。
   - 为什么：每个 token 只算一次，长回答的 token 多，总权重自然更大，这是有意为之。TRL 里对应 `loss_type="dapo"`（默认）和 `"dr_grpo"`；原版 `"grpo"` 的文档注明了"有长度偏差，不推荐"。
4. **难度偏差。** 一组的总推力 $\sum_i\lvert\hat A_i\rvert$：
   - 有标准差归一化时等于 $2G\sqrt{\hat p(1-\hat p)}$；
   - 没有时等于 $2G\,\hat p(1-\hat p)$。

   以 $\hat p=1/8$ 和 $\hat p=1/2$ 两组的比值为例：没有标准差时是 0.44，有标准差时是 0.66。
   - 为什么：标准差归一化相对地放大了太容易和太难的题，这就是 Dr. GRPO 所说的难度偏差 [T§6]。
5. 难度加权到底是缺陷还是好处，目前没有定论 [争议]：
   - TRL 的默认值仍是组内归一化；
   - ScaleRL 改成了批级归一化 [T§6]；
   - Dr. GRPO 主张不做归一化。

   本课只要求学生说清这三种做法各自偏向哪类题。

```python
def group_advantages(rewards, G, scale="group", eps=1e-4):
    r = rewards.view(-1, G)                          # (B, G)，同一道题的 G 个回答连续排列
    adv = r - r.mean(dim=1, keepdim=True)            # (B, G) 组内基线
    if scale == "group":
        adv = adv / (r.std(dim=1, keepdim=True) + eps)   # 样本标准差，分母 G-1
    elif scale == "batch":
        adv = adv / (r.std() + eps)
    frac_zero = (r.std(dim=1) < 1e-6).float().mean()     # 零方差组比例，对应 TRL 的 frac_reward_zero_std
    return adv.view(-1), frac_zero

def grpo_loss(logp, old_logp, adv, mask, eps_low=0.2, eps_high=0.28,
              agg="token", L_max=None, ref_logp=None, beta=0.0):
    ratio = torch.exp(logp - old_logp)               # (N, T)
    a = adv.unsqueeze(1)                             # (N, 1)，整条回答共用一个优势
    per_tok = -torch.min(ratio * a, torch.clamp(ratio, 1 - eps_low, 1 + eps_high) * a)
    if beta > 0:                                     # k3：x - log x - 1，其中 x = π_ref/π_θ
        x = torch.exp(ref_logp - logp)
        per_tok = per_tok + beta * (x - (ref_logp - logp) - 1)
    if agg == "sequence":                            # 原版 GRPO：先在每条回答内平均（有长度偏差）
        return ((per_tok * mask).sum(1) / mask.sum(1)).mean()
    if agg == "token":                               # DAPO：全批 token 平均
        return (per_tok * mask).sum() / mask.sum()
    return (per_tok * mask).sum() / (mask.shape[0] * L_max)   # Dr. GRPO：除以常数
```

```python
ds = load_dataset("openai/gsm8k", "main", split="train").map(lambda ex: {

def correctness(completions, gold, **kwargs):                  # 对话格式：completion 是消息列表
    out = []
    for c, g in zip(completions, gold):

    return out                                                 # 必须返回与 completions 等长的 float 列表
def fmt(completions, **kwargs):
    pat = re.compile(r"^<think>.*?</think>\s*<answer>.*?</answer>\s*$", re.S)
    return [0.2 if pat.match(c[0]["content"]) else 0.0 for c in completions]
```

**要解开的误解**
- `r1-is-pure-rl`
  - 误解：R1 就是纯强化学习。
  - 实际：纯强化学习的是 R1-Zero。R1 走了四个阶段：冷启动 SFT → 强化学习 → 约 80 万条拒绝采样数据上的 SFT → 覆盖所有场景的强化学习 [T§6]。
- `aha-created`
  - 误解："aha 时刻"是强化学习凭空创造出来的。
  - 实际：Dr. GRPO 在基座模型里就找到了"aha"式的自我反思 [T§6, P§2]。此外，E1 讲过的长度偏差也会把回答推长。
- `prm-always-better`
  - 误解：过程奖励总比结果奖励好。
  - 实际：
    - Lightman 等人（2305.20050）发现，从多个候选答案里挑一个时，过程奖励模型比结果奖励模型更好 [标准知识，核对]。
    - 但 R1 论文把过程奖励模型列为"不成功的尝试"，理由是步骤难以界定、标注困难，而且会被钻空子 [标准知识，核对]。
    - 今天实验室的训练奖励主要来自验证器、评分细则和评委 [A§4, A§6]。
- `pass1-is-boundary`
  - 误解：pass@1 就代表模型能力的边界。
  - 实际：Yue 等人发现，k 很大时基座模型的 pass@k 反而更高，而 RLVR 训出来的模型能解的题没有超出基座的覆盖范围 [T§6]。
- `debate-settled` [争议]：教会还是激发，目前没有定论。双方证据见第 13 段。
- `same-weights-same-probs`
  - 误解：推理引擎和训练框架加载同一份权重，算出的概率就一样。
  - 实际：两边用的算子和数值精度不同，算出的 token 概率并不相同。这种训练-推理不一致需要专门修正，例如截断重要性采样（TIS）或改用 FP16 [T§6]。

**必要细节（第 13 段：教会还是激发）**

- **支持"只是激发"：**
  - Yue 等人：k 大时基座赢；RLVR 训出的模型能解的题，没有超出基座的覆盖范围；蒸馏反而能带来新的解题模式 [T§6]。
  - 虚假奖励（spurious rewards）：对 Qwen2.5-Math-7B 给随机奖励，MATH-500 也能涨 21.4 分（真实奖励涨 29.1 分）；但这个现象在 Llama 和 OLMo 上不成立 [T§6]。
  - DeepSeekMath：强化学习提升 Maj@K，不提升 Pass@K [T§6]。
- **支持"能教会"：**
  - ProRL：长时间训练，配合 KL 控制和参考模型重置，能扩大 pass@k [T§6]。
  - Zhang、Neubig、Yue（ICML'26）在可控的合成任务上发现：只有当题目恰好处在模型能力的边缘时，强化学习才带来真正的新能力（pass@128 最多 +42%）；他们还指出中期训练被低估了 [T§6]。
- **双方都同意的部分：** 强化学习一定会"锐化"，把概率集中到已经能做对的路径上。有没有"扩展"，取决于训练时长、题目难度是否处在能力边缘，以及基座本身。
- **实操含义：**
  - 在自己的模型上测大 k 的 pass@k，并统计覆盖率，也就是"至少做对一次的题"占多少；
  - 想要新能力，选在能力边缘的题，或者先做中期训练、SFT、蒸馏；
  - "虚假奖励"的结果提醒我们：只在一个模型家族上得到的结论要谨慎推广。

**必要细节（第 17 段：工程）**

- **时间花在哪。** 长思维链要一个 token 一个 token 地生成，这一步占了强化学习大部分的墙钟时间 [标准知识]。所以采样交给 vLLM 或 SGLang 这样的推理引擎。TRL 的 `vllm_mode` 有两种：
  - `colocate`：生成和训练在同一张卡上，省卡；
  - `server`：用专门的卡做生成。
- **同步与异步**（图 F-E2-6）。
  - 同步：生成 → 训练 → 同步权重，循环往复。训练时生成卡闲着，生成时训练卡闲着。
  - 异步：例如 PipelineRL，ScaleRL 允许落后 8 步 [T§6]。生成用的是几步之前的权重，于是样本是离线（异策略）的，需要 E1 讲的截断或重要性采样来校正。在这种情况下，截断才真正起作用。
- **训练-推理不一致**（图 F-E2-7）。
  - 现象：同一份权重，推理引擎和训练框架用的算子、精度不同，算出的 token 概率也不同（π_rollout ≠ π_train）。本以为是在线训练，实际上是离线（异策略）的。回答越长、用 MoE 时，问题越严重 [T§6]。
  - 办法：
    - 截断重要性采样：每个 token 乘以权重 $w_t=\min\big(\pi_{train}(o_t)/\pi_{rollout}(o_t),\,C\big)$（verl 文档 [T§6]）；
    - 改用 FP16 [T§6]；
    - LM head 用 FP32（ScaleRL [T§6]）。
  - TRL v1.15 的对应：默认开启 `vllm_importance_sampling_correction=True`，`vllm_importance_sampling_clip_max=3.0`；相关日志是 `sampling/sampling_logp_difference/*` 和 `sampling/importance_sampling_ratio/*`。
- **监控清单。**
  - 奖励（分项记录）；
  - 留出集 pass@1，并定期测大 k 的 pass@k；
  - `frac_reward_zero_std`；
  - 回答长度，正确和错误分开记；
  - `completions/clipped_ratio`；
  - `entropy`；
  - `clip_ratio/*`；
  - `kl`（只在 β>0 时有）；
  - `sampling/*`。
- **工具怎么选** [T§8, A§2]：
  - 单卡：Unsloth，或者 TRL 加 PEFT；
  - 单机多卡：TRL（vLLM 用 server 模式）或 OpenRLHF；
  - 大规模、异步、智能体：verl、slime、prime-rl、SkyRL；
  - 托管：E1 讲的强化微调服务，或者 Tinker（只支持 LoRA 的托管 API）。

**交互规格：`pass_k_sharpen`**

- **变量：**
  - 24 道题各自的基座成功率 p_q，画成柱子，每根都可以拖；
  - 锐化强度 s，范围 0–3；
  - 锐化阈值 t，范围 0.02–0.5，默认 0.1，放在"高级"里；
  - k 的横轴，对数刻度，1–256。
- **示意模型（锐化变换）：**
  - 公式：$\mathrm{logit}(p')=(1+s)\big(\mathrm{logit}(p)-\mathrm{logit}(t)\big)+\mathrm{logit}(t)$；
  - 含义：p 高于阈值的题被推向 1，低于阈值的题被推向 0，p=0 的题保持 0。
- **精确计算：** $\text{pass@}k=\frac1Q\sum_q\big[1-(1-p_q)^k\big]$。
- **画面：**
  - 左边：每道题的柱子，基座为灰色，当前为彩色；
  - 右边：基座和当前两条 pass@k 曲线，横轴是 log₂k；
  - 读数：pass@1、pass@256、交叉点 k*，以及覆盖率（p_q>0 的题数）。
- **默认数据：** 用固定种子生成。离线试算结果：
  - 基座：4 道题 p=0，6 道 p 在 0.001–0.05，7 道在 0.05–0.4，7 道在 0.5–0.95；pass@1 = 0.28，pass@256 = 0.74。
  - s=1、t=0.1 时：pass@1 升到 0.39，pass@256 降到 0.63，两条曲线在 k≈16 附近交叉。
- **学生做什么：**
  1. 先在第 10 段下注，然后把 s 从 0 拖到 2，看 pass@1 上升、pass@256 下降；
  2. 找出是哪些题拉低了大 k 的值：p 很小的题被压得更小；
  3. 把 s 归零，把一道 p=0 的题拖到 0.01，读出变化：pass@1 几乎不动（+0.0004），pass@256 跳升约 3.8 个点（1/24 × (1 − 0.99²⁵⁶) ≈ 0.038）。
- **应该注意到：**
  - pass@1 衡量的是采样效率；
  - 大 k 的 pass@k 衡量的是覆盖率；
  - 锐化只能在覆盖范围之内搬动概率，而且可能把覆盖率搬丢；
  - "教会"一道新题，只在大 k 处才看得出来。
- **结束时的问题**（choice）：只看 pass@1，能不能判断强化学习有没有扩大模型能解的题的范围？
  - ✓ 不能，要看大 k 的 pass@k 或覆盖率；
  - 能，pass@1 涨了就说明能力变强了（误区 `pass1-is-boundary`）。
- **world 配置：**
  - goals：
    - `cross`：pass@1 ≥ 基座 + 0.1，并且 pass@256 < 基座；
    - `teach`：s > 0 的同时，通过拖高 p=0 的题，让 pass@256 回到基座之上。
  - detectors：学生在 pass@256 下降时停下，并选择"强化学习让模型更强"，发出 `pass1-is-boundary` 提示。
- **零件名：** `pass_k_sharpen`（新）。
- **怎么满足交互准则的三条：**
  1. **关系：** "锐化强度"和"小 k 上升、大 k 下降、两线交叉"之间的关系，以及"新增一道可解题只在大 k 处显现"，文字只能断言，学生很难自己想出两条曲线为什么会交叉。
  2. **形式对应：** 拖锐化，就是强化学习把概率集中到原本常对的题和路径上；把一根柱子从 0 拖上来，就是给模型一项新能力。拖的是"原因"（每道题的成功率分布），不是曲线的横轴 k。README 第 4 节否决的是"拖动 k 看一条静态曲线"，这里不同。
  3. **以问题收尾：** 第 10 段下注，世界结尾的选择题，第 14 段让学生设计实验。

**推导全文**

*E2-a pass@k 的无偏估计，以及 maj@k*

1. 定义：$\text{pass@}k=\mathbb E_q\big[1-(1-p_q)^k\big]$。
   - 为什么：k 次独立采样全部做错的概率是 $(1-p_q)^k$。
2. $p_q$ 不知道，只能对每道题采 n ≥ k 次，数出其中 c 次做对。直接代入 $\hat p=c/n$ 得到 $1-(1-c/n)^k$，这是有偏的。
   - 为什么：$f(p)=1-(1-p)^k$ 是凹函数，由 Jensen 不等式 $\mathbb E[f(\hat p)]\le f(p)$，所以直接代入会系统性地低估。
3. 无偏估计（Chen et al. 2021，Codex 论文 2107.03374）[标准知识]：$\widehat{\text{pass@}k}=1-\binom{n-c}{k}\Big/\binom{n}{k}$。
   - 为什么：这是"从这 n 个样本里不放回地随机抽 k 个，全部是错的"的精确概率。n 个样本是独立同分布的，随机抽出的 k 个同样独立同分布，所以它们全错的概率的期望正好是 $(1-p)^k$。
4. 例：n=16，c=2，k=4。
   - 无偏估计：$1-\binom{14}{4}/\binom{16}{4}=1-1001/1820=0.45$；
   - 直接代入：$1-(14/16)^4=0.41$。

   为什么：样本少时，两者的差别不小。
5. **maj@k**（也叫 cons@k）：采 k 个答案，取出现最多的那个，看它对不对。它需要能抽取出答案，测的是"一致性"。pass@1 的估计就是 c/n。
   - 为什么：R1-Zero 报告的 cons@64 = 86.7% 就是 maj@64 [T§6]。
6. **填空：** n=8，c=0 时，pass@8 的估计值是 ___。（答案：0。没有采到过对的答案，就没有任何证据表明它会做。）

### E3 蒸馏与合并

- **时长**：核心内容约 31 分钟；加上第 7 段的选读代码，约 33 分钟。
- **前置**：
  - B2：序列级蒸馏 = 正向 KL，以及 R1-Distill 的数字；
  - E1：k1 和 k3 估计量、策略梯度的写法；
  - E2：每条轨迹约 1 比特；
  - B3：遗忘。
- **技能 id**：`kd-kinds`、`kl-direction`、`kd-temperature`、`on-policy-distill`、`multi-teacher-distill`、`merging-basics`、`forgetting-kl`
- **误区 id**：`distill-needs-logits`、`kl-direction-swap`、`t2-optional`、`seqkd-is-onpolicy`、`rl-strictly-better`、`merge-any`、`average-is-enough`

**学完能做到**
1. **分清三类蒸馏。** 序列级、logit 级、在线蒸馏，分别说出：训练信号从哪来、样本由谁生成、要不要同一个分词器、成本多大。按手头的条件选对方法，条件包括：老师只能通过 API 调用、老师能在本地运行且分词器相同、分词器不同。
2. **预测 KL 的方向。** 学生容量不够时，预测正向 KL 和反向 KL 各会拟合成什么样。说出"正向 KL 在老师的样本上算，反向 KL 在学生的样本上算"，并对应到序列级蒸馏和在线蒸馏。
3. **推两条公式。**
   - 带温度的 logit 蒸馏梯度，以及 T² 这个因子；
   - "逐 token 反向 KL 的梯度，就是以 −(log π_s − log π_t) 为逐 token 奖励的策略梯度"。
4. **讲清在线蒸馏。**
   - 说出在线蒸馏和多老师在线蒸馏怎么做、花多少、什么时候用；
   - 用三组数字说明小模型上蒸馏为什么常常胜过强化学习：R1-Distill 的 72.6 对 47.0、Qwen3 的约 1/10 GPU 小时、Thinking Machines 的 74.4 对 67.6；
   - 说出蒸馏的上限在哪。
5. **合并与遗忘。** 用任务向量解释模型合并，手算一次 TIES，判断两个模型能不能合并。用 RL's Razor 解释为什么在线（同策略）的方法遗忘更少。

**要解开的误解**
- `distill-needs-logits`
  - 误解：蒸馏一定要拿到老师的 logits。
  - 实际：序列级蒸馏只需要老师生成的文本。R1-Distill 就是用约 80 万条 R1 输出直接做 SFT [T§7, A§3]。在实验室以外，大多数蒸馏都是以"用合成数据做 SFT"的形式出现的 [A§3]。
- `kl-direction-swap`
  - 误解：把两个方向的行为记反，以为正向 KL 会挑一个峰。
  - 实际：正向 KL 覆盖所有峰，反向 KL 挑一个峰（MiniLLM [T§7]）。第 3 段的世界会精确算给学生看。
- `t2-optional`
  - 误解：温度只是让分布变软，T² 可有可无。
  - 实际：不乘 T²，软标签项的梯度会按 1/T² 缩小。见推导 E3-a [T§7 Hinton]。
- `seqkd-is-onpolicy`
  - 误解：用老师的输出做 SFT 就是在线蒸馏。
  - 实际：在线蒸馏的样本是学生自己生成的，老师只负责打分（GKD、Thinking Machines [T§7]）。
- `rl-strictly-better`
  - 误解：强化学习总比蒸馏强，也更"高级"。
  - 实际：
    - 在 Qwen-32B 上，R1-Distill 得 72.6，直接做强化学习只有 47.0 [T§6]；
    - Qwen3 的小模型用蒸馏，花的 GPU 小时约为强化学习的 1/10 [A§3]；
    - 在线蒸馏在 AIME 上得 74.4，强化学习是 67.6，算力只用了约 1/10 [T§7]。
- `merge-any`
  - 误解：任何两个模型都能把权重平均起来合并。
  - 实际：只有同一个基座微调出来的模型才行，因为不同基座的参数坐标互不对应 [T§7]。
- `average-is-enough`
  - 误解：合并时简单平均就够了。
  - 实际：符号冲突的坐标会相互抵消，只有一个任务改动过的坐标会被稀释。TIES 就是为此设计的 [T§7]。

**必要细节（第 11 段：多老师在线蒸馏）**

- **做法：**
  1. 先训练几个领域专家，比如数学强化学习专家、代码专家、智能体专家。它们通常来自同一个基座，是不同的强化学习分支。
  2. 学生在混合的提示上自己生成回答。
  3. 每条提示交给对应领域的老师，逐 token 打分。
  4. 学生最小化各领域的反向 KL：
     $$\mathcal L=\sum_d w_d\ \mathbb E_{x\sim\mathcal D_d,\ y\sim\pi_s}\Big[\sum_t \mathrm{KL}\big(\pi_s(\cdot\mid x,y_{<t})\,\Vert\,\pi_{T_d}(\cdot\mid x,y_{<t})\big)\Big]$$
- **谁在用：**
  - DeepSeek V4、Nemotron 3 Ultra、MiMo Flash v2 [A§3]。这条来自 Interconnects 的访谈整理，细节以各家的技术报告为准 [A 的 Caveats]。
  - Gemma 3 从一个大的指令模型蒸馏 [A§3]。
  - Qwen3 的小模型：强到弱蒸馏，先离线、后在线 [A§3]。
- **为什么它取代了权重合并** [A§8]：
  - 把多个专家合成一个，以前靠权重算术，现在越来越多靠蒸馏。
  - 蒸馏不要求同一个基座，序列级蒸馏连分词器都不要求一样；学生还可以比老师小。
  - 学生是在自己的分布上学，不同专家之间的冲突由数据来裁决，而不是由权重算术来裁决。
- **代价：**
  - 每个老师都要能在线算 log 概率，带来显存或服务成本；
  - 老师之间风格不一致时，学生会被来回拉扯，所以要按领域路由提示，并调节权重 w_d；
  - 领域必须划分清楚。
- **工具：**
  - Tinker cookbook 里有蒸馏配方 [A-缺 3]；
  - TRL 的 GKD 和 GOLD（实验性）只支持单个老师，多老师需要自己按领域路由 [核对]。
- **和 E2 的关系：** 实验室的"推理模型配方"越来越像这样一条流水线：
  1. 在基座上分别用强化学习训出多个专家（E1、E2）；
  2. 用多老师在线蒸馏把它们合进一个模型（本段）；
  3. 必要时再做一轮通用强化学习。

**交互规格：`forward_reverse_kl`**

- **变量：**
  - 学生高斯 q = N(μ, σ²)：拖中心手柄改 μ，拖宽度手柄改 σ；
  - KL 的方向：正向、反向、两个都显示；
  - 老师分布 p = w·N(−d, s₀²) + (1−w)·N(d, s₀²) 的参数：左峰权重 w（0.5 或 0.7）、峰距 d（默认 2）、峰宽 s₀（默认 0.6）。
- **画面：**
  - 老师 p 和学生 q 两条曲线；
  - 两种 KL 的实时读数，用数值积分精确算出；
  - 被积函数的阴影：正向是 p·log(p/q)，大的地方在"p 有质量而 q 很小"；反向是 q·log(q/p)，大的地方在"q 有质量而 p 很小"；
  - 一个"优化"按钮：从当前位置对所选的 KL 做梯度下降，并画出路径。
- **阶段 B（"在谁的样本上算"）：**
  - 打开采样点：正向 KL 用从 p 抽的点，反向 KL 用从 q 抽的点。每个点标出 log 比值，KL 就是这些点的平均。
  - 学生拖动 q 时，反向 KL 的样本点会跟着 q 一起移动，正向 KL 的样本点不动。这正是"反向 KL 需要学生自己的样本，也就是在线"的几何含义。
- **离线算好的参考值**（数值积分，s₀=0.6，d=2）：
  - w = 0.5：
    - 正向 KL 的最小值在 μ=0、σ=2.09，KL=0.555（等于做矩匹配）；
    - 反向 KL 的最小值在 μ=±2、σ≈0.59，KL≈0.692（约等于 ln 2）；
    - 在矩匹配那一点，反向 KL 是 1.27；停在一个峰上时，正向 KL 是 10.4。
  - w = 0.7（左峰重）：
    - 正向 KL 的最小值在 μ=−0.8、σ=1.93；
    - 反向 KL 的全局最小在左峰，KL=0.356；右峰是一个局部最小，KL=1.20。从右侧开始优化，会停在右峰。
- **学生做什么：**
  1. 先在第 2 段下注，再手动把正向 KL 拖到最小；
  2. 切到反向，把反向 KL 拖到最小；
  3. 把 w 设成 0.7，从右侧出发跑"优化"，看它停在局部最小；
  4. 打开阶段 B 的采样点，拖动 q，观察哪组点在跟着动。
- **应该注意到：**
  - 正向 KL 会惩罚"老师有、学生没有"，所以学生把自己摊开；
  - 反向 KL 会惩罚"学生有、老师没有"，所以学生缩进一个峰；
  - 反向 KL 的期望是在学生的样本上取的。
- **结束时的问题**（choice）：一个容量不够的学生，用反向 KL 在线蒸馏一个会多种写法的老师，最可能的副作用是什么？
  - ✓ 多样性下降，丢掉老师的一些写法；
  - 生成老师不会说的话（反馈：这是正向 KL 的问题）；
  - 完全学不会。
- **精确计算还是示意：** 在这个一维玩具上，KL 是用数值积分精确算的；双峰老师本身是示意。
- **world 配置：**
  - goals：
    - `fwd-min`：正向 KL 与最小值的差在 0.02 以内；
    - `rev-min`：反向 KL 与某个局部最小的差在 0.02 以内；
    - `samples`：打开采样点后，拖动过 q。
  - detectors：在"正向"模式下，学生把 q 停在一个峰上，并选择"这是正向 KL 的最小值"，发出 `kl-direction-swap` 提示。
- **零件名：** `forward_reverse_kl`（新）。
- **怎么满足交互准则的三条：**
  1. **关系：** q 的位置和宽度与两种 KL 数值之间的关系、两者的不对称，以及"样本跟谁走"，文字只能断言。
  2. **形式对应：** 拖高斯就是在选学生的分布；切换方向就是在选蒸馏损失（TRL 的 `beta`）；打开采样点，就是在选"用老师的样本还是学生的样本"（TRL 的 `lmbda`）。
  3. **以问题收尾：** 第 2 段下注，世界结尾有选择题，第 17 段是迁移诊断。

**推导全文**

*E3-a 带温度的 logit 蒸馏与 T²*

记号：词表大小 N，学生的 logits 是 z，老师的 logits 是 v；$q_i=\dfrac{e^{z_i/T}}{\sum_j e^{z_j/T}}$，$p_i$ 的定义同理。

1. 软标签损失 $L_{soft}=\mathrm{KL}(p\Vert q)=\sum_i p_i\log p_i-\sum_i p_i\log q_i$。只有第二项依赖 z。
   - 为什么：老师是固定的，不参与求梯度。
2. $\log q_k=z_k/T-\log\sum_j e^{z_j/T}$，所以 $\dfrac{\partial\log q_k}{\partial z_i}=\dfrac{\delta_{ki}-q_i}{T}$。
   - 为什么：这是 softmax 的对数导数；1/T 来自链式法则。
3. $\dfrac{\partial L_{soft}}{\partial z_i}=-\sum_k p_k\dfrac{\delta_{ki}-q_i}{T}=\dfrac{q_i-p_i}{T}$。
   - 为什么：$\sum_k p_k=1$。
4. 温度高时，$e^{x/T}\approx1+x/T$。不妨设每个位置的 logits 均值为 0（softmax 对整体平移不变，所以这样设不失一般性），于是 $q_i\approx(1+z_i/T)/N$，$p_i\approx(1+v_i/T)/N$。
   - 为什么：一阶泰勒展开，分母约等于 N。
5. $\dfrac{\partial L_{soft}}{\partial z_i}\approx\dfrac{z_i-v_i}{N\,T^2}$。
   - 为什么：代入上一步即得。这说明两件事：梯度大小按 $1/T^2$ 缩小；而且它正好是 $\frac{1}{2NT^2}\sum_i(z_i-v_i)^2$ 的梯度，也就是说高温下的蒸馏等于"直接匹配 logits"，这是 Hinton 的结论 [T§7]。
6. 总损失 $L=\alpha\,\mathrm{CE}(y,q^{(T=1)})+(1-\alpha)\,T^2\,\mathrm{KL}(p^{(T)}\Vert q^{(T)})$。
   - 为什么：乘上 $T^2$，软标签项的梯度大小就基本不随 T 变化。这样调 T 的时候，α 的含义保持不变。
7. 大模型版本：对回答里的每个位置求和并归一化，$L=\frac{T^2}{\sum_t m_t}\sum_t m_t\,\mathrm{KL}(p_t\Vert q_t)$。
   - 为什么：下标 i 必须在师生两边指同一个 token，所以需要同一套词表 [T§7]。实践中，大模型蒸馏常常就用 T≈1（TRL 的 GKD 默认生成温度是 0.9），T² 的作用在经典的分类蒸馏里更关键。
8. （可折叠）反向 KL 的梯度：$\dfrac{\partial\,\mathrm{KL}(q\Vert p)}{\partial z_i}=\dfrac{q_i}{T}\big[(\log q_i-\log p_i)-\mathrm{KL}(q\Vert p)\big]$。
   - 为什么：每一项前面都乘着 $q_i$，也就是说，只有学生已经给了概率的 token 才会收到梯度。这就是"挑峰"在公式里的样子。
9. **填空：** 不乘 T² 时，把 T 从 2 调到 8，软标签项的梯度约变为原来的 ___ 倍。（答案：1/16。）

*E3-b 在线蒸馏 = 逐 token 奖励的策略梯度*

1. 序列级的反向 KL：$\mathrm{KL}(\pi_s\Vert\pi_t)=\mathbb E_{y\sim\pi_s}\big[\sum_t d_t\big]$，其中 $d_t=\log\pi_s(y_t\mid x,y_{<t})-\log\pi_t(y_t\mid x,y_{<t})$。
   - 为什么：序列的概率等于逐 token 概率的乘积，取对数后变成求和。注意期望是在学生的样本上取的。
2. 对 θ 求梯度：$\nabla\mathbb E_{y\sim\pi_s}[f_\theta(y)]=\mathbb E[f_\theta\nabla\log\pi_s(y)]+\mathbb E[\nabla f_\theta]$。第二项等于 $\mathbb E[\nabla\log\pi_s(y)]=0$。
   - 为什么：前一项是 E1 和 D2 的对数导数技巧；后一项为 0，原因和 E1 推导第 3 步一样：$\sum_y\nabla\pi_s=\nabla 1=0$。
3. 由因果性，$t'<t$ 时的 $d_{t'}$ 和第 t 步之后的动作无关，可以去掉，于是 $\nabla\mathrm{KL}=\mathbb E\big[\sum_t\big(\sum_{t'\ge t}d_{t'}\big)\nabla\log\pi_s(y_t\mid\cdot)\big]$。
   - 为什么：这和策略梯度里的"未来回报"（reward-to-go）是同一个论证。
4. 也就是说：把逐 token 奖励设为 $r_t=-d_t=\log\pi_t(y_t)-\log\pi_s(y_t)$，最小化反向 KL 就等于用这个奖励做策略梯度。老师认可的 token 奖励为正，老师认为不该出现的 token 奖励为负。
   - 为什么：RL 每条轨迹只有一个标量（E2 说的约 1 比特），这里每个 token 都有一个奖励，信号稠密得多。
5. 实践中有两种写法：
   - **只用当前 token**（折扣为 0）：优势 $A_t=-d_t$。Thinking Machines 报告这样就够了 [核对]。这种写法只需要采样 token 的 log 概率，所以在只开放采样接口的 API 上也能用。
   - **在每个位置算完整词表上的 KL**，直接反传，把前缀当作固定的样本。GKD 和 TRL 的 GKDTrainer 是这种做法。
   - 为什么：前一种是对 KL 的单样本估计，也就是 E1 和 B3 里的 k1；后一种需要老师的完整分布，方差更小。
6. 学生在自己的前缀上学，包括自己犯过的错误，老师会在这些错误之后告诉它下一步该怎么走。这样就没有"训练时看老师的前缀、推理时看自己的前缀"的错位，也就是暴露偏差（exposure bias）。
   - 为什么：这正是 GKD 论文副标题"从自己生成的错误中学习"的含义 [TRL 文档]。
7. **填空：** 学生采样到一个 token，老师给它的 log 概率是 −0.2，学生给它的是 −1.5，这个 token 的优势 $A_t=$ ___。（答案：+1.3。老师比学生更认可这个 token，所以要提高它的概率。）

*E3-c 任务向量算术（可折叠，第 14 段）*

1. $\tau_i=\theta_i-\theta_0$。
   - 为什么：这是微调造成的改动。只有同一个 $\theta_0$ 出发的模型，坐标才对得上。
2. 合并 $\theta_m=\theta_0+\sum_i\lambda_i\tau_i$。
   - 模型汤：取 $\lambda_i=1/n$，因为 $\frac1n\sum\theta_i=\theta_0+\frac1n\sum\tau_i$；
   - WiSE-FT：只有一个任务，$\lambda\in[0,1]$，就是插值；
   - λ<0：减去一个任务向量，可以去掉一种行为 [T§7]。
3. 对任务 A，在 $\theta_A$ 附近做二阶展开。由于 $\theta_A$ 近似是最优点，梯度约为 0，所以 $L_A(\theta_m)\approx L_A(\theta_A)+\tfrac12\Delta^\top H_A\Delta$，其中 $\Delta=\theta_m-\theta_A$。
   - 为什么：其他任务的向量落在 A 的损失平坦的方向上（$H_A$ 的小特征值方向，回扣"特征值 → PCA"课里椭圆的轴），干扰就小。
4. **TIES** [T§7]：
   - 修剪：每个 τ 只保留幅值最大的 k%；
   - 选符号：$\gamma_j=\mathrm{sgn}\big(\sum_i\hat\tau_i[j]\big)$；
   - 合并：只对与 $\gamma_j$ 同号的项取平均。
   - 为什么：直接平均时，符号相反的坐标会相互抵消，只有一个任务改过的坐标会被稀释。
5. **DARE** [T§7]：以概率 p 把每个分量置零，留下的分量乘以 $1/(1-p)$，期望不变。
   - 为什么：和 dropout 的放大是同一个道理。

```python
def kd_loss(s_logits, t_logits, mask, T=1.0, direction="forward"):
    # s_logits, t_logits: (B, L, V)；mask: (B, L)，只在回答 token 上为 1
    s_lp = F.log_softmax(s_logits.float() / T, dim=-1)
    t_lp = F.log_softmax(t_logits.float() / T, dim=-1)
    if direction == "forward":                        # KL(p_t || q_s)：覆盖所有峰
        kl = (t_lp.exp() * (t_lp - s_lp)).sum(-1)     # (B, L)
    else:                                             # KL(q_s || p_t)：挑一个峰
        kl = (s_lp.exp() * (s_lp - t_lp)).sum(-1)
    return T * T * (kl * mask).sum() / mask.sum()
```

E3-code-2 的要点（要求师生分词器相同；注意 logits 和 token 要错开一位）：

```python
def token_logprobs(model, seqs):                       # seqs: (B, S)
    logits = model(seqs).logits[:, :-1].float()        # (B, S-1, V)：第 i 个位置预测 seqs[:, i+1]
    return torch.log_softmax(logits, -1).gather(-1, seqs[:, 1:, None]).squeeze(-1)  # (B, S-1)

with torch.no_grad():
    seqs = student.generate(**prompts, do_sample=True, temperature=1.0, max_new_tokens=512)
    t_lp = token_logprobs(teacher, seqs)               # 老师只做一次前向（预填充）
s_lp = token_logprobs(student, seqs)                   # 带梯度
mask = completion_mask(seqs, prompt_len, eos_id)[:, 1:]   # 只算学生生成的 token
adv = -(s_lp.detach() - t_lp)                          # A_t = log π_t − log π_s
loss = -(adv * s_lp * mask).sum() / mask.sum()
```

**检验题**

- **Q1 计算**（number）
  - 题目：不乘 T² 时，把 T 从 2 调到 8，软标签项的梯度大约缩小到原来的几分之一？
  - 答案：16。
  - 判分要点：填 4 的，反馈"梯度按 1/T² 变，不是按 1/T"。
- **Q2 选择**（三个小题，各选一种）
  - (a) 老师是闭源 API，只返回文本 → 序列级蒸馏，并先查服务条款。
  - (b) 老师是本地的 Qwen3-32B，学生是 Qwen3-1.7B，分词器相同 → 先做序列级 SFT 热身，再做在线蒸馏。
  - (c) 手上有同一个基座的数学专家和代码专家，想得到一个模型 → 多老师在线蒸馏；想零成本先试一下，可以做 TIES 合并，并在两个任务上分别评测。
  - 判分要点：(b) 只选"序列级"的给一半分，反馈"能拿到完整分布，又能在线，就别浪费"；(c) 选"不同基座也能合并"的，标记误区 `merge-any`。
- **Q3 计算**（number）
  - 题目：三个任务向量，每个有四个坐标：
    - τ₁ = (0.8, −0.1, 0.5, 0.02)
    - τ₂ = (0.6, 0.3, −0.7, 0.01)
    - τ₃ = (−0.1, 0.4, −0.2, 0.9)

    每个向量只保留幅值最大的两个坐标。求 TIES 合并后的第 3 个坐标。
  - 答案：−0.7。
  - 推导过程：
    - 修剪后，第 3 坐标只剩 τ₁ 的 0.5 和 τ₂ 的 −0.7；
    - 两者之和是 −0.2，所以选出的符号为负；
    - 只平均同号的值，结果是 −0.7。
  - 判分要点：
    - 填 −0.133 的，是直接平均（误区 `average-is-enough`）；
    - 填 −0.1 的，是把异号的值也平均了；
    - 填 −0.2 的，是把投票的总和当成了合并值。
  - 讲解：对照图 F-E3-7 里第 4 坐标的变化。只有 τ₃ 改动了它，直接平均把 0.9 稀释成了 0.31，TIES 保留了 0.9。
- **Q4 解释**（自由作答，AI 判读）
  - 题目：用一两句话解释，在线蒸馏为什么能用约 1/10 的算力，达到甚至超过强化学习的效果？
  - 判分要点：
    - 必须提到：每个 token 都有老师给的信号（稠密），而强化学习每条轨迹只有一个标量；
    - 加分：提到老师只需要做前向、不用生成；提到样本是学生自己生成的（在线），没有暴露偏差。
- **Q5 诊断**（choice）
  - 题目：用反向 KL 做在线蒸馏之后，学生的数学准确率上去了，但写故事时，8 次采样几乎写出同一个开头。为什么？怎么办？
  - 选项：
    - ✓ 反向 KL 会挑峰，学生收缩到了老师的主要模式上。办法：让 β 往正向那边靠，或者在创作类数据上混入序列级蒸馏的数据，或者对数学和创作分别处理。
    - 学习率太高；
    - 老师太弱；
    - 温度太低。反馈：采样温度会影响多样性，但这里分布本身已经收缩了，回到第 3 段的世界看看。

**"怎么选"卡片（E3 给决策图加的内容）**
- **节点**：DM-E2（蒸馏到小模型）、DM-C3（老师）、DM-E3（上线形态：多老师蒸馏或较轻的合并）。
- **规则 E3-1**：手里有更强的老师，小模型优先蒸馏，不要直接做强化学习。依据：72.6 对 47.0；约 1/10 的 GPU 小时 [T§6, A§3]。
- **规则 E3-2**：选哪种蒸馏，看你能拿到老师的什么：
  - 只有文本（API）：序列级蒸馏，先查服务条款；
  - 能在本地跑，分词器也相同：先用序列级 SFT 热身，再做在线蒸馏。这是 Qwen3 的顺序：先离线，后在线 [A§3]；
  - 分词器不同：序列级蒸馏，或者用 GOLD/ULD（实验性）。
- **规则 E3-3**：想把多个专家合成一个模型，2026 年的默认做法是多老师在线蒸馏。权重合并只在"同一个基座、想零训练成本先试一下"时使用 [A§3, A§8]。
- **规则 E3-4**：担心遗忘时，选在线的方法（强化学习、在线蒸馏），或者用旧模型当老师做一次在线蒸馏，把旧能力找回来。衡量遗忘的指标是新任务上相对基座的 KL [T§7]。
- **反例 E3-a**：老师在你的领域里本身就不行。蒸馏的上限就是老师，要超过老师，需要强化学习和真实数据。
- **反例 E3-b**：不同基座的模型不能做权重合并，因为坐标不对应。分词器不同时，logit 蒸馏也只能近似。
- **反例 E3-c**：需要多样输出的任务（比如创作），只用反向 KL 在线蒸馏，会让多样性下降。
