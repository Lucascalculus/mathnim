## 0.5 "这些是不是目前最常用的技术？"（结论，证据见 research-adoption.md）

按实际使用程度排序：
1. **提示词、上下文工程加 RAG**：企业的默认做法。调查中约 80% 的团队用提示词，约 49% 用 RAG，约 26% 做微调。
2. **SFT 加 LoRA/QLoRA**：微调里的绝对主力，数据常常是合成的。在 Hugging Face 上，SFT 训练的模型约 7.8 万个，PEFT 适配器约 27 万个。
3. **蒸馏**：实验室里普遍使用。2026 年的标志做法是多个专家老师的在线蒸馏（Qwen3、Gemma 3、DeepSeek V4）。
4. **可验证奖励的强化学习（GRPO 类）**，以及云厂商托管的强化微调服务（带评分器）：增长很快，在 Hub 上已经超过 DPO。
5. **DPO**：各平台都提供，但在前沿配方里正在淡出。
6. **奖励信号**：实际主要来自验证器、评分细则和大模型评委，单独训练的 Bradley–Terry 奖励模型反而少见。

其余的：
- 继续预训练：实验室常用，其他场景少用；
- 模型合并：在衰退；
- PPO：基本只剩历史意义。

**据此对课程做的调整：**
- **增加或加重：**
  - A1 从"什么时候不该微调"讲起，决策图里加入编码器分类模型微调；
  - B2 以合成数据和拒绝采样为核心；
  - B3 把评测作为大段内容（评测连续几年都是从业者的头号难题）；
  - E1 加入托管强化微调服务和评分器设计；
  - E3 深入讲在线蒸馏；
  - 智能体和工具调用作为案例，放在 B2、E2、F1。
- **减少：**
  - PPO 讲作"通往 GRPO 的概念桥梁"，不作为当前实践；
  - DPO 的变体压缩成一张对照表；
  - 模型合并只讲短短一段；
  - 奖励模型扩展为"奖励信号的几种来源"。
- **不讲：** 多模态微调，课程里只注明"超出范围"。

## 1. 学生与验收标准

- **学生：** 懂神经网络、反向传播、softmax 和交叉熵、基本线性代数；不要求有强化学习背景，策略梯度会从头讲。
- **验收标准：** 和 v1 相同，学生能做到预测、计算、诊断、选择、解释五件事，其中**"选择"权重最高**。
- **检验方式：**
  - 课前、课后各做一次概念测验，测验题专门针对常见误区；
  - 每课结尾有迁移题；
  - 最后一课用案例综合检验"怎么选"。

## 2. 课程结构（6 部分，16 课，另有 5 个实验教程）

| 部分 | 课 | 核心问题 |
|---|---|---|
| **A 地图** | A1 让模型做事的五种办法 | 提示词、RAG、SFT、偏好优化、强化学习，各自改的是什么（上下文还是权重），代价是什么 |
| | A2 RAG：把知识放进上下文 | 切块、向量、检索、重排、拼上下文；RAG 在哪里失败；什么时候要微调向量模型 |
| **B 模仿（SFT）** | B1 SFT 机制 | 损失、聊天模板、loss 掩码、EOS、打包 |
| | B2 数据从哪来 | 人工数据、合成数据、拒绝采样、序列级蒸馏、继续预训练与 SFT 的区别 |
| | B3 训练动态、评测与遗忘 | 过拟合、"loss 低 ≠ 好"、怎么评测、灾难性遗忘及缓解 |
| **C 装得下** | C1 显存账 | 16 字节/参数、激活值、logits |
| | C2 LoRA | 低秩改动、B=0 初始化、α/r、加在哪层、学习率、容量 |
| | C3 QLoRA 与上线 | NF4、按块缩放、合并与多适配器 |
| **D 偏好（重点）** | D1 为什么要偏好，以及奖励模型 | 两两比较、Bradley–Terry、奖励模型怎么验 |
| | D2 从策略梯度到 RLHF | REINFORCE → 基线 → PPO 截断 → KL 约束 → 奖励被钻空子 |
| | D3 DPO：推导与几何 | 闭式最优策略 → 隐式奖励 → 损失；β 的作用；似然位移 |
| | D4 DPO 家族与偏好数据实践 | IPO、KTO、ORPO、SimPO；偏好数据怎么构造；离线与在线；方法怎么选 |
| **E 推理（重点）** | E1 可验证奖励与 GRPO | 组内基线、截断、零方差组、长度偏差、各种改进版本 |
| | E2 推理模型的完整配方 | R1 流程、拒绝采样、过程奖励与结果奖励、测试时扩展、"教会还是激发"之争 |
| | E3 蒸馏与合并 | 正向与反向 KL、在线蒸馏、任务向量、TIES |
| **F 怎么选（收官）** | F1 决策框架与案例研讨 | 十个真实场景，从需求一路推到方案、数据、风险和评测 |

**说明：**
- 工具调用和智能体微调放在 B2 或 F1 作为应用案例；如果 research-adoption.md 证实它非常普遍，再单独成课。
- 每课 20–35 分钟。
- 学习顺序：A → B → C → D → E → F，其中 C 可以和 D 互换。

**"怎么选"这条主线：** A1 建立一张决策图，B 到 E 每课结尾更新这张图，在"怎么选"卡片上补充一条规则和一个反例，F1 用案例把整张图用一遍。

## 3. 页面类型

现有的页面类型：
- 动画场景
- 探索（世界）
- 题目（检查点）
- 提问 AI

**需要新增的文字类页面（平台工作，见第 9 节）：**
- **文字页（read）：**
  - 章节、段落、公式（行内与独立行）；
  - 代码块：语法高亮、复制按钮、可在 PyTorch 和 TRL 两种写法之间切换；
  - 图片：附图注和出处；
  - 提示框：注意、常见误区、开放问题；
  - 可折叠的细节、脚注引用；
  - 可以内嵌一个交互图，复用零件。
- **推导页（derive）：**
  - 逐行展开公式，每一步都可以点开"这一步为什么成立"；
  - 可以和 manim 的公式变换动画同步；
  - 最后一步可以留成填空题，用来检验。
- **代码讲解页（code）：**
  - 左边代码、右边讲解，滚动时同步高亮对应的代码行；
  - 关键行旁边标注张量的形状。
- **图片：**
  - 流程图和架构图用 SVG，尽量用 manim 生成，保持风格统一；
  - 论文里的图一律重绘，并注明出处，不直接截图。

## 4. 交互准则：不为交互而交互

每个交互必须**同时满足三条**，否则改用静态图或文字：

1. **关系：** 学生调的是一个真实的变量，屏幕上能看到这个变量和结果之间的关系，而且这个关系是文字只能断言、学生很难自己想象出来的。
2. **形式对应：** 操作方式和概念是同构的。例如：
   - 拖动 β，就是收紧或放松"缰绳"；
   - 翻转一张答案卡的对错，就是改变奖励；
   - 拖动秩，就是保留或截掉奇异值；
   - 拖动显存计算器里的参数，就是在做真实的预算。
3. **以问题收尾：** 交互之前先让学生预测，交互结束时要用观察到的东西回答一个问题（预测 → 观察 → 解释）。

**诚实标注：** 每个交互都要标明是"精确计算"（例如 π* ∝ π_ref·e^{r/β} 的闭式解）、"示意模型"，还是"真实数据重绘"。

**v1 交互审查结果：**

| 保留为交互（理由） | 改为静态图或文字（理由） |
|---|---|
| **逐 token 的 loss 掩码：** 学生切换掩码时，能看到 loss 和梯度分配在哪里 | **基座模型与聊天模型逐词对照：** 拖动游标并不比一张热力图更能说明问题 → 改为带标注的热力图 |
| **pad = EOS 导致模型停不下来：** 改一个设置，直接看到后果 | **softmax、温度和 KL 补课：** 学生已经懂神经网络 → 改为公式卡片；KL 的不对称留到 E3 的交互里讲 |
| **打包时的注意力掩码：** 能直接看到哪些格子在"串台" | **Bradley–Terry 的"整体平移不变"：** 一张图加一道题就够 |
| **两个山谷的遗忘地形：** 学习率和步数与遗忘程度的关系 | **LoRA 的"容量水桶"：** 比喻成分太重 → 改为重绘真实实验曲线并配文字 |
| **显存计算器：** 真实预算，并且先让学生预测 | **pass@k 拖动 k：** 拖动一条静态曲线不比看图强 → 改为重绘的静态图 |
| **秩 r 重建一个真实的 ΔW，以及秩 1 的线性变换** | **代理奖励与真实奖励两条曲线：** 并入 D2 的"缰绳"世界，在那里由 β 驱动 |
| **NF4 量化格点放在哪，以及异常值** | |
| **KL 缰绳：** 精确闭式解，是偏好部分的核心 | |
| **PPO 截断函数：** 看清截断在什么时候起作用 | |
| **DPO 的"只看差距"：** 让学生自己找出似然位移 | |
| **GRPO 的一组采样：** 翻转对错，看优势和长度偏差 | |
| **正向 KL 与反向 KL 拟合双峰分布** | |
| **任务向量相加与 TIES 的正负号投票** | |

新增的交互同样要过这三条；各部分的规划文件里，每个交互都要写出它是怎么满足这三条的。

## 5. 双语

- **课程内容：**
  - 每课一个数据文件，学生看到的所有文字都以 `{ en, zh }` 成对存放；公式、代码和零件参数两种语言共用。
  - 中文版不是逐句翻译，而是按中文的表达习惯来写。
- **术语表：**
  - 维护一份中英对照，统一译名，例如：fine-tuning 微调、reward hacking 奖励投机、likelihood displacement 似然位移、rejection sampling 拒绝采样。
  - 第一次出现的术语写成"中文（English）"。
- **旁白：**
  - 只给"视频"（scene 步骤）配旁白，另外只在确有必要处配（例如学生正盯着画布操作时，世界里简短的发现/目标台词）。
  - 文字页（read / derive / code）和题目不配旁白：学生自己读，读得比听快（用户 2026-10-10 要求）。
  - 英文用 Andrew（en-US-AndrewMultilingualNeural），中文用 Yunxi（zh-CN-YunxiNeural）；两种语言都预先录好。
- **界面：**
  - 设置页和课程页都可以切换语言；
  - AI 导师按学生提问所用的语言回答，这一点已经支持。

## 6. 实验教程（只给教程，不托管算力）

| 实验 | 内容 | 环境 |
|---|---|---|
| L1 | 搭一个 RAG 管线，并做检索评测；选做：微调一个向量模型 | CPU 或 Colab |
| L2 | 用 LoRA 做 SFT，比较掩码、秩、学习率三组设置 | Colab T4 或本地 GPU |
| L3 | 做 DPO，记录 chosen 和 rejected 的 log 概率，观察似然位移 | Colab |
| L4 | 在 GSM8K 上做 GRPO，记录奖励、回答长度、零方差组的比例 | Colab，4 位量化加 LoRA |
| L5（选做） | 序列级蒸馏：用大模型的推理轨迹去训练一个小模型 | Colab |

每个教程都包括：
- 目标；
- 环境；
- 逐步代码；
- 预期输出和曲线；
- 运行前让学生先写下的预测；
- 常见报错及处理；
- 这个实验对应课程里的哪一个交互。

## 7. 检验题的类型

- **预测：** 改某个设置之前，先说出会发生什么。
- **计算：** 显存、参数量、优势、胜率。
- **诊断：** 给出曲线或症状，找原因。
- **选择：** 给出场景，选方案并写出理由、数据和风险。
- **解释：** 用一句话写出机制，由 AI 导师判读。

每课 3–5 道，都附答案和判分要点。概念测验约 20 题，课前课后各做一次。
