### A1 让模型做事的五种办法

- **时长：** 约 35 分钟
- **前置：** 无（默认学生懂神经网络、softmax、交叉熵）
- **技能 id：** `a1-when-not`（什么时候不该微调）、`a1-levers`（上下文与权重两根杠杆）、`a1-signals`（训练信号决定方法）、`a1-costs`（成本与延迟账）、`a1-map`（决策图的前三问）
- **误区 id：** `ft-is-default`、`ft-injects-knowledge`、`llm-for-everything`、`rl-strictly-better`、`ft-always-cheaper`、`rag-xor-ft`

**本课从"什么时候不该微调"讲起。** 按 adoption 的数据：
- 提示词和上下文工程是大多数团队的默认做法；
- 做微调的团队只占约四分之一；
- OpenAI 2026 年开始关闭自助微调平台。据二手报道，给出的理由是新模型听指令的能力已经足够，靠提示词就能解决。

**"五种"怎么数：**
- 五根主杠杆是：提示词与上下文工程、RAG、SFT、偏好优化、强化学习。
- 方法表里还有三行，它们不是新的杠杆，而是同一套机制的特殊用法：
  - **编码器分类模型微调**：很多任务根本不需要生成式大模型；
  - **蒸馏**：借用 SFT（序列级）或 KL 损失（logit 级、在线）的机制，把大模型的本事搬到小模型上；
  - **继续预训练**：在领域文本上接着做下一个词预测。
- 合成数据和拒绝采样是**数据来源**，不是训练方法，贯穿 SFT、蒸馏和偏好优化，在 B2 详讲。
- 多模态微调（视觉、语音）超出本课程范围，只在方法表下加一句说明。

#### 要解开的误解

| 误区 id | 误解 | 证据 |
|---|---|---|
| `ft-is-default` | "做 AI 应用就该微调，提示词是业余做法。" | 2026 年对 1,053 个团队的调查（自报）：用提示词的约 80%，用 RAG 的约 49%，做微调的约 26%，用强化学习的约 22%（[Notion × Amplify × Vercel](https://www.notion.com/lp/ai-engineering-survey)）。Menlo 2024：生产环境里只有约 9% 的模型经过微调（[Menlo 2024](https://menlovc.com/2024-the-state-of-generative-ai-in-the-enterprise/)）。OpenAI 2026 年 5 月开始关闭自助微调，理由是新模型靠提示词已经足够（[Tessl 的二手报道](https://tessl.io/blog/openai-shutting-fine-tuning-signals-for-enterprise-ai)；官方页面也写明了"正在关闭"，见 [model-optimization 指南](https://developers.openai.com/api/docs/guides/model-optimization)）。OpenAI 的官方流程是：先写评测，再写提示词，需要时才微调，然后循环。Huyen 的阶梯是"提示词 → 示例 → RAG → 微调"（[AI Engineering ch.7](https://oreilly.com/library/view/ai-engineering/9781098166298/ch07.html)）。LIMA 和 URIAL 认为对齐主要改的是风格。**[有争议]** 数学、代码这类能力随数据量按幂律增长（[Raghavendra 2024](https://arxiv.org/abs/2410.03717)）。 |
| `llm-for-everything` | "分类、路由、审核这类任务，也该用（或微调）生成式大模型。" | 输出只是固定标签的任务，用一个编码器加分类头往往就够，训练和推理都便宜得多（标准知识）。Hugging Face 上用 Trainer 训练的文本分类模型有 43,372 个，这仍然是生产中最常见的微调之一（adoption 第 6 条）。 |
| `ft-injects-knowledge` | "要让模型知道新东西，就拿这些资料去微调。" | 模型原本不知道的事实，在 SFT 中学得更慢；一旦学会，幻觉近似线性上升（[Gekhman et al., EMNLP 2024](https://arxiv.org/abs/2405.05904)）。注入知识时 RAG 胜过无监督微调（[Ovadia et al.](https://arxiv.org/abs/2312.05934)）。只有预训练时经过改写增强的知识才能被提取出来，指令微调救不回来（[Physics of LMs 3.1](https://arxiv.org/abs/2309.14316)）。**[有争议]** Unsloth 认为"微调加不了知识"是误解（[FAQ](https://unsloth.ai/docs/get-started/fine-tuning-for-beginners/faq-+-is-fine-tuning-right-for-me)，厂商来源）。教学口径采用 research-pedagogy 的建议："可以加，但要多样化地重复，且有幻觉风险。" |
| `rl-strictly-better` | "强化学习是最高级的方法，越往后越好。" | 在 32B 规模上，蒸馏胜过直接强化学习：AIME 2024 pass@1 分别为 72.6 和 47.0（[DeepSeek-R1](https://arxiv.org/abs/2501.12948)）。强化学习需要能打分的信号。RLVR 的结果停留在基座模型的覆盖范围之内（[Yue et al.](https://arxiv.org/abs/2504.13837)，**[有争议]**）。 |
| `ft-always-cheaper` | "微调以后提示变短，一定更省钱。" | 微调有固定成本（训练、托管）。提示缓存可以把长提示的成本降低多达 90%、延迟降低一半以上（[Anthropic, Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval) 中关于提示缓存的说明）。另外，部分闭源平台的微调本身正在关闭：OpenAI 2026 年起不再对新用户开放（同一指南页的公告）。 |
| `rag-xor-ft` | "RAG 和微调只能二选一。" | RAFT 用带干扰文档的检索结果去微调生成模型（[RAFT](https://arxiv.org/abs/2403.10131)）。向量模型和重排模型本身也可以微调（A2）。OpenAI 指南把微调定位成与提示、上下文配合使用。 |

**W-A1-1 `cost_crossover`（持平点世界）**

- **变量（全部是真实的预算输入，附示例默认值，界面注明"示例价格，请换成当前报价"）：**
  - 每天请求数 N：对数滑块，10 到 10⁶；
  - 方案 A（大模型 + 长提示）：
    - 输入 token 数 T_A：默认 3,000；
    - 输入、输出单价 p_in^A、p_out^A：默认每百万 token 3 美元、15 美元；
    - 缓存命中比例 h：默认 0；
    - 缓存价与原价之比 κ：默认 0.1；
  - 方案 B（微调小模型 + 短提示）：
    - 输入 token 数 T_B：默认 300；
    - 单价 p_in^B、p_out^B：默认每百万 token 0.2 美元、0.8 美元；
    - 每天固定成本 F：默认 20 美元，包括托管费和摊销后的训练费；可以拖到 0，代表按 token 计费的托管 LoRA；
  - 两个方案共用输出 token 数 T_out：默认 300。
- **学生做什么：**
  1. 拖动 N，找到两条日成本线的交点；
  2. 把 h 拖到 0.8–0.9，看交点怎么移动；
  3. 把 T_out 调大，看"缩短提示"还能省多少；
  4. 把 F 拖到 0。
- **应该注意到什么：**
  - 低请求量时，固定成本占主导，微调不划算；
  - 缓存会把 A 的输入成本压下去，持平点往右移；
  - 输出 token 占大头时，缩短提示省不了多少钱；
  - F 为 0 时，几乎任何请求量下微调都划算。这正是托管多适配器服务改变决策的地方（C3）。
- **结束时的问题：** "'微调能省钱'这句话，要满足哪三个条件才成立？"答案要点：请求量高；输入成本占主导，且没有被缓存吃掉；固定成本相对每次请求省下的钱不大。
- **标注：** 精确计算。公式在第 10 段，价格是示例。延迟只用文字说明，零件里不显示，避免"示意数字"冒充真实数据。
- **零件名：** `cost_crossover`（新）。F1 的案例 9 复用。
- **如何满足三条准则：**
  1. **关系：** 持平点由四五个量共同决定，而且对缓存和输出长度很敏感。文字只能说"量大才划算"，学生自己想象不出交点会移多远。
  2. **形式对应：** 每个滑块就是预算表里的一个真实输入，拖动它就是在做一份真实的预算。这和 README 认可的显存计算器同构。
  3. **以问题收尾：** 先做第 11 段的下注，最后回答上面那道"三个条件"的问题。

#### 推导全文（成本模型，第 10 段）

单次请求成本（单价按每百万 token 计）：

$$c = \frac{T_{\text{in,未缓存}}\,p_{\text{in}} + T_{\text{in,缓存}}\,\kappa\,p_{\text{in}} + T_{\text{out}}\,p_{\text{out}}}{10^6}$$

方案 A：$c_A = \big[T_A\,p^A_{\text{in}}(1-h+h\kappa) + T_{\text{out}}\,p^A_{\text{out}}\big]/10^6$。
方案 B：$c_B = \big[T_B\,p^B_{\text{in}} + T_{\text{out}}\,p^B_{\text{out}}\big]/10^6$，另有每天的固定成本 $F = F_{\text{托管}} + C_{\text{训练}}/D$，其中 D 是摊销天数。

日成本：$A(N) = N c_A$，$B(N) = F + N c_B$。两者相等时：

$$N^* = \frac{F}{c_A - c_B}\quad(\text{仅当 } c_A > c_B)$$

三条推论，对应世界里的三个操作：
1. $N^* \propto F$。F 趋近 0 时，$N^*$ 也趋近 0。
2. h 增大时 $c_A$ 变小，$N^*$ 变大。
3. 如果 $T_{\text{out}}p_{\text{out}}$ 占主导，$c_A - c_B$ 主要取决于输出单价的差。这时省钱靠的是换一个更便宜的模型，而不是缩短提示。

算例（Q3 用）：$c_A = 3000\times3/10^6 + 300\times15/10^6 = 0.0135$，$c_B = 300\times0.2/10^6 + 300\times0.8/10^6 = 0.0003$，F = 20，得 $N^* = 20/0.0132 \approx 1{,}515$ 次/天。

**Q0（预测，不计分，第 1 段）** 在做 AI 应用的团队里，你猜有多少在改模型权重（做微调）？
- 约 10% / 约 25% ✔ / 约 50% / 约 80%

**Q1（预测，不计分，第 3 段）** 一家公司用 500 条内部 FAQ 问答对，对一个开源对话模型做了 SFT。上线后，用户问到 FAQ 里没有的新产品参数。最可能发生什么？
- A. 模型回答"不知道"
- B. 模型用 FAQ 的口吻，流畅地编出参数 ✔
- C. 模型答对，因为它学会了公司的知识（`ft-injects-knowledge`）
- D. 模型对所有问题都开始拒答

揭晓（第 8 段）：SFT 主要学到的是格式和口吻；训练数据里没有的事实，它不会凭空知道；学会"未知"事实还会推高幻觉（Gekhman）。

**Q2（练习，6 个小题，单选）**

可选答案：示范 → SFT / 比较 → 偏好优化 / 验证器 → RLVR / 老师 → 蒸馏 / 上下文 → RAG 或提示词 / 标签 → 编码器分类模型

1. 法务团队能写出标准的合同摘要。→ SFT
2. 评审员写不出完美回答，但能稳定判断两份回答哪份更得体。→ 偏好优化
3. 每道题都有标准答案，可以用程序判分。→ RLVR
4. 答案在每周更新的内部文档里。→ RAG
5. 已经有一个大模型做得很好，只是太贵。→ 蒸馏
6. 每天 50 万条工单要分到 12 个类别，手上已有 2 万条人工标注。→ 编码器分类模型

判分：每小题独立判对错。
- 第 3 题选"SFT"时反馈："你手里只有答案，没有解题过程。答案可以当验证器，不能当示范。"
- 第 6 题选"SFT 一个生成式大模型"时，标记 `llm-for-everything`，反馈："输出只是 12 个标签之一，用编码器加分类头就够了，而且每条的推理成本要低几个数量级。"

**Q3（计算，数值题）** 方案 A 每次请求 0.0135 美元，方案 B 每次请求 0.0003 美元外加每天 20 美元固定成本。每天多少次请求时两者持平？
- 答案：1,515，容差 3%。
- 常见错答：
  - 1,481，即 20/0.0135，忘了减去 B 的单次成本；
  - 66,667，即 20/0.0003，把 B 的单次成本当成了差值。

**Q4（解释，AI 判读）** 用一两句话说明：为什么"让模型知道上周刚调整的价格"应该放进上下文，而不是写进权重？
- 判分要点，满分需要命中其中两点：
  1. 价格会变，写进权重就得每次变化都重新训练；
  2. SFT 学未知事实学得慢，而且会推高幻觉（Gekhman），注入知识时 RAG 更好（Ovadia）；
  3. 放在上下文里可以引用出处、核对来源，也能控制谁可以看到。
- 只写"RAG 更好"而不说理由，算 0 分。

**Q5（迁移选择）** 一个团队想让 7B 模型在竞赛数学上变强。手里只有题目和标准答案，没有解题过程，也没有更强的老师模型可用。第一步应该做什么？
- A. 用题目和答案做 SFT
- B. 先测基座模型在这些题上的 pass@k，确认 k 较大时它能偶尔做对，再做 RLVR ✔
- C. 让人工两两比较回答，然后做 DPO
- D. 把题目放进 RAG

判分：
- 选 A，反馈"答案不是示范，模型学不到解题过程"；
- 选 C，反馈"有验证器时，比较是更弱的信号"；
- 选 D，反馈"缺的是能力，不是知识"。
- 选 B 时追问一句："如果 pass@64 也几乎是 0 呢？"预期回答：强化学习拿不到学习信号，要先换更容易的题、先做 SFT，或者去找一个老师模型。这一点在 E1 展开。

#### "怎么选"卡片（A1）

- **节点：** DM-0（先写评测）、DM-1（上下文工程基线）、DM-T（任务形态）、DM-2（差距分类）
- **规则：**
  1. 默认不微调。先写评测，再用最强的可用模型加上下文工程跑出基线（大多数团队到这一步就停了）。
  2. 把剩下的失败分成知识、行为、能力、效率四类。知识类先放进上下文；只有行为、能力和效率类的差距，才考虑改权重。
  3. 改权重时用哪种方法，看你手里有哪种信号：示范、比较、验证器、老师，还是标签。输出是固定标签的，交给编码器分类模型。
- **反例：** 用 500 条 FAQ 做 SFT，想让模型"记住"新产品。结果它学会了 FAQ 的口吻，事实却不可靠，还会编造（Q1，Gekhman）。

#### 要解开的误解

| 误区 id | 误解 | 证据 |
|---|---|---|
| `rag-is-vector-db` | "RAG 就是把文档丢进向量数据库。" | BM25 是稳健的基线；稠密检索在零样本跨领域时常常不如它（[BEIR, NeurIPS 2021](https://arxiv.org/abs/2104.08663)）。Anthropic 的实验里，前 20 块检索失败率从基线的 5.7% 降到 3.7%（加上下文化嵌入）、2.9%（再加上下文化 BM25）、1.9%（再加重排）（[Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval)）。 |
| `similar-means-relevant` | "向量越相似，越能回答问题。" | 嵌入衡量的是语义上像不像，不是能不能回答问题。复述问题的段落可能比含答案的段落得分还高（标准知识；HyDE 的动机就是这个，[Gao et al. 2022](https://arxiv.org/abs/2212.10496)）。 |
| `chunk-size-monotone` | "块越大（或越小）越好。" | 上下文预算是固定的：块小，答案会被切散，指代也会丢失；块大，嵌入被稀释，放得进上下文的块也更少。见世界 W-A2-1（真实数据）。 |
| `fix-generator-first` | "答错了，就换更大的生成模型，或者微调它。" | 七个失败点里有三个发生在答案进入上下文之前：FP1 缺内容、FP2 排名靠后没进前 k、FP3 整合时被丢弃（[Barnett et al. 2024](https://arxiv.org/abs/2401.05856)）。所以要先单独评测检索。 |
| `long-context-kills-rag` | "上下文窗口够长了，就不需要 RAG。" | 资源充足时，长上下文的平均效果确实更好，但 RAG 便宜得多。两者按问题路由（Self-Route），可以在大幅降本的同时保持接近长上下文的效果（[Li et al., EMNLP 2024](https://arxiv.org/abs/2407.16833)）。相关信息落在长上下文中间时，表现明显下降（[Lost in the Middle, TACL](https://arxiv.org/abs/2307.03172)）。反过来，知识库小于约 20 万 token 时，Anthropic 建议直接全部放进提示，配合缓存（同上 Contextual Retrieval）。 |
| `false-negatives-harmless` | "负例里混进几个其实相关的，问题不大。" | 推导（第 14 段）：最像查询的负例被推得最狠。所以挖难负例时要过滤掉太像正例的候选，例如 sentence-transformers 的 `relative_margin`（[文档](https://sbert.net/docs/package_reference/util/hard_negatives.html)）。 |
| `embed-ft-no-reindex` | "微调完向量模型，直接替换就行。" | 文档向量是旧模型算出来的。新旧模型的向量不在同一个空间，必须用新模型重新嵌入整个语料。重排模型在查询时才给（查询，文档）打分，不需要重建索引。（标准知识） |

#### 交互规格

**W-A2-1 `chunk_size_recall`（块大小与固定预算）**

- **变量：**
  - 块大小：64 / 128 / 256 / 512 / 1,024 token，离散滑块；
  - 重叠：0 / 10% / 20%，开关；
  - 上下文预算 B：默认固定为 1,024 token，选读时可以调；
  - 能放进上下文的块数由这两项算出：k = ⌊B / 块大小⌋。
- **画面：**
  - 左边：文档竖条，标出块的边界；当前选中问题的答案片段用黄色标出；被检索进前 k 的块用描边标出。
  - 右边：12 个问题的命中表。命中的定义是"答案片段完整落在某个被取回的块里"。未命中再分两种原因：
    - "答案被切断"：答案跨了块边界；
    - "排名不够"：含答案的块存在，但没进前 k。
  - 下方：命中率随块大小变化的折线，当前设置高亮。
- **学生做什么：**
  1. 拖动块大小，找到命中率最高的设置；
  2. 打开重叠，看哪些"被切断"的问题被修好；
  3. 点开某个"排名不够"的问题，看含答案的块排在第几，以及它和查询的相似度。
- **应该注意到什么：**
  - 块很小时，有的答案被切断，指代也会丢失，例如"它"指的是上一块里提到的产品；
  - 块很大时，k 只剩 1–2 个，而且大块的嵌入被稀释，含答案的大块可能排不进前 k；
  - 中间的块大小最好；
  - 重叠主要修复的是"被切断"这一类。
- **结束时的问题：** "如果把预算从 1,024 提高到 4,096，最佳块大小会往哪边移？为什么？"答案要点：预算变大，能放的块变多，大块排不进前 k 的代价变小，最佳点通常会往大的方向移。如果离线数据显示不是这样，就按数据改写题目和答案。
- **标注：** 真实数据。用一篇公开文档离线计算：
  - 候选文档：一份公开的产品手册，或一篇维基百科长文；
  - 12 个问题加人工标注的答案片段；
  - 一个开源向量模型，例如 multilingual-e5-small，模型名写在图注里；
  - 计算所有"块大小 × 重叠"组合的排名。
  如果数据呈现的不是非单调的权衡，就照实展示，并改写结束问题，不为了好看去挑数据。同一份语料和问题集给 L1 复用。
- **零件名：** `chunk_size_recall`（新）
- **如何满足三条准则：**
  1. **关系：** 在固定预算下，命中率先升后降，原因有两种，而且两种原因随块大小此消彼长。文字只能说"太大太小都不好"，具体在哪里折返、为什么折返，学生想象不出来。
  2. **形式对应：** 滑块就是切块器的 `chunk_size` 和 `overlap` 参数。拖动它，文档就真的重新切块、重新检索。
  3. **以问题收尾：** 先做 Q-A2-1 的下注，结束时回答预算变化的问题。

**W-A2-2 `contrastive_infonce`（对比损失把谁推开）**

- **变量：**
  - 温度 τ：0.02–1，对数滑块，旁边显示 scale = 1/τ；
  - 批内负例数：1–7，对应 batch size − 1；
  - "训练一步"按钮：用 D-A2-5 推出的梯度更新一次，学习率固定；
  - "过滤假负例"开关：模拟 `relative_margin` 过滤。
- **画面：**
  - 单位圆上画出查询 q、正例 d⁺，以及若干负例。其中一个是难负例：和 q 很像，但不相关。另一个是假负例：其实相关，却被当成了负例。假负例在揭晓前不标出来。
  - 每个文档向量上画一支切向箭头，长度等于它受到的梯度大小。
  - 旁边是 softmax 权重 w_j 的柱状图，以及损失 L 的读数。
- **学生做什么：**
  1. 先预测哪个负例被推得最远；
  2. 拖动 τ，看箭头长度的分配怎么变；
  3. 连按"训练一步"，看各个向量怎么移动；
  4. 揭晓假负例以后，打开过滤开关，再训练几步。
- **应该注意到什么：**
  - 推力按 w_j ∝ e^{s_j/τ} 分配。τ 小的时候，推力几乎全部集中在最像 q 的负例上；τ 大的时候，各负例平分推力，信号变弱。
  - 假负例往往就是"最像 q 的负例"，因此它被推得最狠。结果是一段相关的文档被推离查询。
  - 打开过滤以后，正例和假负例都能留在 q 附近。
  - 负例越多，越可能碰到难负例。
- **结束时的问题：** "为什么挖难负例时，要丢掉和正例分数太接近的候选？"答案要点：这些候选很可能其实是相关的，也就是假负例；而 InfoNCE 恰恰把最大的推力分给它们。
- **标注：** 精确计算。梯度公式是精确的；向量是二维玩具例子，只演示几何关系。
- **零件名：** `contrastive_infonce`（新）
- **如何满足三条准则：**
  1. **关系：** τ 和"推力在各负例之间怎么分配"之间是指数关系，假负例因此受伤。文字只能说"低温聚焦难负例"，看不到推力具体怎么分。
  2. **形式对应：** τ 就是损失里的温度，即 MNRL 的 `scale` 取倒数。"训练一步"就是按推导出的梯度做一次 SGD。负例数就是批大小减一。
  3. **以问题收尾：** 先做 Q-A2-5 的预测，结束时回答为什么要过滤。

#### 推导全文

**D-A2-1 余弦与点积**

$\cos(q,d) = \dfrac{q^\top d}{\|q\|\,\|d\|}$。若 $\|q\| = \|d\| = 1$，则 $\cos(q,d) = q^\top d$。

所以先归一化，再用内积索引，就等价于按余弦检索。在 sentence-transformers 里，对应写法是 `normalize_embeddings=True`。

**D-A2-2 BM25（公式卡片，不需要推导）**

$$\text{BM25}(q,d) = \sum_{t\in q}\text{IDF}(t)\cdot\frac{f(t,d)\,(k_1+1)}{f(t,d) + k_1\big(1-b+b\,|d|/\text{avgdl}\big)}$$

常用取值：$k_1\in[1.2,2.0]$，$b=0.75$。三个部分各管一件事：
- IDF：词越罕见，权重越大；
- $k_1$：同一个词重复出现时，得分趋于饱和；
- $b$：对长文档做惩罚。

**D-A2-3 RRF（公式卡片）**

$$\text{RRF}(d) = \sum_{r\in\text{检索器}} \frac{1}{k + \text{rank}_r(d)},\qquad k = 60$$

RRF 只用排名，不用分数，因此不受各检索器分数尺度不同的影响（Cormack, Clarke & Büttcher, SIGIR 2009）。

**D-A2-4 检索指标**

- $\text{Recall@}k = |R\cap \text{Top}_k| / |R|$，其中 R 是相关块的集合。
- 每个问题只有一个相关块时，Recall@k 就是 Hit@k。
- $\text{MRR} = \frac1{|Q|}\sum_q 1/\text{rank}_q$。第一个相关块不在截断位置之内时，这一项记 0。
- 选读：$\text{nDCG@}k = \text{DCG@}k/\text{IDCG@}k$，其中 $\text{DCG@}k = \sum_{i=1}^{k} \text{rel}_i/\log_2(i+1)$。

为什么要两类指标：
- Recall 回答"答案进没进上下文"。生成模型只能用上下文里有的东西。
- MRR 和 nDCG 衡量排序。排序会影响截断，也会影响模型对中间内容的利用（中间遗失）。

页面最后一步留成填空：给四个问题的排名 1、3、未找到、2，学生填 MRR。

**D-A2-5 InfoNCE 及其梯度**

设查询为 $q$，候选为 $d_0=d^+, d_1,\dots,d_{N-1}$，全部是单位向量。相似度 $s_j=q^\top d_j$。

1. **损失。**
   $\mathcal L = -\log\dfrac{e^{s_0/\tau}}{\sum_{j=0}^{N-1} e^{s_j/\tau}} = -\dfrac{s_0}{\tau} + \log\sum_j e^{s_j/\tau}$
   - 为什么成立：这就是以 $s_j/\tau$ 为 logits、正确类别为 0 的 softmax 交叉熵。对比学习等于在 N 个候选里做分类（[van den Oord et al. 2018](https://arxiv.org/abs/1807.03748)）。

2. **对相似度求导。**
   记 $w_j = e^{s_j/\tau}/\sum_k e^{s_k/\tau}$，则 $\dfrac{\partial\mathcal L}{\partial s_j} = \dfrac{w_j - \mathbb 1[j=0]}{\tau}$。
   - 为什么成立：softmax 交叉熵对 logit 的梯度等于"预测概率减 one-hot"，这是学生已知的结论。链式法则再乘上 $1/\tau$。

3. **相似度对向量求导。**
   $\partial s_j/\partial q = d_j$，$\partial s_j/\partial d_j = q$。

4. **对查询的梯度。**
   $\nabla_q\mathcal L = \dfrac1\tau\Big(\sum_j w_j d_j - d_0\Big) = \dfrac1\tau\Big(-(1-w_0)\,d_0 + \sum_{j\ge1} w_j d_j\Big)$

5. **对文档的梯度。**
   $\nabla_{d_0}\mathcal L = -\dfrac{1-w_0}{\tau}\,q$；对 $j\ge1$，$\nabla_{d_j}\mathcal L = \dfrac{w_j}{\tau}\,q$。

6. **梯度下降一步之后。**
   - 正例 $d_0$ 被拉向 $q$，力度是 $(1-w_0)/\tau$；
   - 负例 $d_j$ 被推离 $q$，力度是 $w_j/\tau$；
   - 因为 $w_j\propto e^{s_j/\tau}$，越像 $q$ 的负例被推得越狠；τ 越小，推力越集中。

7. **单位球约束。**
   若 $q=u/\|u\|$，则 $\nabla_u\mathcal L = \dfrac1{\|u\|}(I-qq^\top)\nabla_q\mathcal L$，只剩切向分量。所以零件里的向量只会沿着圆转动。

8. **两个推论。**
   - (a) 假负例的 $s_j$ 大，所以 $w_j$ 大，被推得最狠。因此需要过滤假负例。
   - (b) 选读折叠：InfoNCE 给出互信息的下界 $I(q;d)\ge\log N-\mathcal L$（van den Oord et al.），这是"批越大越好"的一种解释。实践中，可以用 CachedMNRL 在显存有限时把批做大。

9. **对应到库。**
   sentence-transformers 的 `MultipleNegativesRankingLoss` 默认用余弦相似度，`scale=20`，相当于 τ = 0.05。批内其他样本的正例，自动成为当前样本的负例。

推导页最后一步留成选择题："$\nabla_{d_j}\mathcal L$ 的方向是？"
- A. 沿 $+q$，即使 $d_j$ 远离 $q$ 的方向 ✔
- B. 沿 $-q$
- C. 沿 $d_0$
- D. 为 0

#### 检验题

**Q-A2-1（预测，第 4 段）** 预算为 1,024 token，块大小取 64 / 256 / 1,024 中的哪一个，能装下答案的问题最多？
- 不计分；揭晓就是世界 W-A2-1。
- 常见错误预测：选 1,024，理由是"块越大装得越多"（`chunk-size-monotone`）。

**Q-A2-2（检验）** 下面三条查询，各自更依赖哪种检索？
1. "订单号 7731-Q 为什么被拦截"
2. "怎么让孩子少玩手机"，文档里的写法是"儿童屏幕时间管理"
3. "ISO 27001 第 A.8 条要求什么"

答案：1 关键词；2 稠密；3 关键词为主，混合检索最稳。

追加一问（单选）：为什么 RRF 不需要先把分数归一化？
- 答案："它只用排名。"
- 选"因为 BM25 分数本来就在 0–1 之间"（错误）时，反馈："BM25 分数没有上限。"

**Q-A2-3（计算，两道数值题）** 每个问题只有一个相关块。四个问题里，相关块分别排在第 1、3、未进前 10、2 位。
- Recall@5 = 0.75
- MRR@10 = (1 + 1/3 + 0 + 1/2)/4 ≈ 0.458，容差 0.01
- 常见错答：0.611，即只对三个找到的问题取平均。反馈："没找到的问题也要计入分母，记 0 分。"

**Q-A2-4（诊断，配对）**
- (a) 正确块排在第 37 位，k = 10 → FP2 排名没进前 k。修法：混合检索或重排；仍然不行再微调向量模型。
- (b) 正确块已经在提示里，但回答引用了旁边一份过时文档的数字 → FP4 没提取出来（被噪声或矛盾干扰）。修法：按日期和版本元数据过滤、去重，在提示里规定"冲突时以最新版本为准"。
- (c) 用户问语料里根本没有的产品，模型自信地给出了答案 → FP1 缺内容。修法：规定"没有就说没有"，并在评测集里专门加入"应当拒答"的问题。

判分：每对一项得 1 分。症状 (a) 选"换更大的生成模型"时，标记 `fix-generator-first`。

**Q-A2-5（预测，第 15 段）** 五个负例与 q 的相似度分别为 0.9、0.5、0.3、0.1、−0.2。哪个被推得最远？τ 从 0.5 降到 0.05 以后呢？
- 答案：都是 0.9 那个。只在负例之间比较，它占的推力份额是 $e^{s_j/\tau}/\sum_{\text{负例}} e^{s_k/\tau}$：τ = 0.5 时约 48%，τ = 0.05 时约 99.97%。
- 揭晓就是世界 W-A2-2，读数以世界里的精确计算为准。

**Q-A2-6（选择，两个子场景）**
- (i) 法律条文检索：recall@20 只有 55%，但正确条文 90% 都在前 100 之内。最省事的修法是：加交叉编码器重排，需要时再微调重排模型 ✔
  - 干扰项：微调向量模型（可行，但要重建索引，代价更大）；微调生成模型；增大块。
- (ii) 医疗缩写很多，正确文档常常连前 300 都进不了；BM25 也找不回来，因为查询用缩写，文档用全称。修法是：先加查询改写或同义词扩展；仍然不行，就用领域查询对加难负例、以 MNRL 微调向量模型，然后重建索引 ✔
  - 干扰项：只加重排。重排只能调整已经取回的候选，进不了候选池的文档它救不回来。

**Q-A2-7（解释，AI 判读）** 为什么换向量模型要重建索引，换重排模型却不用？
- 判分要点：
  1. 文档向量是索引期用旧模型算好存下来的，新旧模型的向量不在同一个空间；
  2. 重排模型在查询时才对（查询，文档）打分，不依赖存下来的向量。
- 两点都答到，满分。

#### "怎么选"卡片（A2）

- **节点：** DM-K1 到 DM-K4
- **规则：** RAG 答错时，先单独测检索的 recall@k。召回不够，按这个顺序改：切块和元数据 → 混合检索 → 重排 → 微调重排模型或向量模型（对比损失；改向量模型要重建索引）。召回已经够、生成还是用不好，再改提示的拼法，最后才考虑 RAFT 式 SFT 生成模型。
- **反例：** 团队看到答案错，就拿问答对去微调生成模型。实际问题是正确块根本没进前 k（FP2）。微调只是教会模型在没有证据时也自信作答。
