## B1 SFT 机制

- **时长：** 约 33 分钟
- **前置：**
  - A1（五种办法；基座模型与聊天模型）；
  - softmax 和交叉熵（学生已会，不再补课）。
- **技能 id：** `sft-objective`、`chat-template`、`loss-mask`、`packing`、`loss-normalization`
- **误区 id：** `sft-new-objective`、`template-cosmetic`、`mask-dogma`、`pad-eos-harmless`、`packing-harmless`、`mean-of-means`

### 学完能做到
1. **写和算损失：** 写出带掩码和提示权重 λ 的 SFT 损失；给一段 token 序列和掩码，能手算它，并指出哪些位置对梯度有贡献。
2. **找静默 bug：** 给一段渲染后的对话和它的 labels，能指出三类静默 bug：
   - 提示没有掩掉；
   - 结束标记被掩掉（pad = EOS）；
   - 训练和推理用的模板或停止符不一致。
3. **说清提示权重的证据：** 什么情况下 λ = 0 合适，什么情况下 0.01–0.5 的小权重更好。
4. **算打包的两个比例：** 给一组样本长度，算出填充（padding）浪费的比例，以及直接拼接时跨样本注意力格子的比例；说出 `position_ids` 在打包里的作用。
5. **算梯度累积的归一化：** 给出跨 micro-batch 的 token 数和 loss 和，算出正确的全局 token 平均，并算出"平均的平均"让短样本的 token 被放大了多少倍。

### 要解开的误解

| id | 误解 | 实际情况与证据 |
|---|---|---|
| `sft-new-objective` | SFT 是一种新的训练目标 | 和预训练一样，都是预测下一个 token 的交叉熵，只是换了数据、加了掩码（[技] §2；[Lambert ch4](https://rlhfbook.com/c/04-instruction-tuning)）。 |
| `template-cosmetic` | 模板只是格式，推理时换一个也没关系 | 模型学到的是"在这串特殊 token 之后输出结束标记"。结束标记和生成器的停止符不一致，模型就停不下来。TRL 文档专门提醒：给 Qwen 基座做 SFT 时要设 `eos_token="<\|im_end\|>"`（[TRL 文档](https://huggingface.co/docs/trl/sft_trainer)；[Mistral 分词文档](https://docs.mistral.ai/cookbooks/concept-deep-dive-tokenization-basics)）。 |
| `mask-dogma` | 两个相反的极端："提示永远不能算 loss"，或者"整段都算也无所谓" | 整段算的反例：HF 论坛上有人"loss 一直降，模型什么都没学会"，原因是 loss 大部分花在了预测提示上（[HF 论坛](https://discuss.huggingface.co/t/sfttrainer-work-but-without-result/169118)）。另外，TRL 对纯文本数据集默认在整段上算 loss（[TRL main 文档](https://huggingface.co/docs/trl/main/en/sft_trainer)）。反过来，在回答短、提示长、数据少的数据上，给提示一个 0.01–0.5 的小权重比 0 和 1 都好（[Huerta-Enochian 2024](https://arxiv.org/abs/2401.13586)；[Shi et al. 2024](https://arxiv.org/abs/2405.14394)）。 |
| `pad-eos-harmless` | 把 pad 设成 EOS 没关系 | 按 token id 掩掉 pad 的 collator 会把真正的 EOS 也一起掩掉，模型从来没被要求输出它，于是不会停（[教] §3.3）。 |
| `packing-harmless` | 把样本拼起来训练就行 | 不切断样本之间的注意力就会串台。按样本边界切断（`position_ids` 加变长 FlashAttention）后，吞吐在 FLAN 上约 2 倍、在 OrcaMath 上约 1.4 倍，验证 loss 不变（[HF 博客](https://huggingface.co/blog/packing-with-FA2)）。 |
| `mean-of-means` | 每个 micro-batch 先求平均、再把这些平均数平均，和全局平均一样 | 不一样。2024 年 10 月修复之前，HF 的梯度累积就有这个 bug（[HF 博客](https://huggingface.co/blog/gradient_accumulation)）。 |

### 交互规格

**I1 "谁在算 loss"**（零件 `token_loss_mask`）
- **变量：**
  - 掩码模式：整段 / 只算回答 / 只算助手轮（多轮）；
  - 提示权重 λ ∈ [0, 1]，对数刻度滑块，含 0；
  - 也可以单击任意 token，切换它的 $m_t$。
- **学生做什么：** 先完成第 4 段的预测，然后切换模式、拖动 λ、点 token。
- **画面：**
  - 每个 token 一个格子，颜色深浅表示这个位置的 $-\log p(y_t)$；
  - 格子下方的小柱表示 logits 梯度的大小 $\lVert p_t-e_{y_t}\rVert$；
  - 右侧一个堆叠条，显示 loss 总和里"回答 / 提示 / 模板 token"各占多少。
- **应该注意到：**
  - 提示比回答长 15 倍时，即使回答每个 token 的 loss 更高，整段的 loss 总和也是提示占大头；
  - `<|im_start|>`、`assistant` 这类模板 token 的 loss 接近 0，几乎不产生梯度；
  - λ = 0.1 时，回答的份额就已经回到大头。
- **结束时的问题：** "λ 从 0 拖到 1，回答在 loss 总和里的份额从 100% 降到了多少？什么样的数据集上，给提示一点权重反而有好处？"答对的要点：回答短、提示长、数据少的时候，提示 loss 起正则作用、减轻过拟合（Shi）。
- **数据：** 真实数据，离线计算。
  - 用 Qwen2.5-0.5B 基座给一段 Qwen 模板对话打分：提示约 300 token，含 system；回答约 20 token；
  - 存每个位置的 $p(y_t)$ 和 top-20 概率；
  - 梯度大小用 top-20 加"其余概率合为一项"来计算，界面上注明这是近似。
- **三条准则：**
  - **关系：** 掩码和 λ 决定 loss 总和怎样分给回答和提示。"模板 token 的 loss 几乎为 0"和"提示 loss 的量级"这两件事，学生无法凭空想到。
  - **形式：** 点一个 token 就是改它的 $m_t$，拖滑块就是改提示权重，和 TRL 里的配置项一一对应。
  - **以问题收尾：** 第 4 段先预测，最后回答上面的问题。
- **世界：**
  - 目标 1：把回答的份额调到 ≥ 90%（λ ≤ 某个值，或只算回答）；
  - 目标 2：在多轮样本上切到"只算助手轮"，并确认最后的 `<|im_end|>` 是计入 loss 的。
  - 检测器：如果学生把助手轮末尾的结束 token 也掩掉了，记误区 `pad-eos-harmless`，并接到 I2。
  - `solve`：单轮样本切到"只算回答"；多轮样本切到"只算助手轮"。

**I2 "它为什么停不下来"**（零件 `pad_eos_trap`）
- **变量（三个开关，都是真实的配置项）：**
  1. pad token：设成 EOS（Llama 3 的 `<|eot_id|>`）/ 专用的 pad token；
  2. labels 怎么掩：按 attention_mask 掩 / 按 `token id == pad_token_id` 掩。第二种就是 `DataCollatorForLanguageModeling` 的做法；
  3. 生成时的停止符：`<|eot_id|>` / `<|end_of_text|>`。
- **学生做什么：** 切换开关，看一个填充后的 3 条样本的 batch：
  - input_ids 一行、labels 一行，被掩的格子是灰色；
  - 计数器："EOS 作为训练目标出现了几次"。
- **右侧"后果"面板（示意，明确标注）：**
  - 机制部分是精确的：这一 batch 里"EOS 作为训练目标"的次数，以及 labels 行本身；
  - 后果用一段标注为"示意"的生成条表示：EOS 训练目标为 0 时，生成一直写到长度上限；停止符不一致时，模型输出了结束标记但生成器不认。不使用训练出来的检查点（协调者决定，2026-10-10）。
- **应该注意到：**
  - 只有"pad = EOS"加"按 id 掩"这一种组合会让 EOS 的训练目标计数变成 0。这时 P(EOS) 很低，生成一直写到长度上限。
  - 停止符和训练时的轮次结束 token 不一致，也会停不下来，原因不同：模型输出了结束标记，但生成器不认。
- **结束时的问题：** "给出两种只改一个设置的修法，并说出各自修的是哪一环。"
  - 修法一：用专用 pad，或按 attention_mask 掩，修的是训练目标；
  - 修法二：停止符设成轮次结束 token，修的是推理。
- **数据：**
  - batch、labels、计数都是精确计算（就是 collator 的真实规则）；
  - 生成条是示意，界面上写明。
- **三条准则：**
  - **关系：** 三个设置的组合决定哪个 label 被掩、模型会不会停。这个组合效应，文字只能断言。
  - **形式：** 开关就是代码里的配置。
  - **以问题收尾：** 开场先问"pad 设成 EOS 会出事吗？"，最后回答上面的问题。
- **世界：**
  - 目标：找到一个能正常停下的配置；
  - 检测器：学生在 bug 组合下点"看起来没问题"时，记误区 `pad-eos-harmless`；
  - `solve`：把 pad 设成专用 token。

**I3 打包与注意力掩码**（零件 `attention_mask_packing`）
- **变量：**
  - 4 条样本的长度：拖动长度条的末端；
  - 每行的最大长度 `max_length`；
  - 模式：填充 / 直接拼接（因果注意力）/ 拼接并按边界切断（`position_ids` 加 varlen）。
- **画面：**
  - 上方：token 布局条，pad 为灰色；
  - 中间：注意力矩阵，因果下三角；跨样本的格子标红，并在格子上加斜线纹，不只靠颜色区分；
  - 下方：`position_ids` 一行；
  - 读数：填充浪费 %、跨样本格子 %。
- **学生做什么：**
  - 先预测"4 条等长样本直接拼接，跨样本格子占多少"；
  - 再拖动长度；
  - 最后切到"按边界切断"。
- **应该注意到：**
  - 直接拼接时，跨样本格子的比例约为 1 − 1/k（k 是拼进去的样本数）。4 条样本就是约 75%，不是"一点点"。
  - 填充的浪费取决于长度的离散程度。
  - 按边界切断后两者都归零，代价是需要变长注意力内核，而且 loss 的加权方式变了（接到第 11 段）。
- **结束时的问题：** "预训练常常直接拼接不切断，为什么 SFT 推荐切断？切断后什么变了，什么没变？"
  - 要点：SFT 的样本短而且相互独立，串台的比例高；切断后吞吐收益保留，验证 loss 和不打包时一样（[HF 博客](https://huggingface.co/blog/packing-with-FA2)）。
  - 变的是：按样本平均的 loss 变成了按 token 平均。
- **计算：** 精确计算。
- **三条准则：**
  - **关系：** 长度和模式决定"浪费 vs 串台"，是非线性的取舍。
  - **形式：** 拖长度就是换数据，切模式就是换 collator 或打包策略。
  - **以问题收尾：** 先预测，最后回答上面的问题。

### 推导全文

**D1 带掩码和权重的损失，以及它的梯度**
1. 第 i 条样本第 t 个位置的权重：$w_{i,t}=1$（回答）、$\lambda$（提示）、$0$（pad 或不训练的部分）。
2. $L(\theta)=-\dfrac{1}{Z}\sum_i\sum_t w_{i,t}\log p_\theta(y_{i,t}\mid y_{i,<t})$，归一化常数 $Z$ 的选法见 D2。
3. 记 $\ell_t=-\log\mathrm{softmax}(z_t)_{y_t}$，则 $\partial \ell_t/\partial z_t = p_t - e_{y_t}$，其大小 $\lVert p_t-e_{y_t}\rVert^2=(1-p_{y})^2+\sum_{j\ne y}p_j^2$。
   - $p_y\to1$ 时它趋于 0，所以模板 token 几乎不产生梯度。
4. $w_{i,t}=0$ 的位置，第 3 步那一项直接是 0。
   - 但对于 $s<t$ 的提示位置，回答位置 t 的 loss 关于隐藏状态 $h_s$ 的梯度 $\partial \ell_t/\partial h_s\neq 0$，因为注意力会读到 $h_s$。
   - 结论：**掩码去掉的是"预测提示"这个任务，并没有切断提示对学习的影响。**
5. 回答在 loss 总和里的份额 $=\dfrac{\sum_{R}\ell_t}{\sum_R\ell_t+\lambda\sum_P\ell_t}$，和 $Z$ 无关。I1 里显示的就是它。
   - 填空：$|P|=300$，提示 token 平均 loss 为 1.5；$|R|=20$，回答 token 平均 loss 为 2.5。λ = 1 时，回答份额 = 50/(50+450) = **10%**；λ = 0.1 时 = 50/95 ≈ **53%**。

**D2 归一化与梯度累积**
1. **三种 Z：**
   - 按 token 平均：$Z=\sum_{i,t}w_{i,t}$；
   - 按样本平均：每条样本先除以自己的 token 数，再除以样本数 B；
   - 求和：$Z=1$（Tülu 3）。用求和时，"每步的有效学习率"会随这一批的 token 数变化，所以学习率要相应调小。
2. **两种平均对长短样本的权重：**
   - 按样本平均时，样本 i 的每个 token 权重为 $1/(B\,N_i)$；
   - 按 token 平均时，每个 token 都是 $1/\sum N$；
   - 所以按 token 平均会让回答长的样本在总梯度里占更多。
3. **梯度累积，K 个 micro-batch：**
   - 记第 k 个 micro-batch 的有效 token 数为 $N_k$、loss 和为 $S_k$；
   - 正确的全局 token 平均：$L=\sum_k S_k/\sum_k N_k$；
   - 有 bug 的写法：$L'=\frac1K\sum_k S_k/N_k$。
4. **数字例子：**
   - micro-batch A：1 条样本，10 个 token，$S=20$；micro-batch B：1 条样本，990 个 token，$S=990$。
   - $L=1010/1000=1.01$，$L'=(2.0+1.0)/2=1.5$。
   - A 中每个 token 的权重：正确写法下是 1/1000，有 bug 时是 1/20，**放大了 50 倍**。
5. **修法：**
   - 先数出整个累积窗口的 $\sum_k N_k$，每个 micro-batch 用 $S_k/\sum N$ 反传；
   - transformers 的修复就是把 `num_items_in_batch` 传给损失函数（[HF 博客](https://huggingface.co/blog/gradient_accumulation)）。
6. **打包：** 一行里装了几条样本，如果代码"按行平均"，按样本平均就悄悄变成了行内按 token 平均。打开打包可能改变长短样本的相对权重（[技] §2）。
   - 填空：多卡训练时还要再跨卡汇总一次 $\sum N$。

**D3 打包的两个比例**
1. **填充的浪费：** 一个 batch 的长度为 $n_1..n_B$，都填充到 $\max n$，浪费 $=1-\sum n_i/(B\max n)$。
   - 例：长度为 100、300、900、200，浪费 = 1 − 1500/3600 ≈ **58%**。
2. **直接拼接时的跨样本格子：**
   - 一行总长 $n=\sum n_i$，因果注意力的格子数为 $n(n+1)/2$，样本内部的格子数为 $\sum n_i(n_i+1)/2$；
   - 跨样本比例 $=1-\dfrac{\sum n_i(n_i+1)}{n(n+1)}$。
3. **例：** 4 × 256 拼成 1024：1 − 4·256·257/(1024·1025) = 1 − 131584/524800 ≈ **75%**。k 条等长样本时约为 1 − 1/k。
4. **按边界切断：** 每条样本内部从 0 开始编 `position_ids`，varlen 内核按 `cu_seqlens` 只在块对角内做注意力，跨样本比例为 0；padding-free 时浪费也为 0。

### 检验题
1. **计算（number）：** 梯度累积 2 步。
   - micro-batch A：2 条样本，共 30 个回答 token，loss 和 60；micro-batch B：1 条样本，270 个回答 token，loss 和 270。
   - 问：正确的全局 token 平均 loss 是多少？
   - **答案：** 330/300 = **1.10**。
   - **判分：**
     - 答 1.5 → 误区 `mean-of-means`，反馈："A 的每个 token 被放大了 5 倍（1/60 对 1/300）"；
     - 答 2.0 或 1.0（只看了一个 micro-batch）→ 提示回到 D2 第 3 步。
2. **诊断（choice + 解释）：** "训练 loss 稳定下降，但生成和训练前几乎一样，而且常常不停。"选出最可能的两个原因，并各写一个验证方法。
   - **正确选项：**
     - (a) loss 大部分算在提示或 system 上；
     - (c) 回答末尾的结束 token 被掩掉了（pad = EOS 加按 id 掩码）。
   - **干扰项：**
     - (b) 学习率太大：通常表现为 loss 尖刺，不是"没变化"；
     - (d) 模型太小。
   - **判分要点：** 验证方法要具体，例如"打印 labels 看回答末尾的 `<|eot_id|>` 是不是 −100"、"统计 labels ≠ −100 的 token 中回答占多少"。
3. **预测（choice）：** 一个数据集有 2,000 条样本，平均提示 400 token、回答 15 token。λ = 0、0.1、1 三种设置，哪个最可能在留出集上最好？
   - **答案：** 0.1。
   - **判分：** 以理由为主。说出"短回答、长提示、数据少时，小权重减轻过拟合（Huerta-Enochian、Shi）"即得满分；只答选项得一半分。
   - 解释框注明：这是有条件的经验结论，不是定律。
4. **解释（AI 判读）：** "提示被掩掉以后，模型的提示部分还会被训练吗？"
   - **要点：** 会。提示位置的隐藏状态通过注意力参与预测回答，回答的 loss 会把梯度传回去；被掩掉的只是"预测提示的下一个 token"这个任务。
   - 只答"不会"判错，记误区 `mask-dogma`。

**概念测验候选：** "SFT 和预训练的损失函数有什么不同？"（只有数据和掩码不同。）

### "怎么选"卡片（B1 加到决策图上的）
- **节点：** DM-B1、DM-B2、DM-K4（编号见 [part-f-choosing.md](part-f-choosing.md) 第 1 节）。用到本卡的检验题：Q3。

### 学完能做到
1. **比较数据来源：** 对一个任务列出 4 种数据来源，并比较各自的成本、质量控制、风险（含许可）：
   - 人工标注；
   - 强模型合成；
   - 拒绝采样或自举；
   - 序列级蒸馏。
2. **算拒绝采样的产出：** 给一组题目的通过率 p 和每题采样数 n，算出覆盖率 $1-(1-p)^n$ 和数据集里各难度的占比；解释"数据偏向简单题"，并给出两种修法。
3. **联系 RL：** 说出"只在正确样本上做 SFT"等于二值奖励下、离线走一步的策略梯度，并说出它缺了什么：没有基线，也没有负信号。
4. **做领域适配的选择：** 在继续预训练、SFT、RAG 之间做选择或组合；写出防遗忘的数据配比；知道什么时候要扩词表、怎样训练嵌入层。
5. **工具调用数据：** 为一条工具调用（tool calling）对话写出哪些 token 计入 loss，并说出这类数据通常怎么造、怎么验证。

### 要解开的误解

| id | 误解 | 实际情况与证据 |
|---|---|---|
| `more-data-better` / `few-examples-suffice` | 两个相反的极端："数据越多越好"，或者"1,000 条就够" | 要分任务看。<br>• **格式和风格：** 少而精就够。LIMA 用约 1,000 条精选样本，人评中 43% 的比较不输 GPT-4（[LIMA](https://arxiv.org/abs/2305.11206)），而且 LIMA 自己的消融显示，只加数量而不加多样性没有帮助。<br>• **激发推理：** 底座够强时，少量也行。s1 用 1,000 条推理轨迹，在 MATH/AIME 上最多超过 o1-preview 27%（[s1](https://arxiv.org/abs/2501.19393)）。<br>• **数学、代码、多跳推理：** 这类真实能力随数据量按幂律提升（[Raghavendra 2024](https://arxiv.org/abs/2410.03717)）。 |

| `tool-output-trained` | 工具调用数据整段都算 loss | 工具返回的内容是环境的输出，不是模型的输出。在它上面算 loss，等于教模型自己编工具结果。工具返回要像提示一样掩掉（B1 的规则推广过来）。 |

- **变量：**

  - 最后开"难题加采"。

  - n = 8、不设上限时，难题占题目的 30%，在数据里却只占约 1.5%，而且只有约 15% 的难题出现过；

- **结束时的问题：** "为什么拒绝采样的数据会偏向模型本来就会的题？这对'用它来提高能力'意味着什么？"

  - 二项分布期望值的精确计算；
  - 三类题的通过率分布是示意数值，界面上标注"示意"（不跑 GSM8K）。

  - **关系：** n、c 和数据集构成之间是非线性关系，"偏向简单题"的程度凭空想不出来。
  - **形式：** 拖 n 就是采样预算，c 就是去重或上限策略，加采就是按难度分配预算，都是真实的数据工程决策。

- **世界：**
  - 目标：在总采样预算 ≤ 1,600（100 道题）内，让难题在数据集里占 ≥ 10%；

### 推导全文

**D1 覆盖率与数据偏斜**
1. 题 j 的通过率为 $p_j$，采 n 次，正确次数 $X_j\sim\mathrm{Bin}(n,p_j)$。
2. 题 j 至少有一个正确样本的概率：$P(X_j\ge1)=1-(1-p_j)^n$。
3. 不设上限时，题 j 期望保留 $E[X_j]=np_j$ 条，所以数据集里各类题的份额 ∝ 题目数 × p。
4. **数字（第 5 段的题，100 道题，n = 8）：**
   - 每题期望保留：简单 7.2、中等 2.4、难 0.16 条；
   - 合计：30×7.2 + 40×2.4 + 30×0.16 = 216 + 96 + 4.8 = 316.8；
   - 份额：简单 68.2%、中等 30.3%、**难 1.5%**；
   - 难题的覆盖率：$1-0.98^8\approx0.149$。
5. **每题上限 c = 1：** 每题期望保留 $P(X_j\ge1)$ 条，即简单约 1.00、中等 $1-0.7^8\approx0.942$、难 0.149。份额：简单 41.4%、中等 52.1%、**难 6.2%**。
6. **难题加采到 n = 64：** 覆盖率为 $1-0.98^{64}\approx0.726$。
   - 填空：p = 0.05、n = 16 时，覆盖率 = ？（≈ 0.56）

**D2 拒绝采样 SFT 与策略梯度**
1. 目标：$J(\theta)=\mathbb E_x\,\mathbb E_{y\sim\pi_\theta}[r(x,y)]$。策略梯度：$\nabla J=\mathbb E[r\,\nabla\log\pi_\theta(y\mid x)]$。D2 会从头推它（REINFORCE），这里先当作公式卡片使用。
2. 从 $\pi_{\text{old}}$ 采 $y_1..y_n$，在 $\theta=\theta_{\text{old}}$ 处的蒙特卡洛估计：$\hat g=\frac1n\sum_i r_i\nabla\log\pi_\theta(y_i\mid x)$。
3. 当 $r\in\{0,1\}$ 时，$\hat g=\frac1n\sum_{i:\,r_i=1}\nabla\log\pi_\theta(y_i\mid x)$。这正是"只在正确样本上做 SFT"的梯度，每题的权重 ∝ 正确数，和 D1 第 3 步一致。
4. **它缺什么：**
   - $r=0$ 的样本权重为 0，没有"往下推"的信号；
   - 没有基线：GRPO 会减去组内均值，见 E1；
   - 只在第一步是 on-policy 的，之后样本就过时了。所以要"采样 → 过滤 → SFT"循环几轮，这就是专家迭代（expert iteration；ReST^EM 把它解释为 EM 算法，[补]）。
5. **每题上限 c 的含义：** 它改变了每题的权重，不再是无偏估计。换来的是难度更均衡，这是一个有意的取舍。

**D3 序列级蒸馏是正向 KL**
1. $\mathbb E_{y\sim\pi_T}[-\log\pi_S(y\mid x)]=H(\pi_T)+\mathrm{KL}(\pi_T\Vert\pi_S)$。
2. $H(\pi_T)$ 与学生的参数无关，所以"用老师的样本做 SFT"就是在最小化正向 KL(老师‖学生)，覆盖老师的所有模式。
3. 前瞻：E3 会讲反向 KL 和在线蒸馏，以及它们为什么更"挑峰"。

### 检验题
1. **计算（number）：** 某类题通过率 0.05，每题采 16 次，至少得到一个正确样本的题占多少？

2. **选择（解释，AI 判读）：** 一家律所有 10 万份内部合同。他们希望模型：
   - (a) 按事务所的固定格式写审查意见；
   - (b) 回答时引用具体条款。
   请给出方案、数据怎么准备、主要风险。
   - **要点：**
     - (b) 用 RAG（要能追溯、内容会更新）；
     - (a) 用 SFT：数据可以用强模型在检索到的条款上合成审查意见，再由律师抽检；
     - CPT 只在领域语言和基座差异很大、而且 token 量充足时才考虑，并且要混入对话数据；
     - 风险：合成数据只学到风格、事实出错（Gudibande、Gekhman）；客户数据的许可。
   - **判分：** 方案 2 分、数据 2 分、风险 1 分。
3. **诊断（choice）：** "用强模型合成了 5 万条客服对话做 SFT。人评说语气很像，但事实错误比原模型多了。"最可能的原因是？
   - **答案：** 合成数据里有原模型不知道的事实，模型学到的是风格加上自信地编造（Gekhman 的"未知事实增加幻觉"，加上模仿只得风格）。
   - **干扰项：** 学习率太低；数据太少；没有打包。
   - **修法：** 用 RAG 提供事实；过滤掉原模型不知道的样本；早停。
4. **解释（AI 判读）：** "只在正确样本上做 SFT，和策略梯度是什么关系？少了什么？"
   - **要点：** 等于二值奖励下、在采样那一刻的策略梯度估计；少了负样本信号和基线；离线，所以要迭代。
   - 能说出其中两点即可。

**概念测验候选：** "用 GPT 级模型的输出微调小模型，小模型就获得了同等能力吗？"（不会；主要得到风格。）

### 学完能做到
1. **起始超参：** 为全量或 LoRA 的 SFT 给出起始超参（学习率、轮数、batch、预热），说出每个数的出处和调整方向。
2. **读曲线选检查点：** 看 train/val loss 加上任务评测的曲线，区分"正常 / 过拟合 / 学习率过大 / 掩码错误"四种情况，并用任务评测（而不是验证 loss）选检查点。
3. **设计评测：** 设计一份评测清单：
   - 任务留出集；
   - 通用能力回归；
   - 安全回归；
   - 大模型评委（附偏差对策）。
4. **报告评测：** 算出"200 道题上相差 3 分是否可信"，报告置信区间，并知道配对分析能把区间缩小多少。

### 要解开的误解

| id | 误解 | 实际情况与证据 |

### 交互规格

**I1 评测的噪声**（零件 `eval_noise`）
- **变量：**
  - 题数 n：10–5000，对数刻度（E2 用 n = 30 讲 AIME 的噪声）；
  - 两个模型的真实正确率 $p_A$、$p_B$，默认 0.70 和 0.73；

  - 一个按钮"重新抽一个评测集"。
- **画面：**
  - 观测差值 $\hat p_B-\hat p_A$ 的分布曲线（正态近似，精确公式）；
  - 小于 0 的部分涂色并加纹理，即"排名翻转的概率"；

  - 每按一次按钮，在分布上落一个点（固定种子模拟）。
- **学生做什么：**
  - 预测："n = 200、相差 3 分，B 在评测里反而输给 A 的概率是多少？"（<5% / 约 10% / 约 25% / 约 50%）
  - 然后拖 n，切换配对。
- **应该注意到：**
  - n = 200、独立比较时，翻转概率约 25%，差值的 95% 区间约 ±8.8 分；
  - 改成配对分析（同一批题，不一致率 10%）后，区间缩到约 ±4.4 分，翻转概率约 9%；
  - 想把独立比较的区间缩到 ±3 分，需要大约 1,700 题。
- **结束时的问题：** "你的新检查点在 200 道题上比旧的高 3 分，你会怎么报告？要多大的评测集，或者用什么分析方法，才能下结论？"
  - 要点：报告置信区间；用配对分析；或者扩大评测集（[补] Miller 2024）。
- **计算：** 精确计算（二项分布的正态近似），模拟抽样用固定种子。
- **三条准则：**
  - **关系：** n、差距、配对和翻转概率之间是 √n 关系，学生系统性地低估噪声。
  - **形式：** 拖 n 就是决定评测集多大，切配对就是换分析方法，按钮就是"换一份评测集"。
  - **以问题收尾：** 先预测，最后回答上面的问题。
- **世界：**
  - 目标：在"独立比较"下，找到让翻转概率 < 5% 的最小 n；
  - `solve`：n ≈ 1,225（由 $0.03/\sqrt{0.4071/n}=1.645$ 解出，见推导 D2 第 4 步；目标容差 ±10%）。

### 推导全文

**D1 为什么验证 loss 会和质量背离**
1. $\mathbb E_{y\sim D(\cdot\mid x)}[-\log\pi(y\mid x)]=H(D)+\mathrm{KL}(D\Vert\pi)$。
2. 最小化验证 loss，就是最小化正向 KL。它要求 π 给**每一种**参考写法都留概率（覆盖）。
3. 训练轮数一多，π 会变尖：熵下降，对某一种好写法很自信。
   - 参考答案里的其他写法在 π 下概率变小，所以正向 KL 上升，验证 loss 上升；
   - 但从 π 采样得到的回答可以更好。人评和奖励模型评的正是这些样本。
4. 结论：验证 loss 和"样本质量"衡量的是两件事，要用任务评测选检查点（接 E3 讲正向和反向 KL）。

**D2 评测的置信区间**
1. 单个模型：$\mathrm{SE}=\sqrt{p(1-p)/n}$。p = 0.7、n = 200 时，SE = 0.0324，95% 区间为 ±6.35 分。
2. **两个模型，独立比较：**
   - $\mathrm{SE}_\Delta=\sqrt{(p_Aq_A+p_Bq_B)/n}=\sqrt{(0.21+0.1971)/200}=0.0451$，95% 区间为 ±8.8 分；
   - 真实差距 3 分时，翻转概率为 $\Phi(-0.03/0.0451)=\Phi(-0.665)\approx0.25$。
3. **配对比较（同一批题）：**
   - 每题的差值 $d_i\in\{-1,0,1\}$。设两模型不一致的题占 10%（B 对 A 错 6.5%，A 对 B 错 3.5%）；
   - $\mathrm{Var}(d)=0.10-0.03^2=0.0991$，$\mathrm{SE}=\sqrt{0.0991/200}=0.0223$，区间为 ±4.4 分；
   - 翻转概率为 $\Phi(-1.35)\approx0.09$。
4. **独立比较时，要把区间缩到 ±3 分：** $n=1.96^2\times0.4071/0.03^2\approx1{,}738$。
   - 填空：要让翻转概率 < 5%，需要 $0.03/\sqrt{0.4071/n}\ge1.645$，即 n ≥ ？（≈ 1,225）

### 检验题
1. **计算（number）：** 两个检查点在同一份 400 题的评测集上，正确率分别是 0.80 和 0.82，按独立比较算，差值的 95% 置信区间半宽是多少分？
   - **答案：** $1.96\sqrt{(0.16+0.1476)/400}=1.96\times0.02773\approx$ **5.4 分**，容差 0.3。
   - **判分：** 答 2 分或"显著" → 误区 `eval-small-diff-real`。
2. **诊断（choice）：** "train loss 在 50 步内从 2.1 掉到 0.3，之后平稳；只算回答的 val loss 和任务正确率完全不动。"
   - **答案：** 掩码错误：loss 主要算在一段很长、每条都一样的 system 提示上，模型很快就背下来了。
   - **干扰项：** 过拟合；学习率过大；数据太少。
3. **选择（choice，选两项）：** "你用一个强模型当评委比较新旧两个模型，新模型胜率 62%；新模型的回答平均长 40%。"下一步最该做的两件事是？
   - **答案：** 交换 A/B 顺序重判并报告一致率；做长度控制（或报告长度、按长度分层比较）。
   - **干扰项：** "62% 已经足够，直接上线"（误区 `judge-objective`）；"换一个同家族更大的评委"。
   - **判分：** 两项都对得满分；能补充"用约 100 条人工标注校准评委"的，在解释框里给予肯定。

## B4 遗忘

- **时长：** 约 21.5 分钟

  - 正向 KL 的公式卡片（B2 推导 D3）。
- **技能 id：** `forgetting`、`forgetting-kl`、`forgetting-mitigation`
- **误区 id：** `clean-data-safe`、`forgetting-distance`、`lora-no-forgetting`

### 学完能做到
1. **两个山谷：** 用"两个山谷"解释遗忘，预测学习率、步数、回放比例对新旧任务 loss 的影响。
2. **证据：** 说出三类遗忘证据（持续指令微调、安全对齐被削弱、涌现不对齐），并说明为什么用"干净"数据也会遗忘。
3. **RL's Razor：** 说出它的结论——遗忘取决于在新任务分布上相对基座的 KL，而不是参数挪了多远；并能写出怎么估计 KL(π_ft‖π_0)。
4. **选缓解办法：** 为一个场景选遗忘的缓解手段，并用 B3 的回归评测给出验证方法。

### 要解开的误解

| id | 误解 | 实际情况与证据 |
|---|---|---|
| `clean-data-safe` | 用干净、正常的数据微调不会伤害别的能力 | 用良性数据微调也会削弱安全性；10 条对抗样本（不到 0.2 美元）就能破坏 GPT-3.5 的安全对齐（[Qi et al.](https://arxiv.org/abs/2310.03693)）；在不安全代码上做窄领域微调，会带来广泛的"涌现不对齐"（[Nature 2026](https://arxiv.org/abs/2502.17424)）。 |
| `forgetting-distance` | 参数挪得越远，忘得越多 | RL's Razor：预测遗忘的是新任务分布上的 KL(微调后‖基座)，不是权重变化的大小（[2509.04259](https://arxiv.org/abs/2509.04259)）。 |
| `lora-no-forgetting` | LoRA 不会遗忘 | 忘得少，但不是零（[Biderman](https://arxiv.org/abs/2405.09673)；[技] §7）。 |

### 交互规格

**I1 两个山谷**（零件 `two_valleys_forgetting`）
- **地形（示意模型，二维二次函数）：**
  - 旧任务：$L_{old}(\theta)=\tfrac12(\theta-\theta_0)^\top H_{old}(\theta-\theta_0)$，$\theta_0=(0,0)$ 是基座；
  - 新任务是一条长槽：$L_{new}(\theta)=\tfrac12\cdot8(\theta_1-2)^2+\tfrac12\cdot0.02(\theta_2-3)^2$。槽底沿着 $\theta_2$ 方向，最低点在 (2, 3)。
  - 预设 A：$H_{old}=\mathrm{diag}(1,1)$；
  - 预设 B："旧任务不在乎的方向"，$H_{old}=\mathrm{diag}(1,0.05)$。
- **变量：**
  - 学习率 η：0.005–0.3，对数刻度；
  - 步数：0–3000，可拖动的数字；
  - 回放比例 ρ：优化 $(1-\rho)L_{new}+\rho L_{old}$；
  - SGD 噪声：大小 ∝ η，固定种子；
  - 进阶开关：参数空间的锚 $\tfrac\beta2\lVert\theta-\theta_0\rVert^2$。
- **画面：**
  - 两组等高线；
  - 参数轨迹；
  - 右侧两条小曲线：新任务 loss 和旧任务 loss 随步数变化；
  - 读数："参数移动距离"和"旧任务 loss"并排显示。
- **学生做什么：**
  - 先完成第 2 段的预测；
  - 再拖 η、步数、ρ；
  - 最后切到预设 B。
- **应该注意到：**
  1. 1,000 步时，η = 0.02 和 η = 0.2 下新任务 loss 差不多（陡的方向都已收敛）。但 θ₂ 分别走到约 0.99 和约 2.95，旧任务 loss 分别约 2.5 和约 6.4，差了约 2.5 倍。
     - 原因：在槽底慢慢"漂移"的速度 ∝ η。
     - η 超过 2/8 = 0.25 时，陡的方向开始发散。
  2. 新任务 loss 已经平了，继续训练，旧任务 loss 还在涨。
  3. ρ = 0.3 时，新任务 loss 只升到约 0.12，旧任务 loss 从 6.5 降到约 1.8。
     - 原因：回放约束的是新任务不在乎的方向，所以几乎不花新任务的代价。
  4. 预设 B 里，参数走得很远，旧任务 loss 却不高，所以"移动距离 ≠ 遗忘"。
     - 这是 RL's Razor 的二维示意：要看的是行为（分布）变了多少，不是参数挪了多远。
- **结束时的问题：** "新任务 loss 已经不降了，再训 2,000 步会发生什么？为什么回放这么便宜？"
- **计算：** 在示意地形上做精确的梯度下降，固定种子的噪声。界面上的标注："示意模型：真实模型有数十亿维；遗忘取决于输出分布的变化（RL's Razor），不是参数距离；二维地形只用来看学习率、步数、回放的作用。"
- **为什么没有 LoRA 开关：** 二维参数点上的"一维子空间"和低秩矩阵并不同构，加了会违反第 2 条准则。LoRA 忘得少这一点用 C2 的重绘曲线（Biderman）来讲。
- **三条准则：**
  - **关系：** η、步数、ρ 与新旧两个 loss 的动态关系（尤其是收敛后的漂移和回放的低代价），文字只能断言。
  - **形式：** 拖 η 就是学习率，拖步数就是训练时长，拖 ρ 就是数据配比，都是真实的旋钮。
  - **以问题收尾：** 先预测，最后回答上面的问题。
- **世界：**
  - 目标 1（早停）：ρ = 0 时，在步数 ≥ 300 的条件下做到 $L_{new}<0.15$ 且 $L_{old}<2.2$。这要求小学习率加早停，例如 η = 0.02、500 步时 θ₂ ≈ 0.54、$L_{old}\approx2.15$。
  - 目标 2（长期稳定）：步数 ≥ 2,000 时仍做到 $L_{new}<0.15$ 且 $L_{old}<2.0$。只靠早停做不到（槽底上 $L_{old}\ge2$），必须用回放或锚。
  - 检测器：η 拖到 ≥ 0.25（陡的方向发散）时给出提示；
  - `solve`：先 η = 0.02、500 步（目标 1），再 ρ = 0.3、η = 0.05、2,000 步（$L_{new}\approx0.12$，$L_{old}\approx1.81$，目标 2）。

### 推导全文

**D1 测量遗忘的 KL，以及权重插值**
1. $\widehat{\mathrm{KL}}=\frac1{N}\sum_{x\in\text{新任务}}\sum_{t}\big[\log\pi_{ft}(y_t\mid x,y_{<t})-\log\pi_0(y_t\mid x,y_{<t})\big]$，其中 $y\sim\pi_{ft}$。
2. 这是逐 token 的无偏估计（k1 估计量）。
   - 填空：3 个 token 上，$\log\pi_{ft}$ 为 −0.1、−0.5、−0.2，$\log\pi_0$ 为 −0.4、−1.5、−0.3，平均 KL 估计 = ？（(0.3 + 1.0 + 0.1)/3 ≈ 0.47）E1 会讲 GRPO 里用的 k3 估计量。
3. 实际操作：每隔一段时间用这个数监控遗忘，它比只看参数变化更能预测遗忘（RL's Razor）。
4. 权重插值（WiSE-FT）：$\theta_\alpha=(1-\alpha)\theta_0+\alpha\theta_{ft}$，α 从 1 往下调，在新任务指标和回归评测之间找折中点（[WiSE-FT](https://arxiv.org/abs/2109.01903) 源于视觉模型；同一基座的权重合并见 E3）。

### 检验题
1. **选择（text，AI 判读）：** 你在客服对话上做了 SFT，任务指标提升了 6 分，但 IFEval 掉了 9 分，拒答测试集的通过率也下降了。给出两种缓解办法，并说出各自怎么验证。
   - **要点（任选两条，每条要有验证方法）：**
     - 混入通用对话或指令数据做回放（重跑 IFEval）；
     - 降低学习率或减少步数（画出新旧指标随步数的变化）；
     - 换用 LoRA（同上）；
     - 用旧模型做在线蒸馏或加 KL（E3）；
     - 加入安全数据，并重跑安全评测（Qi）。
2. **计算（number）：** 从 π_ft 采样了 3 个 token，$\log\pi_{ft}$ 分别为 −0.1、−0.5、−0.2，$\log\pi_0$ 分别为 −0.4、−1.5、−0.3。逐 token KL 估计的平均值是多少？
   - **答案：** (0.3 + 1.0 + 0.1)/3 ≈ **0.47**，容差 0.02。
   - **判分：** 答 −0.47（减反了）→ 提示"是 log π_ft − log π_0，样本来自 π_ft"。
3. **解释（text，AI 判读）：** "为什么 RL's Razor 说参数挪动的距离不是遗忘的好预测量？在两个山谷的哪个预设里能看到这一点？"
   - **要点：** 遗忘看的是旧任务上的行为（输出分布）变了多少；有些方向旧任务根本不在乎，在这些方向上走得再远也不遗忘；预设 B。

**概念测验候选：** "只用干净、无害的数据微调，模型的安全性就不会变差吗？"（会变差，Qi et al.）

### "怎么选"卡片（B4 加到决策图上的）
- **节点：** DM-X3（编号见 [part-f-choosing.md](part-f-choosing.md) 第 1 节）。用到本卡的检验题：Q1。
- **规则：** 改了权重，就必须跑通用能力和安全两类回归评测（B3 的第②层）。
- **规则：** 新任务和旧能力都要 → 默认用回放（约 3 成通用数据）加较小的学习率；还不够时用 LoRA、KL 约束或在线方法（E3）。
- **规则：** 训练中监控 KL(π_ft‖π_0)，它是遗忘的早期信号。
- **反例：** "数据都是干净的，不用测安全"不成立（Qi et al.）。
- **反例：** "用了 LoRA 就不会遗忘"不成立：忘得少，不是零（Biderman）。
