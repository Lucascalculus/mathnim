# 专题课程设计：大模型微调（LLM Fine-tuning）

2026-10-10 起草。依据两份调研（教法与学习难点、截至 2026 年的技术现状），关键出处列在文末。

## 0. 课程定位

### 0.1 验收标准："真的讲懂"

学完以后，学生在**没有看过答案**的新情境里能做到下面五件事。每一件都对应课程里的检验题（见第 5 节）。

1. **预测**：改一个旋钮之前，能说出会发生什么，以及为什么。例如：把 LoRA 的秩调大、把 DPO 的 β 调小、去掉 loss 掩码、提高学习率。
2. **计算**：能估算一个具体配置要多少显存，例如 8B 模型分别做全量微调、LoRA、QLoRA；能算出 LoRA 的可训练参数量。
3. **诊断**：看到训练曲线或症状，能说出最可能的原因。例如：loss 在降但模型什么都没学会；DPO 的 loss 在降，被选回答的概率也在降；GRPO 的回答越来越长。
4. **选择**：给一个业务场景，能在提示词、RAG、SFT、偏好优化、强化学习之间做选择，并说出理由。
5. **解释**：能用自己的话讲清几条核心机制：为什么低秩就够、为什么需要 KL 约束、为什么 DPO 不需要单独的奖励模型、GRPO 的基线从哪里来。

衡量方式：
- 课前、课后各做一次约 20 题的"概念测验"，题目专门针对常见误区，看学习增益；
- 再找少量学生边做边说出想法，观察他们实际卡在哪里。

### 0.2 学生画像与前置知识

- 默认对象：懂基本神经网络、梯度下降和矩阵运算的大学生或初级工程师。
- 前置课：
  - Mathnim 已有的"特征值 → PCA"课（The directions a matrix can't turn）：它讲的秩、低秩、主方向，正是 LoRA 的数学基础；
  - 新做一节约 15 分钟的"必要数学补课"：softmax 与温度、交叉熵与 log 概率、KL 散度、学习率与损失地形（第 1 课）。

### 0.3 总体结构

共 11 课，每课约 20–30 分钟，分四部分。另有 3 个可选的动手实验，在浏览器外跑真模型。

| 部分 | 课 | 一句话 |
|---|---|---|
| 序 | 0 从"续写机器"到"助手" | 微调到底改了什么、不改什么 |
| 补课 | 1 必要的数学 | softmax、交叉熵、KL、学习率 |
| 一、模仿：SFT | 2 损失还是那个损失，变的是数据 | 聊天模板、loss 掩码、EOS、打包（packing） |
| | 3 训练动态：过拟合与遗忘 | 学习率、轮数、"loss 低 ≠ 好"、为什么会遗忘 |
| 二、装得下：省显存 | 4 显存都去哪了 | 16 字节/参数、激活值、logits |
| | 5 LoRA：只学一个低秩的改动 | 秩、B=0 初始化、α/r、加在哪层、合并 |
| | 6 量化与 QLoRA | NF4、按块缩放、双重量化 |
| 三、偏好：从"像"到"更好" | 7 奖励模型与 Bradley–Terry | 为什么用两两比较 |
| | 8 RLHF：带 KL 缰绳的强化学习 | 目标函数、奖励被钻空子、PPO 的截断 |
| | 9 DPO：把强化学习变成分类 | 推导、β、似然位移 |
| 四、推理与收尾 | 10 可验证奖励与 GRPO | 组内基线、截断、长度偏差、"教会还是激发" |
| | 11 蒸馏、遗忘、合并与怎么选 | 正向与反向 KL、任务向量、决策图 |

### 0.4 三条讲法原则

1. **先让学生下注，再展示**：每个关键点先出一道预测题，再用交互画面揭晓，最后让学生用一句话解释。这一做法有实证支持（Kim et al., CHI 2017），也是 Mathnim 现有课程的结构。
2. **玩具模型讲直觉，真实数字讲规模**：交互画面里的模型是可控的小例子，界面上明确标注"示意"；涉及规模的数字（显存、学习率、效果差距）一律用论文或官方文档的真实数值，并注明出处。
3. **争议就讲成争议**：2025–26 年还在争论的问题（强化学习是教会还是激发推理、微调能不能加知识、RLVR 要不要 KL），放在"开放问题"框里，列出双方证据，不替学生下结论。

### 0.5 什么用交互、什么用文字

**适合做成 Mathnim 交互的：**
- 存在一个连续可调、效果反直觉的旋钮：秩 r、β、学习率、量化位数、截断 ε、温度。
- 有几何或线性代数结构：低秩、KL 的形状、权重空间里的向量加法、损失地形。
- 算法一步步展开的过程：一组采样 → 打分 → 优势 → 更新。
- 需要"先猜再看"的反直觉时刻。

**更适合文字（加图表、代码）的：**
- 方法全景和发展脉络、变体对照（IPO、KTO、ORPO、SimPO 各一行）。
- 超参数配方表、工具链（TRL、Unsloth、Axolotl、verl 等）、数据准备流程。
- 带出处的证据与争论、代码走读、安全注意事项。

**两者结合的：**
- 推导：先用动画一步步变形公式（manim 的公式变换），再配一段文字小结。DPO 的推导就是典型。

## 1. 逐课大纲

每课按同一结构写：
- **学完能做到**
- **要解开的误解**
- **讲法**：直觉 → 必要细节
- **呈现方式**：▶ 交互 / ▤ 文字
- **检验题**

### 第 0 课 从"续写机器"到"助手"（序）

**学完能做到**
- 说出预训练、SFT、偏好优化、强化学习各自用什么数据、优化什么。
- 判断"微调能不能教会模型新知识"。

**要解开的误解**
- "微调是往模型里灌新知识"。实际上它主要改的是行为和格式，硬灌新事实反而会增加幻觉（Gekhman 2024）。
- "基座模型就是一个笨一点的 ChatGPT"。

**讲法**
1. **开场对比**：让学生给基座模型下指令，比如"写一首关于秋天的诗"。基座模型会续写出更多问题，把它当成一份试卷来续写。"基座模型只会续写文档"（Karpathy）。
2. **教科书类比**（Karpathy）：
   - 正文 = 预训练；
   - 带解答的例题 = SFT；
   - 只给最终答案的练习题 = 强化学习。
3. **"对齐主要改风格"的证据**（URIAL）：在同一段对话里逐个位置比较基座模型和聊天模型最可能的下一个词。绝大多数位置两者相同，不同的集中在风格类的词（"当然"、"以下是"）和回答开头。
4. **必要细节：**
   - LIMA：只用约 1000 条精选样本微调，就能得到不错的助手。
   - 反例：Raghavendra 2024 发现数学、代码这类能力随数据量按幂律增长，"只改风格"的说法过于简化。这一点放进开放问题框。
   - Gekhman 2024：模型没学过的事实学得慢，而一旦学会，幻觉就近似线性增加。
   - 怎么选：先试提示词，知识类问题用 RAG，格式、风格、固定行为、降本和蒸馏用微调（Huyen 的"形式靠微调，事实靠 RAG"）。

**呈现方式**
- ▶ **"两个模型逐词对照"**：一段真实对话，每个位置显示基座模型和聊天模型的前 5 个候选词及概率（预先离线算好，不在浏览器里跑模型）。学生拖动位置游标，两者不同的位置会高亮。
- ▤ 训练流程总图，加一张"提示词 / RAG / 微调"决策表。

**检验题**
- **预测**：用 500 条公司内部 FAQ 微调，模型能不能可靠回答 FAQ 里没有的新产品问题？会有什么副作用？
- **选择**：三个场景各选一种做法：
  - 统一输出 JSON 格式；
  - 回答昨天刚发布的政策；
  - 把一个大模型的能力压到小模型上。

### 第 1 课 必要的数学（补课）

**学完能做到**
- 从 logits 手算 softmax 和交叉熵。
- 解释温度的作用。
- 说出 KL(P‖Q) 和 KL(Q‖P) 的区别。
- 解释学习率太大会怎样。

**讲法**
- **softmax**：把分数变成概率；温度 T 把分布拉平或拉尖。
- **交叉熵**：等于 −log p(正确的词)。直觉是"惊讶程度"。一句话的 loss 是每个词的惊讶程度取平均。
- **KL 散度**：两个分布有多不像。KL 不对称，这一点在第 8、11 课都要用到。
- **学习率**：在损失地形上迈的步长。步子太大会越过谷底，甚至跳出原来的谷。

**呈现方式**（全部交互，这一课是练手感的）
- ▶ **softmax 与温度**：拖动 4 个 logit 和温度 T，看概率柱随之变化；点选"正确的词"，实时显示交叉熵。
- ▶ **KL 散度**：拖动两个分布的柱高，显示 KL(P‖Q) 和 KL(Q‖P) 两个数，体会不对称。
- ▶ **二维损失地形上的梯度下降**：调学习率，看轨迹是收敛、来回振荡还是发散。

**检验题**
- 把温度调到 0.1，原本概率 0.4 的那个词会变成多少，往哪个方向变？
- 正确词的概率从 0.5 降到 0.25，交叉熵增加多少？

### 第 2 课 损失还是那个损失，变的是数据（SFT 机制）

**学完能做到**
- 写出带掩码的 SFT 损失。
- 说出聊天模板、特殊 token、EOS 各自的作用。
- 能找出"loss 降了但模型什么都没学会"的原因。

**要解开的误解**
- "SFT 是一种新的训练目标"。不是，它和预训练一样是预测下一个词，只是换了数据、加了掩码。
- 静默 bug：模板不一致、没做掩码、pad 和 EOS 设成同一个导致模型学不会停。这些都有论坛和官方文档里的真实案例。

**讲法**
1. **公式**：L = −Σ_t m_t · log p_θ(y_t | y_<t)，其中 m_t 是掩码，决定哪些词算 loss。
2. **聊天模板**：一段对话被渲染成带角色标记和特殊 token 的纯文本。训练和推理必须用同一个模板。结束标记必须和生成时的停止条件一致，否则模型不会停。
3. **为什么只在回答上算 loss**：否则模型也在学"预测用户会问什么"。
   - 必要细节：这不是铁律。Shi 2024、Huerta-Enochian 2024 发现，指令长、回答短、数据少时，给提示部分一个小权重（0.01–0.5）反而更好。
   - TRL 当前默认：prompt-completion 格式的数据只在回答上算 loss，纯文本格式在整段上算。
4. **打包（packing）**：把多条样本拼进一条序列以提高吞吐。如果不切断样本之间的注意力，样本会互相"串台"。正确做法是按样本边界做块对角注意力，吞吐约提升 1.4–2 倍，效果不变。
5. **必要细节**：
   - loss 要按整批里"有效 token 总数"做归一化。2024 年之前，梯度累积在这一点上有 bug。
   - 新增的特殊 token 需要训练对应的嵌入行和输出行。

**呈现方式**
- ▶ **"谁在算 loss"**：一段渲染好的对话，逐个 token 显示概率和 loss。点击任意 token 切换是否计入 loss，下方实时显示总 loss，以及梯度主要推动了哪些词的概率。学生会直接看到：不做掩码时，大部分梯度花在了"背用户的问题"上。
- ▶ **"它为什么停不下来"**：先演示一个 pad 等于 EOS 的训练批次，EOS 全被掩掉，生成时模型一直写下去；改对之后，模型在该停的地方停下。
- ▶ **打包与注意力掩码**：画出注意力矩阵，在"直接拼接"和"块对角"之间切换，并标出哪些格子是串台。
- ▤ 一个真实聊天模板的样例（Qwen 或 Llama 格式），以及 TRL 里对应的配置项和常见坑。

**检验题**
- **诊断**："训练 loss 稳定下降，但模型的回答和训练前一模一样。"给出三个最可能的原因，并说出各自怎么验证。
- **调试**：给一个批次的 token 和掩码，找出哪里错了。

### 第 3 课 训练动态：过拟合与遗忘

**学完能做到**
- 读懂训练集和验证集的 loss 曲线。
- 知道为什么"loss 低不等于效果好"。
- 能解释灾难性遗忘的几何直觉，并说出三种缓解办法。

**要解开的误解**
- "loss 越低越好"。反例：
  - InstructGPT 第 1 轮之后验证 loss 已经在过拟合，但多训几轮，人类偏好分数反而更高；
  - LIMA 发现困惑度和回答质量对不上。
- "只用干净的数据微调就不会坏"。反例：Qi 2024 发现用正常数据微调也会削弱安全性；窄领域的微调会带来广泛的行为偏移（emergent misalignment，Nature 2026）。

**讲法**
1. **典型配方**：
   - 全量微调学习率约 1e-6 到 2e-5，例如 Tülu 3 的 8B 模型用 5e-6；
   - 训练 1–3 轮；
   - 预热（warmup）加衰减。
2. **过拟合的信号**：验证 loss 回升、输出多样性塌缩、照搬训练集里的措辞、通用评测退步、不会停。选检查点要看任务评测，而不只看 loss。
3. **遗忘的几何直觉**：把模型参数想象成地形上的一个点。旧任务和新任务各有一个山谷，微调就是把这个点往新山谷里推。推得越远（学习率越大、步数越多），离旧山谷就越远。
   - 缓解办法：降低学习率、用 LoRA（遗忘更少但不是零）、混入旧数据（例如文档与对话 7:3 混合）、加 KL 约束。
   - RL's Razor 的发现：遗忘程度可以用新任务上相对基座模型的 KL 来预测。

**呈现方式**
- ▶ **"两个山谷"**：在二维地形上叠加旧任务和新任务两组等高线。学生调学习率、步数，以及是否混入旧数据，看参数的移动轨迹，旁边两条小曲线同步显示新任务 loss 和旧任务 loss。示意模型，界面上会标注"示意"。
- ▶ **"曲线医生"**：给出 4 组真实形状的训练曲线，让学生判断是正常、过拟合、学习率过大，还是 loss 掩码有问题。
- ▤ 超参数配方表，注明出处。

**检验题**
- **预测**：学习率提高 10 倍后，新任务和旧任务的 loss 各会怎样变化？
- **诊断**：给一组"训练 loss 下降、验证 loss 先降后升、但人工评分还在升"的数据，问该在哪里停，理由是什么。

### 第 4 课 显存都去哪了

**学完能做到**
- 不查资料也能估算出某个配置大概要多少显存，误差在 30% 以内。
- 说出全量微调、LoRA、QLoRA 分别省掉了哪一块显存。

**要解开的误解**
- "模型 16 GB，所以 16 GB 显存就能微调"。

**讲法**
1. **混合精度 Adam，每个参数 16 字节**：
   - bf16 权重 2 字节；
   - bf16 梯度 2 字节；
   - fp32 主权重副本 4 字节；
   - Adam 的两个状态 m、v 各 4 字节。
2. **激活值**：随序列长度和批大小增长。梯度检查点只保留每层的输入，代价是多算约 33% 的计算量。
3. **容易被忽略的 logits**：序列长度 × 词表大小 × 4 字节。8B 模型在 4k 上下文下约 2 GB，它的梯度还要再占同样多。
4. **算例**（Llama-3.1-8B，序列长度 4096，批大小 1）：
   - 全量微调约 135–150 GB，需要两张以上 80 GB 的卡；
   - LoRA（秩 16，加在所有线性层）约 20–23 GB；
   - QLoRA 约 8–10 GB。

**呈现方式**
- ▶ **显存计算器**：用堆叠柱表示各项占用（权重、梯度、优化器状态、激活值、logits），旁边画一张 24 GB 和一张 80 GB 显卡的容量线。可调参数：
  - 参数量；
  - 精度；
  - 方法：全量、LoRA、QLoRA；
  - 秩；
  - 序列长度和批大小；
  - 是否开梯度检查点。

  先让学生估算并下注，再揭晓。这个计算器也是 AI 回答"我的显卡够不够"这类问题时现成可用的画面零件。
- ▤ 计算公式和出处（ZeRO 论文的 16 字节/参数，Korthikanti 的激活值估算）。

**检验题**
- **计算**：13B 模型，QLoRA，序列长度 2k，大约要多少显存？最大的一项是什么？
- **预测**：做 QLoRA 时把批大小从 1 调到 16，省显存的效果为什么会变弱？（因为激活值开始占大头。）

### 第 5 课 LoRA：只学一个低秩的改动

**学完能做到**
- 写出 h = W₀x + (α/r)·BAx，说清每一项的作用。
- 算出可训练参数量 r(d+k)。
- 解释为什么低秩就够、什么时候不够。
- 说出 LoRA 省的是什么，不省什么。

**要解开的误解**
- "LoRA 是一个更小、更快的模型"。实际上合并之后，模型的大小和速度都和原模型一样；它省的是训练时的梯度和优化器状态。
- 秩和 α 的各种"民间配方"（α = 2r、α = r 等）。2025 年的结果显示，学习率比秩重要得多，在 1/r 缩放下，不同秩的早期学习曲线几乎一样（LoRA Without Regret）。
- "秩越大越好"或"秩越小越好"。真实情况是：数据量没超过适配器的容量时，LoRA 能追平全量微调；超过了就落后（Biderman：LoRA 学得少、忘得也少）。

**讲法**（衔接"特征值 → PCA"课）
1. **从上一门课出发**：矩阵就是对空间的一个运动。微调就是在 W₀ 上加一个改动 ΔW。
2. **秩 1 的改动**：u·vᵀ 只沿一个方向推，把整个平面压向一条线。秩 r 的改动就是 r 个这样的方向叠加。
3. **为什么低秩就够**：
   - 微调的"内在维度"很低：只训练随机投影后的 200 个参数，就能达到全量微调 90% 的效果（Aghajanyan）；
   - 反例同样重要：全量微调实际学到的改动，秩比常见的 LoRA 配置高 10–100 倍。
4. **必要细节**：
   - B 初始化为 0，所以训练从原模型出发；
   - α/r 缩放；rsLoRA 改用 α/√r，让大秩也能继续学；
   - 要加在所有线性层上，其中 MLP 层最重要，只加在注意力层效果明显更差；
   - 学习率约为全量微调的 10 倍；
   - 合并后零额外延迟；
   - DoRA 把权重的大小和方向分开学（一句话带过）。
5. **容量与信息量**（Thinking Machines，2025）：SFT 的每个 token 都带来信息，而强化学习每一轮大约只得到 1 比特，所以强化学习里秩为 1 往往就够。这一点会在第 10 课再次用到。

**呈现方式**
- ▶ **"秩 1 是什么样"**：复用 `linear_map` 零件，把 W₀ 和 W₀ + u·vᵀ 放在一起。学生拖动 u 和 v，看改动只发生在一个方向上。
- ▶ **"拿秩去逼近一个真实的改动"**：用一个 64×64 的 ΔW 矩阵热力图（来自一次真实小模型微调的某一层，或者标注为示意）。学生拖动秩 r：
  - 看重建结果和误差；
  - 看奇异值谱；
  - 看参数量 r(d+k) 和 dk 的对比。
- ▶ **"容量水桶"**：在数据信息量和适配器容量之间做一个可调的对比，用来展示 SFT 数据量大时秩不够、强化学习时秩 1 就够。示意图，标注出处。
- ▤ PEFT 配置示例、超参数建议（附出处）、合并与多适配器的说明。

**检验题**
- **计算**：d = k = 4096，秩 16，可训练参数占这一层的百分之多少？
- **预测**：只把秩从 8 调到 64，其他都不变，前 100 步的 loss 曲线会怎样？（几乎不变。）
- **诊断**：用 LoRA 做 10 万条样本的代码 SFT，效果明显不如全量微调。可能的原因有哪些？

### 第 6 课 量化与 QLoRA

**学完能做到**
- 解释 NF4 为什么把量化格点放在正态分布的分位点上。
- 解释按块缩放为什么能对付异常值。
- 估算双重量化省下多少。

**讲法**
1. **量化**：用很少几个格点表示连续的权重，误差取决于格点放在哪里。
2. **NF4**：神经网络的权重近似服从正态分布，把 16 个格点放在正态分布的分位点上，每个格点分到的权重数量相同。
3. **按块缩放**：每 64 个权重共用一个缩放系数，所以一个异常值只会影响它所在的那一小块。
4. **双重量化**：把这些缩放系数本身再量化一次，额外开销从每参数 0.5 比特降到约 0.127 比特，在 65B 模型上大约省 3 GB。
5. **分页优化器**：用统一内存吸收显存的瞬时峰值（一句话带过）。
6. **细节提醒**：QLoRA 的适配器是在反量化后的权重上训练的。合并回 bf16 原模型会有一点误差，合并后要重新评测。

**呈现方式**
- ▶ **"格点放在哪"**：一张权重直方图，学生选 4 位或 8 位、均匀格点或 NF4，看格点位置、每格分到的权重数量和量化误差。还可以往直方图里拖入一个异常值，看按块和不按块的误差差别。
- ▤ bitsandbytes / PEFT 的配置示例。

**检验题**
- 为什么同样是 4 位，NF4 比均匀分布的格点误差更小？
- 一个异常值会让哪些权重的误差变大？

### 第 7 课 奖励模型与 Bradley–Terry

**学完能做到**
- 写出 Bradley–Terry 公式 P(A 优于 B) = σ(r_A − r_B) 和对应的损失。
- 解释为什么用两两比较，而不是让人直接打分。

**讲法**
1. **为什么用两两比较**：绝对打分噪声大、各人的尺度不一致，两两比较更稳定。
2. **Bradley–Terry**：只有奖励的差值才有意义，所以奖励整体加一个常数，结果完全不变。
3. **先检查奖励模型**：上线前先看它在留出的比较数据上的准确率（CS224N："先确认你的奖励模型是对的"）。

**呈现方式**
- ▶ **"差值决定一切"**：拖动两个回答的奖励值，看 σ 曲线上的胜率；把两个奖励一起平移，胜率不变。
- ▶ **"从比较数据里拟合奖励"**：给出 6 个回答之间的若干比较结果，学生手动调整每个回答的奖励，让对数似然最大；之后点按钮，看梯度下降自动做同一件事。

**检验题**
- 两个回答的奖励差是 2，A 胜过 B 的概率是多少？
- 把所有奖励都加 10，模型的哪些行为会改变？（不会改变。）

### 第 8 课 RLHF：带 KL 缰绳的强化学习

**学完能做到**
- 写出目标函数 max E[r] − β·KL(π‖π_ref)，并解释 KL 这一项为什么必须有。
- 能认出奖励被钻空子（reward hacking）。
- 说出 PPO 的截断在做什么。

**要解开的误解**
- "奖励越高越好"。奖励模型只在它训练数据附近可信。随着策略越来越偏离参考模型，代理奖励一直在涨，而真实质量先升后降（Gao 2022）。
- KL 读数为负是怎么回事：通常是采样时用了 top-k 或 top-p 截断造成的。

**讲法**
1. **直觉**："强化做得好的回答"，但是要拴一根缰绳：概率偏离参考模型越远，代价越大。
2. **闭式解**：最优策略 π* ∝ π_ref · exp(r/β)。β 越小，缰绳越松；β 趋近 0 时，策略会全部押到奖励最高的那个回答上，哪怕那个高分是奖励模型的漏洞。
3. **PPO 的必要细节**：
   - 截断代理目标 min(ρA, clip(ρ, 1±ε)A)，ε = 0.2，作用是每一步不要走太远；
   - 训练时要同时放 4 个模型：策略、参考模型、奖励模型、价值模型；
   - InstructGPT 还混入了预训练数据（PPO-ptx）。

**呈现方式**
- ▶ **"缰绳"**：8 个候选回答，柱高是参考模型给出的概率。上方叠一条奖励曲线，其中有一个"漏洞"回答，奖励虚高、但质量很差。学生拖动 β，策略按闭式解 π_ref·exp(r/β)/Z 实时重算，旁边显示 KL 和真实质量。学生会亲眼看到：β 太小时，所有概率都塌到漏洞回答上。这是精确计算，不是示意。
- ▶ **"代理奖励与真实奖励"**：横轴是 KL，两条曲线，形状来自 Gao 2022 的拟合形式。学生拖动停止点，问"在哪里停最好"。
- ▶ **"PPO 截断"**：画出截断目标关于概率比 ρ 的图像，学生调 ε，并切换优势的正负号。
- ▤ InstructGPT 的完整流程、4 个模型的显存和工程负担、过度优化在实际中的表现（重复、切换语言、胡话）。

**检验题**
- **预测**：β 从 0.1 降到 0.001，生成结果会出现什么现象？
- **诊断**：奖励一路上涨，人工评估却在下降，原因是什么？有哪些对策？

### 第 9 课 DPO：把强化学习变成分类

**学完能做到**
- 能自己推导出 DPO 的损失函数。
- 解释 β 的作用和参考模型的作用。
- 解释 loss 下降时，被选回答的概率为什么也可能下降。

**要解开的误解**
- "DPO 不需要奖励模型，所以也没有 KL、也不需要参考模型"。实际上 DPO 优化的是同一个带 KL 约束的目标，β 就是 KL 的强度，参考模型定义了隐式奖励。
- "DPO 会提高被选回答的概率"。不一定：损失只看两者的差距，两个概率可以一起下降（Smaug、似然位移）。

**讲法**（承接第 8 课的闭式解）
1. 由第 8 课，π* = π_ref·exp(r/β)/Z。
2. 反解出奖励：r = β·log(π*/π_ref) + β·log Z。
3. 代入 Bradley–Terry 公式，Z 正好消掉，这就是关键一步。
4. 得到损失：L = −log σ(β·[log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)])。
5. 梯度：只有在模型"排错序"的样本对上权重才大。

**必要细节**
- 典型取值：Llama 3 用 β = 0.1、学习率 1e-5；Tülu 3 用长度归一化的 DPO。
- 似然位移：被选回答和被拒回答很相似时最严重，可以按相似度过滤样本对来缓解。
- 2025 年的"差值学习"（Olmo 3）：被选回答来自大模型、被拒回答来自小模型，用 DPO 有效，而直接用 SFT 学被选回答反而有害。

**呈现方式**
- ▶ **推导动画**：用 manim 的公式变换一步步变形，Z 消掉的那一步高亮。动画结束后，学生可以点击每一步，查看"这一步为什么成立"。
- ▶ **"只看差距"**：两组柱状图，分别是被选回答和被拒回答在策略模型与参考模型下的 log 概率。学生拖动策略模型的两个 log 概率，实时显示 DPO 损失和每个回答受到的梯度方向。然后让学生做一件事：找一种拖法，让 loss 下降，同时被选回答的概率也下降。这是本课最关键的"原来如此"时刻。
- ▤ 变体对照表：IPO、KTO、ORPO、SimPO、差值学习，每个一行，写清和 DPO 的区别与适用场景。

**检验题**
- **推导**：为什么 Z 能消掉？如果去掉参考模型（ORPO、SimPO 的做法），会失去什么？
- **诊断**："DPO 的 loss 在降，chosen 的 log 概率也在降，拒绝回答的比例下降了"，怎么解释？怎么处理？

### 第 10 课 可验证奖励与 GRPO

**学完能做到**
- 讲清 GRPO 的一步：一组采样 → 打分 → 组内归一化得到优势 → 带截断的更新。
- 解释为什么全对或全错的组不提供学习信号。
- 解释长度偏差从哪里来。
- 能分别陈述"强化学习教会了推理"和"只是激发了已有能力"两方的证据。

**讲法**
1. **可验证奖励**：答案可以用规则判对错（数学、代码），不需要神经网络做的奖励模型，也就更难被钻空子。
   - R1-Zero：只用正确性和格式两项规则奖励，AIME 的 pass@1 从 15.6% 升到 71%。
2. **组内基线**：同一个题目采样 G 个回答，优势 = (r − 组内均值)/组内标准差，因此不需要价值模型。
3. **零方差的组**：一组全对或全错时，所有优势都是 0，这一组白算了。动态采样就是把这类组过滤掉。
4. **偏差与修正**（2025）：
   - 按回答长度平均会让"又长又错"的回答受到的惩罚被稀释，Dr. GRPO 去掉了这一项，并去掉标准差归一化；
   - DAPO 用非对称截断（下界 0.2、上界 0.28）；
   - GSPO 改成序列级的比率；
   - 截至 2026 年，各家的做法收敛到一组共识：组内基线、非对称截断、过滤零方差的组、KL 很小或不用、异步采样。
5. **开放问题**：
   - 支持"只是激发"的证据：Yue 2025 发现，k 足够大时，基座模型的 pass@k 反而更高；
   - 支持"能教会新东西"的证据：ProRL 发现长时间训练能扩大 pass@k；2026 年的受控实验发现，题目恰好处在模型能力边缘时，强化学习能带来真实的提升；
   - 提醒学生：回答变长不等于推理变强，"aha"这类说法在基座模型里就已经出现过。

**呈现方式**
- ▶ **"一组采样"**：一个题目、8 张回答卡片，每张显示对错和长度。学生可以翻转任意一张的对错，看每张卡片的优势实时变化；把一组都设成全对，看信号消失。另有开关在"按 token 平均"和"按回答平均"之间切换，看长回答受到的惩罚怎么变。
- ▶ **"截断"**：在第 8 课截断图的基础上加入非对称上下界。
- ▶ **"pass@k"**：两条曲线（强化学习后的模型和基座模型），学生拖动 k，看两者在什么位置交叉。曲线形状来自 Yue 2025，标注出处。
- ▤ DeepSeek-R1 的完整流程、方法变体对照表、"强化学习只需秩 1 的 LoRA"的回扣、工具（verl、TRL GRPO、OpenRLHF）。

**检验题**
- **计算**：8 个回答里 2 个对，算出对的和错的回答各自的优势。
- **诊断**：GRPO 训练时回答越来越长，准确率却不再上升，可能的原因有哪些？

### 第 11 课 蒸馏、遗忘、合并与怎么选（收尾）

**学完能做到**
- 区分序列级蒸馏、logit 级蒸馏和在线蒸馏。
- 解释正向 KL 和反向 KL 的不同行为。
- 用任务向量解释模型合并。
- 对一个新场景给出完整的方案选择。

**讲法**
1. **蒸馏**：
   - 序列级：直接用老师的输出做 SFT，例如 R1-Distill、s1（1000 条推理轨迹）；
   - logit 级：用 KL 让学生的分布逼近老师（温度 T 起软化作用），前提是两者用同一个分词器；
   - 在线蒸馏：在学生自己生成的样本上，逐 token 用反向 KL 学老师。2025 年的结果显示，它以约十分之一的算力达到了比强化学习更好的 AIME 成绩。
2. **正向 KL 与反向 KL**：正向 KL 倾向于"覆盖"所有峰，反向 KL 倾向于"挑一个峰"。
3. **遗忘回顾**：RL's Razor 发现，强化学习更倾向于找到离原模型 KL 最小的解，所以遗忘更少；"SFT 偏记忆，强化学习偏泛化"（Chu 2025）。
4. **模型合并**：
   - 任务向量 τ = θ_微调 − θ_基座，合并就是把几个任务向量加起来；
   - TIES 先去掉小的改动，再对正负号投票；DARE 随机丢弃一部分改动再放大；
   - 前提是这些模型来自同一个基座。
5. **怎么选（决策图）**：提示词 → RAG → SFT → 偏好优化 → 强化学习，每一步写清楚什么时候该往下走，以及对数据的要求。

**呈现方式**
- ▶ **"拟合一个双峰分布"**：目标分布有两个峰，学生用一个高斯去拟合，在正向 KL 和反向 KL 之间切换，并手动拖动高斯的位置和宽度，看两种 KL 的数值。这是演示 KL 不对称最经典的画面。
- ▶ **"任务向量相加"**：二维权重空间里画两个任务向量。学生调它们的系数 λ，看两者相加后的位置；再做一个分量正负号冲突的例子，演示 TIES 的投票。
- ▤ 决策图与对照表、蒸馏和合并的工具（MergeKit），以及"能做什么、不能做什么"的总结页。

**检验题（综合）**
三个真实场景，每个都要写出方案、数据怎么准备、主要风险：
- 客服风格统一；
- 数学推理提升；
- 把模型部署到手机。

工作量：每课大约是"特征值 → PCA"课的 0.6–1 倍（零件、课程、旁白、浏览器验证），11 课合计约等于 8 门那样的课。

## 5. 检验体系（怎么判断"讲懂了"）

- **课内**：每个关键点都是"预测题 → 交互揭晓 → 一句话自我解释"。学生的解释由 AI 导师判读，并据此更新掌握度。
- **每课结尾**：2–3 道迁移题，覆盖计算、诊断和选择，题目是新情境，不复用课上的例子。
- **课前与课后测验**：约 20 题，专门针对误区，例如：
  - 微调加知识；
  - loss 越低越好；
  - LoRA 是小模型；
  - DPO 一定提高 chosen 概率；
  - 奖励越高越好；
  - 回答越长推理越强。

  统计学习增益，并逐题看哪些误区没解开，回头改对应的课。
- **综合项目**（可选）：完成一个动手实验，提交"预测 → 结果 → 解释"报告，由 AI 导师按评分标准给出反馈。

## 6. 需要你确认的几点

1. **学生对象**：默认是懂神经网络基础的大学生或初级工程师。要不要再往下覆盖完全没有机器学习基础的人？如果要，需要多加 2–3 节基础课。
2. **讲课语言**：课程界面和旁白用中文还是英文？现有的课都是英文。
3. **动手实验**：要不要做？要做的话，是以 Colab 链接为主，还是你有固定的 GPU 环境？
4. **先做哪几课**：我建议先做第 5、8、9 三课作为样板，你看是否同意。
