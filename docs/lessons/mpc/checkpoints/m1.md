## Lesson design (not written yet): `m1_lookahead.ts`, id `mpc-m1-lookahead`, mode essay, use `t`, `vis`, `attach` from ./common
Model of tone: apps/mathnim/src/lessons/ft/c/c2_lora.ts. Narration only on scene steps.
Skills: mpc-loop, first-step, horizon-length, mpc-vs-pid.
Misconceptions: pid-tune-fixes, replan-fixes-short-horizon, horizon-fixed-number, longer-is-free, plan-once,
apply-first-saves-compute, plan-sees-everything, mpc-always-better.
Steps:
1. read `react` (chapter The problem): docking task (start at rest at 0, wall at 10 m, |a| up to 1, |v| up to 2, Δt 0.1).
   PID looks at the error now / its past / its trend, never at the brakes or the wall. Visual block `mpc_pd_compare` {}:
   aggressive hits, cautious crawls, tuned docks 8.6 s. Then `mpc_pd_compare {brakes:'0.5', show_mpc:true}`: same tuned PD
   hits at 1.33 m/s; MPC told the brakes (4 s look-ahead) docks 9.0 s.
2. read `idea`: MPC in one sentence (predict with a model, choose N inputs within limits, apply the first, measure, repeat);
   three ingredients model / cost / constraints; small PID vs MPC table.
3. scene `loop`: `mpc_receding_loop` {N:20}, narration (plan dashed + strip, apply first, slide, re-plan; braking enters
   from the far end of the window). Card thumb = 'loop'.
4. read `problem`: the optimisation once: min Σ (p_k−10)² + 0.1 a_k² s.t. x_{k+1}=Ax_k+Bu_k (A=[[1,0.1],[0,1]],
   B=[[0.005],[0.1]]), |a_k| ≤ 1, |v_k| ≤ 2, p_k ≤ 10, x_0 = measured; what each term does; M2/M3/M4 pointers.
5. checkpoint `first-predict` (predict, choice): why not execute the whole t=0 plan? correct = the world departs from the
   model, re-planning from the measurement is feedback; wrong: saves compute (apply-first-saves-compute), later steps
   infeasible, plan-once.
6. scene `push`: `mpc_replan_push`, narration (blind plan hits 1.92 m/s; re-planned docks 7.0 s; push not in model).
7. checkpoint `horizon-predict` (predict, number, seconds): brakes 1, top speed 2: how far ahead must it look? answer 2,
   tolerance 0.15; wrong 0.1 → replan-fixes-short-horizon; wrong 1 → feedback.
8. explore `horizon-world`: `vis('mpc_dock_horizon')`, setup `attach('mpc_dock_horizon')` (visual emits 'released' with
   {N,a,crashed,impact,docked_t}; scene.result(); trackers scene.N, scene.a). cue = [DOCK_LABELS.N, DOCK_LABELS.brakes].
   Goals: (1) a=1 and N=19 (shortest that docks); (2) a=0.5 and N=40. Not met at entry (N=10, brakes 1).
   Detectors: crash with N ≤ 15 → replan-fixes-short-horizon ("it re-planned 50 times and still hit: inside each window
   nothing said brake yet"); a=0.5 with N=19..39 crash → horizon-fixed-number; a=1, N ≥ 30 docks → longer-is-free.
   Lines: enter/idle/goal/each finding, fixed text. solve: N=19, emit released; a=0.5, N=40, emit released.
9. read `takeaway`: look-ahead ≥ time to stop (v_max/a_max); halve brakes → double; short plans are not wrong by their
   own lights, the crash is past the window end (M6: terminal cost); long N costs solve time (M5) and model error.
10. read `preview` (chapter The course): M2..M8 map; where MPC runs (Qin & Badgwell 2003: refining, PID base layer every
    second / MPC every minute; Cheetah 3 QP < 1 ms at 20–30 Hz; GM engines 2018) – sources already verified in
    docs/lessons/mpc/research-c.md §8a–8d, §9; when PID is enough.
11–14 checks (chapter Check): number: v_max 3, brakes 1.5, Δt 0.05 → 40 steps (wrong 20: used Δt 0.1; wrong 3: metres);
    text: solve takes 30 ms at 100 Hz, engineer applies 3 inputs per plan – what is lost (feedback delayed, open loop
    3 steps); choice: which case needs MPC over PID (stop at a line with limited brakes; mpc-always-better distractor);
    choice: 1 s plan at t=5 says "no braking" and ends at wall at 2 m/s – does it violate its constraints? No
    (plan-sees-everything).
