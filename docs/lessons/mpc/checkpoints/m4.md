## Lesson design (step list)
1. read `limits` (chapter Why limits): motor |a| ≤ 1, speed |v| ≤ 2, wall p ≤ 10. M3's law at (7, 0)
   asks for a₁ = 2.44 (two-move) or u0 = 6.75 m/s² (full N = 20). Clipping is what a saturating motor does.
   Tease: is that the same as planning with the limits?
2. derive `qp`: input rows [I; −I]U ≤ …; state rows C Γ U ≤ v_max − C Φ x0 → G U ≤ w + E x0 (G is fixed,
   w holds the limit values, E x0 moves them with the state); with M3's cost this is a QP; convex because H ≻ 0 →
   one optimum (Boyd & Vandenberghe). Add a blank on a state row.
3. read `two-moves`: move blocking to two decisions; rows v(1s)=v0+a1, v(2s)=v0+a1+a2, p(1s)=p0+v0+a1/2,
   p(2s)=p0+2v0+1.5a1+0.5a2; each limit is a line, the feasible set a polygon, the cost an ellipse bowl centred at the no-limits plan.
4. scene `qp-scene`: vis('mpc_qp_plane') full story, with narration.
5. derive `kkt`: Hz + f + Σλᵢgᵢ = 0, λ ≥ 0, λᵢ(slack) = 0; the gradient is perpendicular to the active edge;
   λ = how much J* drops per unit of relaxing that limit (example: λ = 9.06 at (8, 0)). The kit's solve_qp returns x, lambda and active.
6. checkpoint predict `clip-predict`: at rest at 7 m, the clipped plan brakes in the second second (a₂ = −0.75).
   What does the best plan do? Options: brakes too / pushes (correct, a₂ = +1) / coasts (a₂ = 0) / same as clip
   (misconception clip-is-solve).
7. explore `qp-world`: setup `attach('mpc_qp_plane', { story: 'setup', p0: 9, v0: 0.2 })`; the scene emits
   'released' with { p0, v0, feasible, active, wall, speed, flip, a1, a2 } (scene.report(); scene.set_state(p, v)).
   - goal `clip`: v0 ≤ 0.1, p0 ≤ 7.5 and qp_view(...).flip.
   - goal `wall-far`: the wall row is active with p0 ≤ 7.5 (the wall acts on predictions).
   - detector `wall-is-local`: released with p0 ≥ 9.2, the wall inactive and feasible → misconception line
     ("right by the wall but slow: not active; what matters is the predicted position").
   - detector (kind 'progress') `no-plan`: released while infeasible → line that the polygon is empty, pointing to M6.
   - lines: enter, idle, goal, one per finding. cue: [the handle label "the cart's state (p₀, v₀)" / '小车的状态 (p₀, v₀)'].
   - solve: set_state(7, 0) + emit released; set_state(7.1, 1.9) + emit released. Neither goal holds at entry.
8. read `clip`: why clipping is not solving. The no-limits a₂ was designed for an a₁ the motor can't deliver,
   so once a₁ is cut, a₂ must be re-planned. Clipping also can't handle state limits: the clipped plan at (7.1, 1.9)
   breaks the wall and at (6, 1.5) the speed limit (a lower J but an illegal plan). Clipping is exact only for one decision variable.
9. code `qp-code`: docs/lessons/mpc/m4/m4_qp.py (the full N = 20 QP), with notes.
10. checkpoint predict `law-predict`: a₁ against p₀ at v₀ = 0.6. Options: one line / straight pieces joined with kinks
    (correct) / jumps / smooth curve (misconception mpc-is-linear).
11. scene `explicit-scene`: vis('mpc_explicit_map') full story, with narration.
12. read `explicit`: with a fixed active set, KKT is linear with an rhs affine in x0, so z(x0) is affine; the region
    boundaries are linear → polyhedral; the law is continuous piecewise affine (Bemporad et al. 2002). Explicit MPC
    precomputes the regions and online does a lookup plus a multiply, with no solver. Only for small problems: the number of regions can grow
    exponentially with the constraints and the horizon (Alessio & Bemporad 2009 survey; MPT3).
13. checks: (a) number: λ = 9.06 for the a₁ limit; raise it to 1.01 → J* drops by ≈ 0.09 (wrong: 9.06 → forgot ×0.01);
    (b) choice: λ_wall = 0.8, λ_speed = 0 → relaxing which helps (wall; misconception lambda-zero-matters);
    (c) choice: when is clipping guaranteed exact? (a single decision variable with bounds; wrong: "any horizon with only input limits" = clip-is-solve);
    (d) text: why the constrained MPC law is not a single K, yet is cheap to evaluate (key points: regions with fixed active sets → affine; piecewise; lookup).
Misconception ids: clip-is-solve, wall-is-local, lambda-zero-matters, mpc-is-linear, explicit-always.
unit.ts entry: `{ id: m4.id, lesson: m4, minutes: 30, thumb: 'qp-scene', title, summary }` in `constraints`.
