## Key numbers (my simulations: cart from dock.ts, Q=diag(1,0), R=0.1, |a|≤1, |v|≤2, p≤10, target p=10, fallback = brake)
- dlqr: K=[2.789, 2.362], P=[[8.468,3.162],[3.162,2.520]]. The closed-loop eigenvalues are 0.875±0.111i, which are complex. So LQR overshoots, and because the target sits on the wall, the LQR terminal set degenerates to {target}. Add a unit test for this claim.
- **none:** N=5 is first infeasible at k=56 and crashes at k=61 at 1.55 m/s. N=8 crashes at 1.18 m/s, N=15 at 0.54 m/s. N≥19 docks (k=73).
- **cost P only** (terminal cost = dlqr P): it **still crashes** for N=2..15 (N=5 at 1.01 m/s). P assumes unlimited brakes and does not change the feasible set.
- **terminal set 𝒳_f** = {p + c·v ≤ 10}, with c = v_max/a_max − Δt/2 = 1.95 s, plus the existing p≤10 and |v|≤2. It is control invariant under "brake until rest", and I proved it by hand (still to be checked on a grid in a unit test). It is never infeasible and never crashes for any N≥2. Docking times: N=2: 16.7 s, N=3: 15.7 s, N=5: 12.0 s, N=8: 8.3 s. With P added: N=5: 10.3 s.
- **end at target** (x_N = (10,0), the Keerthi–Gilbert pair): infeasible at t=0 for N≤69. It is feasible from N=70 (2 s accelerating + 3 s cruising + 2 s braking = 7 s), and then docks at k=71. One run takes about 250 ms.
- The optimal cost J* decreased monotonically in all the feasible runs, so a J* panel would not tell the modes apart. Don't build one.
- **Exact feasible sets** (used for drawing; check them against make_mpc status in tests):
  - Clamped full braking minimises every p_k and p_N + c·v_N at the same time.
  - X_N(none or cost) = {p + max_{1≤k≤N}(kΔt·v − a(kΔt)²/2) ≤ 10}.
  - C∞ is the same expression with k unbounded; the stop from 2 m/s takes exactly 2.0 m.
  - X_N(set) adds the condition p_N + c·v_N ≤ 10 under clamped braking.
  - The trap = X_N \ C∞. For N=5 at v=2 it is p ∈ (8, 9.125).
- **Soft speed limit** (N=20, push +0.4 m/s at k=30, by make_mpc soft, which also softens the wall):
  - hard: infeasible for 3 steps;
  - l1 = 100 or 1000: the same motion as hard, with slack 0.3, 0.2, 0.1;
  - l1 = 10: runs at 2.78 m/s even without a push;
  - l1 ≤ 3: crashes into the softened wall.
  - For the figure, write my own QP (soft speed rows, hard wall) with `solve_qp`.

## Design
Visuals (one file each in `packages/visuals/src/mpc/`), with math in `terminal_math.ts` and tests in `terminal_math.test.ts`:
1. `mpc_terminal_world` (scene and world). The phase plane is p on [0, 10.5] and v on [−0.2, 2.45]. A Track strip sits above it, aligned to the p axis.
   - Regions: the wall, the v>2 band, the crash-certain area (outside C∞, light coral) and the trap (X_N\C∞, dark coral, live with N and the mode). The 𝒳_f line is drawn in green dashes; the target is a ring.
   - Marks: the trajectory dots, coral where the QP was infeasible; a crash or dock dot; the end of each plan x_N as a hollow circle; the dashed plan at the last moment the cart could still stop.
   - The right column has the outcome, "QP infeasible from t=…", "entered the trap at t=…" and a legend.
   - Controls: a StepSlider for N (2–80) and a 4-pill Choice: none / cost P / terminal set / end at target.
   - The story animation runs a tracker kt: accelerate, enter the trap (pause, show the trap), infeasible, crash. After that kt is set to 1e4 so the whole run is shown, plus the decisive plan.
   - `result()` returns { N, mode, crashed, impact, infeasible_k, docked_t, trap_k, started }; the visual emits 'released'.
2. `mpc_soft_limit` (static): v(t) with the soft limit 2 and a push at 3 s. Curves for l1 = 1000 (exact) and l1 = 10 (a "suggestion"); ticks where the hard QP is infeasible. The wall stays hard.
3. `mpc_shift_tail` (static): the shift argument in the phase plane. The plan at k ends in 𝒳_f; the candidate at k+1 is the plan's tail plus one braking step, which stays in 𝒳_f.
