# 引擎重构：改了什么、新架构、用现有课的验证、性能评估

2026-11-03。设计见 `docs/design/ENGINE.md`（第 15 节记了实现和设计不同的地方），写图的参考见 `packages/engine/README.md`。
本文的数字都是在这台机器上量的：4 核云容器、无头 Chromium（软件 GPU，SwiftShader）。绝对值比真机慢，前后对比在同样条件下做。

## 0. 结论

- **新内核 `@mathnim/engine` + 外观表 `@mathnim/look` 已经接进站点**，和 Manim 并行：一步的图可以是旧的 Scene，也可以是新的 Figure，
  运行时按种类选播放器。四张图已移植（MPC 第 4 课两步计划那一屏和它的探索、M6 的 shift_tail、线性代数的行列式、微调的训练曲线），
  另外用新内核修好了一个原本就坏的草图题。
- **现有课全部过了**（第 3 节）：
  - 类型检查通过，682 个单测通过；
  - doctor 229/229（含 7 个新内核的图）；
  - 94 节课 × 1490 步在桌面上前后逐步对比截图：没有移植的 1482 步和重构前完全一样，移植的 8 步按计划改变，0 个新报错、0 张空白图。
- **性能**（第 4 节，桌面，生产包）：移植的四张图打开快 3–16 倍，跳到任意时刻快几十到几百倍，静止时不再每秒画 35–60 帧（现在 0），拖动一帧在降速 4 倍时快 2–8 倍（不降速时行列式探索持平：6.7 → 7.3 ms），JS 堆从 134 MB 降到 25 MB；CPU 降速 4 倍时，除了 M4 探索（19.6 ms / 18.9 ms）以外每帧都在 16 ms 以内。没移植的对照组前后不变。内核压缩后 23 KB。
- **和原来的效果**：桌面上移植的图和旧版逐帧对齐过——在旁白的同一时刻截图对比，时长、出场顺序、动画和内容都和原来一样；不一样的是刻意改的版式和颜色（图例移到图外、颜色按名词、系统字体），见第 3 节和 `engine-shots/compare-*.png`。
- **排版**：第 2 节诊断的 P1–D6 在移植的图里都没有了（图例不压图；颜色按名词；没有手放的坐标；开发中看过手机：字 15 px 起、不再缩成 5–7 px，这一轮没有做手机的完整对比）。
- **没达到的**：图的代码行数和原来差不多（目标是三分之一）；没做 DOM 镜像、玻璃/液态代数/套索的移植、Manim 方言接内核（第 6 节）。

## 1. 改了什么

### 1.1 新包 `@mathnim/look`（外观表，274 行）

把"长什么样"从课里拿出来，变成数据：调色板（浅色和深色）、**名词表**（墙 = 赭石、速度 = 青绿、计划/代价 = 钴蓝、终端集 = 翠绿、
î = 翠绿、ĵ = 朱红……同一个东西在所有图、所有课、正文里都是同一个颜色）、角色的材质（真值实心、猜测空心、预测虚线、
起作用的约束加粗、区域是名词的淡色）、系统字体栈、四档字号（标签、正文、读数、大号读数）、间距、运动意图（显现、移动、生长、画出……弹簧或慢进慢出）、
排版规则（手机阈值 560 px、最小字号 12 px、最小点击区 44 px）、品味规则（一屏最多一个朱红动作、对比度 4.5:1、图里不写"请拖动"）。
`text_color_of` 把名词的颜色加深到对比度够的程度，所以字和线是同一个色相。改外观只改这个文件，课一行不动。

### 1.2 新包 `@mathnim/engine`（内核，3184 行，压缩后约 62 KB / gzip 23 KB）

| 文件 | 做什么 |
|---|---|
| `state.ts` | 参数和派生值，自动记录依赖；派生值只在它读过的东西变了才重算；全局写入通知（播放器靠它"有变化才画"） |
| `thing.ts` | 每个东西有 id、种类、角色、一句"它是什么"；注册表 |
| `text.ts` | 系统字体，设备上实测字宽；中文断行规则（句号不打头、左括号不收尾、英文单词和数字带单位不拆）；`[墙](noun:wall)` 让正文里的词用名词色 |
| `tex.ts` | MathJax 排一次，缓存成 Path2D，任意字号任意颜色画；保留 `\color` |
| `layout.ts` | 规则化流式排版：并排、上下、网格；按宽度定高度；手机上行变列；优先级（主图最后才缩）；可让位的旁注；**贴附标签**按代价选位置（压到什么、出界多少），每个东西记下"为什么在这里" |
| `kinds.ts` | 文字块、列表、读数（等宽数字，放不下时按字号表降一档）、图例（条目可以随它说的东西淡入）、坐标图（含向量平面、只有 x 轴的轨道、填满格子）、路径（可"画出来"）、区域、标记、点集、箭头、自画标记、贴附标签、玻璃手柄、画布块（逃生口） |
| `script.ts` | 脚本是时间的纯函数：弹簧的闭式解，跳到任何时刻都精确；`beat()` 是旁白的一个 §；每一步记成一行字（工具按节打印） |
| `render.ts` | 只画变了的：一段时间没变的东西画进缓存层（背景也烘进最底层），变的才每帧画；什么都没变就不画 |
| `gpu.ts` | GPU 场：WebGPU（先自测，画不出就不用）→ WebGL2 → CPU（半分辨率），三档同一个公式；软件 GL 当作没有 GPU |
| `figure.ts` | 一张图：参数、东西、排版（宽屏和手机可以各有组合）、脚本、手柄、报告、不变量；`lint()`、`describe()`、`explain()` |
| `player.ts` | `FigurePlayer`：和 `ScenePlayer` 一样的接口；画布按显示尺寸 × 设备像素（最多 2）画；手机上图多高舞台就多高；指针和方向键拖手柄；`FigureUI` 给探索步 |
| `node.ts` | 在 node 里用：画布、`lint_figure`（两个尺寸 × 每节结束）、`render_figure`、`node_player` |

### 1.3 接缝（让站点同时认两种图）

- `@mathnim/core` 新增 `stage.ts`：`make_player`、`make_ui`、`release_player`、`sketch_figure`。运行时、课的类型（`Stage = Scene | Figure`）、世界都改成两种都认。
- `@mathnim/present`：课的页面、正文里嵌的图、导出视频、开发者面板都认 `FigurePlayer`；新图的玻璃手柄自己就是可拖的提示，不再叠一层提示层；
  舞台 CSS 支持"按图的高度长高"；深色设置时新图用深色外观。
- `@mathnim/ai`：导师选的图可以是新图（`load_visual` 用 `make_player`），面板里的"重放、探索"也认。
- `@mathnim/visuals`：`define_figure` 把新图登记进同一个目录（课、导师、工具一视同仁）；`figure_lang`：新图跟页面语言走，不用等中文字体下载。
- 应用：首页封面动画、学生上下文（给导师看的"屏幕上有什么"用 `describe()`）、构建的属性名混淆包含新包。

### 1.4 移植的图

| 图 | 用在 | 新图里变了什么 |
|---|---|---|
| `mpc_qp_plane` | M4 讲解（画面 21.7 秒，配旁白 33 秒，5 个 §）和探索 | 代价碗由 GPU 场画（等代价椭圆是它的等值线）；三类限制各用名词色（电机墨、速度青绿、墙赭石）；图例在图外、随线淡入；手机上拖动面板紧挨着它改变的平面；小车和轨道是 MPC 的引擎套件 `mpc/track.ts` |
| `mpc_shift_tail` | M6 正文里的图 | 三步说明用名词色点出"计划""终端集""一步刹车"；手机上说明排到图下面 |
| `determinant_area` | 线性代数的讲解和探索 | 平面填满格子、单位长度相等；被 A 移动的网格是钴蓝；平行四边形和说明按行列式的状态变色（缩放赭石、压扁朱红、翻转紫）；矩阵的两列用 î、ĵ 的颜色 |
| `training_curves` | 微调 B3 的两道看图题 | 两个小图在手机上也并排（同一个 epoch 对着看）；曲线是"画出来"的；字换行不缩小 |
| 草图题（新） | 微调 D2a 的 `baseline-sketch` | 原来没有场景的草图题会崩、画区还被藏起来（旧版本身的 bug，冒烟测试发现）；现在自动给它一张坐标图来画 |

### 1.5 工具

- doctor：新图在宽屏 960×540 和手机 360 宽、每一节结束时 lint；探索步无头跑 `solve()`。
- `npm run check -w @mathnim/visuals`：新图的手柄拖到取值范围的四个角再 lint，量拖动一帧的耗时，联系表里带手机版。
- `beats.mjs`（旁白对时）、`snapshots`、`thumbnails` 都认新图。
- 新增：`smoke_lessons.cjs`（每节课每一步走一遍、截图）、`smoke_compare.cjs`（前后逐步对比）、`perf_steps.cjs`（打开、播放、跳转、静止、拖动的耗时）、`packages/engine/tools/profile_drag.mjs`（拖动一帧的时间花在哪）。

### 1.6 检查、对比和审阅发现并修掉的问题

**新加的检查自己发现的**

- 一个读数在 640 px 宽的舞台上放不下 → 加了"按字号表降一档"的规则。
- 一列放不下全部东西 → 加了"旁注让位"（`optional`）。
- 我自己写错的不变量（截断的计划违反速度限制时代价可以更低）→ 改成只比较守住限制的截断计划。
- 拖动一帧 19 ms（CPU 档场 14 ms + 每帧全屏背景）→ 背景烘进缓存层、场半分辨率、软件 GL 不当 GPU：6.4 ms。
- WebGPU 在无头浏览器里拿得到设备却画不出来（整张画布变白）→ 先自测再用。

**和旧版逐帧对比发现的（在旁白的同一时刻截图，左旧右新，见 `engine-shots/compare-*.png`）**

- 给了时长的动作没有铺满时长（弹簧提前停住再干等）；四张图用了外观表的默认时长而不是原来的，画面和录好的旁白对不上
  （行列式原来 21.9 秒，被做成 18.4 秒）→ 现在逐步照搬原来的顺序和时长（21.7 / 21.9 / 4.2 / 8.2 秒，和原来一样），长距离移动慢进慢出。
- 少了动画：网格和线自己画出来、î ĵ 从原点长出来、压扁那一下的闪烁 → 补回。
- 少了内容：行列式下面不动的参考网格、行列式按正负变色、小车静止时的 v₀、可行区域要等限制出现才露出 → 补回。
- **一个正确性错误**：M6 的终端集 X_f 画到了 v = 2 以上，还是个自交的多边形 → 改回 p + 1.95 v ≤ 10、v ≤ 2，并让图自己检查这一条。
- 速度标签压在箭头、旗子、墙上；参考网格溢出到右边文字栏 → 修好。

**代码审阅发现的（9 条，全部修好）**

- 学习者在一张新图还在加载时就翻到下一步，这个播放器没有被释放，之后窗口一变大小它就把旧图画到新步上 → 释放。
- 导师在一张还没放进页面的画布上建图，新图按 1280 px 排版、再缩小显示（字又变小了）→ 画布本身也被观察，放进页面后按真实宽度重排（实测 1280 → 420）。
- 画布像素可能是奇数，导出 MP4（H.264）会失败 → 一律取偶数。
- 引擎的双语函数 `t(中文, 英文)` 和课里已有的 `t(英文, 中文)` 顺序相反，容易填反 → 统一成英文在前，并加了测试（英文图里不能出现中文、中文图里必须有）。
- 缓存层每次重建都新建整张画布；场每帧新建缓冲区 → 复用。
- 一个重复的工具函数、一处有副作用的测量、几行无用代码 → 清掉。

## 2. 新架构的结构

```
@mathnim/look            外观表（数据）：调色板、名词、角色材质、字体、字号、间距、运动意图、排版和品味规则
      │  读
@mathnim/engine          内核
  state ── 参数、派生值（依赖追踪）、写入通知
  thing ── 东西 = id + 种类 + 角色 + 意思；注册表
  layout ─ 并排 / 上下 / 网格 / 贴附 + 标签避让 + explain()
  kinds ── 文字、读数、图例、坐标图、各种标记、手柄、场、画布块
  script ─ 意图 → 弹簧；beat = 旁白的 §；时间的纯函数
  render ─ 依赖追踪的脏检查 + 缓存层；没变就不画
  gpu ──── WebGPU / WebGL2 / CPU 三档的场
  figure ─ 把上面装成一张图：lint / describe / explain / check / report
  player ─ FigurePlayer（和 ScenePlayer 同一个接口）+ FigureUI
      │
@mathnim/core            stage.ts：make_player / make_ui（Scene 或 Figure）；运行时、世界、课的格式
@mathnim/present         课的页面：两种播放器都认；舞台按图长高
@mathnim/visuals         define_visual（Manim）和 define_figure（新内核）登记进同一个目录
@mathnim/ai              导师选图、画图，两种都认
apps/mathnim             站点和工具（doctor、check、beats、smoke、perf……）
manim-web                不动；旧图继续用它（"方言"），新图只借它的 MathJax
```

一帧怎么出来：参数变了（脚本、手柄、世界的 `solve()`、导师）→ 写入通知让播放器排一帧 → 渲染器看每个东西读过的参数有没有变 →
没变的从缓存层贴上去，变了的重画 → 排完东西后放贴附标签（避开刚画好的东西）→ 什么都没变就整帧跳过。
跳到某个时刻：脚本从起点算出这一刻每个参数的值（闭式弹簧），不用从头模拟，所以多远都一样快。

那 27 步都在**没有改动**的课里，逐个截出差异区域看过：

- 10 步是选择题的选项顺序不同：每次打开页面选项都会随机打乱。
- 1 步是随机出的变式题不一样（球门柱 3 m / 12 m 和 4 m / 9 m）。
- 7 步是右边导师面板的提问建议正在淡入，截图那一刻不透明度不同。
- 9 步是截图时场景还在自动播放（截到了 0:00 和 0:01 两个不同时刻），包括 pizza 的 6 步、`eigen-pca/moves`、`best-angle/reveal`、`mpc-m3-cost/gain-horizon`。
  这 9 步又在两个版本上暂停在结尾状态、逐像素对比了一遍：**全部 0.000% 不同**。

所以没有移植的部分，电脑版和重构前完全一样。

**移植的图和原来的对比（电脑版）**

在旁白的同一时刻对旧版和新版截图，左右并排（`engine-shots/compare-qp.png`、`compare-det.png`、`compare-tc.png`），结果如下：

- **一样的**：
  - 总时长（M4 21.7 秒、行列式 21.9 秒、训练曲线 4.2 秒、M6 图 8.2 秒）；
  - 每一节里东西出场的顺序和时间，每个时刻的状态和数值（例如第 28.5 秒两边都是 a₁ = −0.33、a₂ = −0.84、墙起作用）；
  - 动画（网格和线画出来、箭头长出来、压扁时的闪烁）；
  - 内容（参考网格、按正负变色、v₀ 读数）。
- **刻意不一样的**：
  - 图例在图外，不再压在数据上；
  - 颜色按名词：速度青绿、墙赭石。旧版是速度金黄、墙朱红，限制线还用虚线区分；
  - 文字用系统字体，大小统一用外观表的字号。旧版逐笔"写出来"的文字效果改成淡入；
  - M4 平面上加了淡淡的代价碗底色，训练曲线加了 epoch 刻度。

  这些就是第 2 节诊断里要改的排版问题。如果其中哪一条要回到旧版的样子，只改外观表或那一张图。

**交互验证（在真实页面里做的）**

- 生产包里用鼠标拖 M4 探索步的手柄：状态跟着动，世界的第一个目标达成，拖动时画了 15 帧，松手以后 0 帧。
- 导出视频：新图导出成 MP4（1.8 MB），可以播放。
- 草图题：在新的坐标图上用鼠标画出曲线（采到 49 个点），可以提交。
- 中文：四张图在中文下用系统字体显示，不用下载中文字体，换行符合中文规则。
- 导师面板：在页面外建的新图，放进 420 px 宽的卡片后会按 420 px 重新排版。

## 4. 性能评估

**怎么量的**：旧版（重构前的提交 `e0c01e4`）和新版各打一个生产包（压缩、混淆，和线上一样），在同一台机器、同一个无头
Chromium（软件 GPU）里打开同一节课的同一步。桌面 1440×900，设备像素比 2。每一步依次量：

- 打开：从进入这一步到图能画；
- 播放：沿整条时间线逐帧计算并画出来；
- 跳转：随机跳 40 次；
- 静止：停在结尾、开着实时模式 2 秒，每秒真正画了几帧；
- 拖动：连续 60 个状态变化，每个后面画一帧。

不降速和用 Chrome 把 CPU 降速 4 倍（相当于慢手机）各量一次。表里是 95 分位，箭头左边旧、右边新。
"M4 显式 MPC"这一步没有移植，新旧两边都是旧引擎，当作对照组：它前后的差别就是测量噪声（大约 ±15%）。

**读法**

- **打开快 3–16 倍**：旧播放器打开一步时要先把整段动画录一遍（每一段存一份快照）；新图只建状态、排一次版。
- **跳转快几十到几百倍**：旧版跳到某一刻，要从那一段的快照开始往前模拟；新版的脚本是时间的纯函数，跳到哪儿都只算一帧。
  拖播放条、导出视频、旁白对时都受益。
- **静止时不画**：旧版的实时模式每秒画 35–60 帧（哪怕什么都没动）；新版没有变化就一帧都不画。探索步里学习者停下来想的时候，CPU 和电量都不花。
- **降速 4 倍时，每一帧都在 16 ms 以内，只有 M4 探索步例外**：它的播放帧 19.6 ms、拖动一帧 18.9 ms（旧版 34 ms、41 ms）。
  这台机器没有真 GPU，M4 的代价碗走的是 CPU 档；真机上它走 WebGL2/WebGPU，会更快。
- **内存**：打开 M4 讲解后整个页面的 JS 堆，旧 134 MB、新 25 MB（旧版存了整条时间线的快照）。对照组前后一样。
- **画布像素**：旧版永远是 1920×1080；新版按显示尺寸 × 设备像素（这里 984×554 × 2）。像素数差不多，但新版的字和线是按真实尺寸画的。

**一张图的检查有多快**（node 里建图 + lint，四张图，每种语言一次）

| 图 | 旧（录制 + 时间线 lint） | 新（建图 + 宽屏和手机两种尺寸、每节结束时 lint） |
|---|---|---|
| mpc_qp_plane | 3.7 s / 2.7 s | 0.18 s / 0.07 s |
| mpc_shift_tail | 0.27 s / 0.17 s | 0.04 s / 0.01 s |
| determinant_area | 2.6 s / 2.5 s | 0.03 s / 0.01 s |
| training_curves | 0.10 s / 0.06 s | 0.008 s / 0.007 s |

新的检查查得更多（两种尺寸、每一节），用时却是原来的 1/10 到 1/80。整个 doctor（229 项）：重构前 3 分 08 秒，现在 3 分 05 秒（它的大头是没移植的旧图）。

| 全部 JS（gzip，含按需加载的课程包） | 3247 KB | 3275 KB |

内核的预算是 150 KB，现在 23 KB（gzip）。旧引擎还在（渐进替换），所以总量多了一点而不是少了。

**量的过程中发现并修掉的**：最初一轮里，新版 M4 讲解有少数跳转要 2 秒多。追下去是 CPU 档的场往 GPU 画布里
`putImageData` 时，要等忙着的 GPU 进程同步，会卡住。改成把这张小画布放在内存里（`willReadFrequently`），只把画好的小图交给 GPU。
改完以后 4 倍降速下跳转的 95 分位从 2400 ms 降到 12 ms。

**没量的**：手机（按你的要求先不管）；真 GPU 的 WebGL2/WebGPU 档（这台机器只有软件 GPU）；真机上的耗电。

## 6. 没做的、已知的问题、下一步

**没做的（按 `ENGINE.md` 第 13 节的阶段）**

- 第 3 阶段的一半：玻璃、液态代数、套索这些界面材质还没移植进内核（实验室里的版本还在 `docs/design/gpu/`）；导师还不能"在图里动手"。
- 第 4 阶段：Manim 方言没有接到内核上。现在是两条路并行（`make_player` 按图的种类选），旧的 60 张图照旧走 manim-web。
  一门课一门课迁移时，旧路径继续能用，直到没有东西用它。
- **读屏用的 DOM 镜像**没做：新图的字画在画布上，`describe()` 已经能给出每个东西的位置和意思，下一步把它变成画布上方的
  无障碍层（可选中、读屏能读）。
- 基准测试（新 agent 用旧接口和新接口各做 5 个任务）没做；"做课效率"的数字只有代码统计和工具耗时（第 5 节）。

**已知的问题**

- 新图的代码行数和旧图差不多（M4 215 行对 219 行；旧图另外靠一个共用的 `PlanPlane` 类，新图靠 90 行的轨道套件）。
  省掉的是手放的坐标、字号、颜色和手机适配，不是行数。要到三分之一，需要更高层的套件（比如"约束平面"本身做成一种东西）。
- 中文字体：新图不需要下载字体了，但站点在切到中文时仍然会下载 1.6 MB 的 Noto Sans SC，因为旧图还要用。全部移植后才能去掉。
- 标签避让在很挤的地方（M4 平面上"不管限制"那个标签在 × 正好被线和点围住时）只能选"压得最少"的位置，lint 记为警告。
- 拖动一帧在慢 CPU（降速 4 倍）上的 95 分位见第 4 节；大头是 CPU 档的场。真 GPU 上场是 WebGL2/WebGPU，这台机器测不到。
- `dock.test.ts` 有一个数值测试在机器满载时会超过 vitest 默认的 5 秒（单独跑 2.4 秒）；和这次改动无关，没改它的超时。
- WebGPU 档：在这台机器（无头、软件 GPU）上自测不过，所以没有量到 WebGPU 的数字；真机上它和 WebGL2 是同一个着色器公式。

**下一步（建议顺序）**

1. 用这次的套件再移植 M4 的另外两张图（`active_set`、`solver_paths`，它们共用 `PlanPlane`），把"约束平面"做成一种东西，量代码行数。
2. DOM 镜像（无障碍）和 `describe()` 接到导师的上下文里（导师已经能读到新图的描述）。
3. 把实验室里的玻璃、液态代数做成内核的插件（`ENGINE.md` 第 8 节），在一张移植的图里用上。
4. 基准测试：5 个任务，旧接口对新接口。
