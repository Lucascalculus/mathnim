# Mathium 引擎重构：架构设计（待确认稿，2026-11-03）

本文把这几轮讨论定下来的东西写成一份可以逐条确认的设计。凡是写着 **【已定】** 的是 Lucas 已经拍板的；
写着 **【建议默认】** 的是我的建议，Lucas 没有反对，但需要在第 13 节确认。

判断一切的四个标准（Lucas，2026-11-03）：

1. **可扩展性**：库会每天升级（设计、排版、新物件的审美、新动效、新选项），课和核心都不能因此变脆。
2. **新 agent 做课时的可读性**：一个没有上下文的 agent 能很快读懂、写对。
3. **做课效率**：从想法到一张能上线的图，轮数少、检查快。
4. **渲染效率**：在学校的旧电脑和手机上也流畅，静止时不耗电。
5. **自由度**（Lucas，2026-11-03 补记："自由度是我们之前的标准之一"，"把自由度留够"）：规则是默认值，不是笼子。
   manim 能画的，新图都要能画；每条规则都有覆盖的办法（样式、手放的标签、精确摆放、自己画），覆盖被 lint 报告为警告，
   不被阻止。

## 0. 决定记录

| 事项 | 结论 |
|---|---|
| 预渲染首帧 | **【已定】不做** |
| 自适应画质（帧慢就降分辨率） | **【已定】不做**。设备档位在启动时测一次，之后固定 |
| 贵的计算放哪 | **【已定】构建时烘焙**（规则见第 7 节） |
| 排版 | **【已定】规则化流式排版**：并排、上下、网格、贴附，加标签避让，加 `explain()`；**不做通用约束求解器** |
| WebGPU | **【已定】做**，作为 GPU 层的第二个后端 |
| 中文字体 | 用系统字体（第 5 节），不再下载 1.6 MB 的 Noto Sans SC |
| 改造方式 | **【建议默认】** 新内核在下，Manim 作为上层方言，逐门课迁移（不推倒重写） |
| 包的边界 | **【建议默认】** 新包 `@mathnim/engine`（内核）和 `@mathnim/look`（外观表）；manim-web 变成内核上的一层 |
| AI 写什么 | **【建议默认】** 继续能写 Manim 方言；新增"图的数据描述 + 材质动作"两种结构化输出，逐步以它们为主 |
| WebGL | **【建议默认】** 2D 画布是必须能跑的底；WebGL2、WebGPU 都是增强 |
| 手机 | **【建议默认】** 手机有自己的排版（由同一套关系算出），不再把 16:9 缩小 |
| 基准测试 | **【建议默认】** 在写内核之前先搭好"新 agent 做课"基准，之后每个选择都拿它衡量 |

## 1. 现状（量过的）

- `manim-web` 约 3.4 万行，是 Manim Community 0.21 的移植：2D 画布、录好的时间线、可 seek。
  规则是"接口和 Manim 一样，看起来像真 Manim 才算对"。交互后来加在 `ext/`（已 4700 行）。
- `visuals` 约 2.5 万行、100 个可视化文件，中位数 225 行（p90 386 行）。代码大部分是手摆坐标：
  `mpc/shift_tail.ts` 里说明文字的坐标是手敲的（`RX = 1.8`，y = 2.0、1.2、0.4……），`.name = …` 手写 9 次，颜色每次单独挑。
- 每门课有自己的工具包（光 `mpc/kit.ts` 就 720 行），`label()` 这类函数在 `ft/d`、`ft/e`、`ft/f` 的工具包里各写了一遍。
- 290 处 `always_redraw` / `add_updater`：可交互的图每一帧重建对象；相机不缓存没变的部分。
- 舞台固定 16:9，手机上整体缩小。
- 场景里的文字是 opentype.js 解析字体文件后画字形轮廓，所以中文必须下载 Noto Sans SC（约 1.6 MB）。
- 新 agent 写图之前要读约 1900 行文档（CAPABILITIES、PLAYBOOK、DEVELOPMENT、EXTENSIONS、visuals README、课程工具包）。
- AI 导师生成场景代码时写的是 Manim（`packages/ai` 里有一份由代码生成的 API 摘要），这是要保留的资产。

## 2. 现在的排版为什么差（MPC 第 4 课"两步计划"那一屏，2026-11-03 截图）

截图：`docs/design/engine-shots/m4-desktop-now.png`（1440×900）和 `m4-phone-now.png`（390×844）。复现：`npm run dev` 后打开 `/mpc/mpc-m4-constraints` 第 4 步，播放到结尾。

**手机**
- P1. 16:9 的画面被缩到约 365 px 宽：画布里的字只有 5–7 px 高，读不了；小车、把手很小，点击区远小于 44 px。
- P2. 画面下面空着半个屏幕，图没有用到高度。
- P3. 本该上下排的两个面板，仍然左右并排。

**桌面**
- D1. 图例画在数据区里，压着网格线；"no limits"标签压在椭圆和虚线上。没有标签避让。
- D2. 标签和它说的东西没有关系："the cart's state now"飘在坐标轴标题旁边；读数 a₁、a₂ 和单位 m/s² 散在顶部，单位离数字很远。

- D5. 四层小字互相抢：画布里的图例和说明、画布里的"Show the full text"、画面下的脚注、再加播放条。
- D6. 字体混用：数学标签是衬线，说明是无衬线，画面里能看到六种以上字号。

**页面**（不属于引擎，属于 `present`）
- G1. 阅读卡片高度固定、下面留白；"Ask"框的点阵边框和裁切角和正文抢注意力；课程底栏和播放条叠在一起。

## 3. 总体结构

```
apps/mathnim ─ 产品：课程、页面、学习者、AI 服务端
   │
   ├── @mathnim/present   课的页面（阅读页、讲解、游戏），CSS + DOM；只读外观表
   ├── @mathnim/ai        导师：文字、图的数据描述、材质动作、（沙箱里的）Manim 代码
   ├── @mathnim/core      课的格式、运行时、世界与检测器、学习者模型（不变）
   │
   ├── 插件包  @mathnim/kit-mpc、kit-ft、kit-linalg …   领域里的东西、图块、排版与模拟插件
   ├── manim-web          Manim 方言：老场景和 AI 写的 Manim 代码在内核上运行（保留 golden 测试）
   │
   ├── @mathnim/look      外观表（纯数据）：颜色、字号、间距、角色→材质、意图→动效、排版规则
   └── @mathnim/engine    内核：六件事（第 4 节）
```

依赖只向下。内核不认识课、星星、AI；插件不改内核；外观表里没有代码。

## 4. 内核：只做六件事

内核设行数预算（目标不超过一万行），CI 统计，超了报警。

### 4.1 状态与派生

```ts
const A = param.matrix([[1, 0], [0, 1]], { range: [-3, 3] });   // 有类型、有范围的参数
const grid = derive(() => apply(A.value, base_grid));           // 派生值：用到谁就依赖谁
```
- 参数变了，只按依赖图重算依赖它的派生值，按拓扑序一次算完，不会出现半新半旧的中间态。
- 一切确定：没有隐藏状态，所以任意时刻 `at(t)` 都能精确重现，`inspect(t)` 打印那一刻全部参数和派生值。
- 状态可序列化（以后可做分享链接、回放学生的探索）；格式带版本号。
- 取代现在 290 处 `always_redraw` / `add_updater` 的每帧重建。

### 4.2 东西：有身份、有角色

```ts
const wall = plane.halfplane(g, b, { id: 'wall', role: 'noun:wall', says: t('墙', 'wall') });
```
- 每个东西有 `id`、`kind`、`role`（材质语法里的角色）、`says`（一句话描述，给读屏、给 AI、给 `describe`）。
- **注册表**：页面上所有东西（包括正文里的词、公式里的符号）都能按 id 查到它的框和含义。
  刷选、把名词拿出来、套索提问、导师的光、无障碍，都建在它上面。
- 写课只写角色，不写颜色、线宽、虚实。长什么样由外观表决定。
- 角色是一个小而固定的词汇（名词 `noun:*`、`truth` 真值、`guess` 猜测、`predicted` 预测、`ghost` 影子、`glass` 手的位置、`verb` 唯一的朱红动作、`scaffold` 脚手架……），
  新角色只能通过外观表加入并经过审阅。

### 4.3 排版：规则化流式排版 【已定】

只有四种关系，加标签避让，加解释。**不做通用约束求解器。**

| 关系 | 写法 | 例子 |
|---|---|---|
| 并排 / 上下 | `row(a, b)`、`column(a, b)` | 图和说明并排；手机上自动改成上下 |
| 网格 | `grid([...], { cols })` | 多个小图 |
| 贴附 | `attach(label, to, side?)` | 标签贴在墙上；单位贴在数字后；读数贴在它的东西旁 |
| 放进 | `inside(plot, thing)` | 数据坐标里的东西 |

- **按设备出方案**：同一套关系，桌面一种排法、手机一种排法。规则（何时并排改上下、最小字号、最小点击区）写在外观表里。
  特别密的图可以用 `variant('phone', …)` 单独写手机版，这是逃生口，不是常态。
- **标签避让**：贴附的标签按优先级在候选位置里选（右上、右、上、左……），避开线、点、别的标签和数据区；
  图例默认放在数据区外（`legend: outside(plot)`）。实在放不下就用引线，并在 doctor 里报出来。
- **空间分配**：按内容的重要性分配面积（角色 `primary` 的图比 `secondary` 大），不再平均切。
- **`explain(thing)`**：说明一个东西为什么在这里，例如
  「wall 的标签：贴附在 wall 的右上；右侧被图例占用，改到上方；距离 0.3 em 来自外观表 `label.gap`」。
  agent 和人都能据此改，而不是猜。
- **文字在运行时量**：因为用系统字体（第 5 节），不同系统字宽不同，所以排版永远在设备上按实测字宽计算；
  烘焙（第 7 节）不包括文字排版。
- **字号只有三档**：图里只用 `label`（标签）、`caption`（说明）、`readout`（读数）三档，数值在外观表里。

### 4.4 时间：脚本、弹簧、意图

```ts
return script(
  reveal(plane, cost),           // 意图：出现
  beat('墙'), reveal(wall),      // 等旁白说到"墙"再出现
  converge(opt),                 // 意图：收敛（空心→实心）
  hold(),
);
```
- 一个确定的时钟。旁白、音频、模拟、回放都挂在它上面。
- 脚本只设目标；弹簧（SwiftUI 式的 response / damping，打断时保留速度）负责追过去，所以任何动作都可打断。
- 写意图，不写曲线：`reveal`、`converge`、`emphasise`、`settle`、`travel`……意图对应的动效参数在外观表里。
- `beat('词')` 对齐旁白的逐词时间戳；画面比声音长就等，短就延。现在单独的 `beats.mjs` 检查并入 doctor。
- 静止时不请求帧，不在视口里的不画。
- 系统开"减少动态效果"时，弹簧直接到位、粒子成形改为淡入（每种动效在外观表里有减弱版）。

### 4.5 检查：不变量、预算、品味

```ts
figure({ … , checks: [area_equals_det, contrast_at_least(4.5)], budget: { frame_ms: 16 } })
```
- **不变量**写在东西和图自己身上（和材质实验室里的 `accept()` 一样）。
- **doctor** 在无头浏览器里跑：每张图 × 桌面/手机 × 中/英，返回截图和失败项。
- **品味 lint** 报错时给出改法：「这屏有 2 个朱红元素……改为 `role: 'secondary'`」「数字用了 graphite，灰色会被读成不可用，改为 ink」「『请拖动滑块』是指令式文案，删去」；
  另查：字号小于 12 px、点击区小于 44 px、重叠、行首标点、文字溢出、硬编码颜色、硬编码坐标。
- **性能预算**：降速 4 倍的手机档上，交互图 95 分位帧时间小于 16 ms；静止时 0 帧；预算超了和画错一样判失败。
- **增量检查**：每次改动只跑依赖图上受影响的图；每晚全量。
- **两层对比**：结构对比（`describe` 的文字：有什么、在哪、什么角色，快、无噪声）+ 像素对比（抓渲染问题）。

### 4.6 渲染：只画变了的

- **保留式场景图 + 脏标记**：没变的部分画一次存成一层，反复复用。
- **三层，一个合成器**：
  - **2D 画布**：必须有，所有东西都要能在这里画对；
  - **WebGL2**：增强（玻璃、水、光粒、真实材质）；
  - **WebGPU**：【已定】做，作为第二个 GPU 后端，带计算着色器（FFT、流体、十万粒子更快更好写）。
- GPU 层抽象成"计算 + 绘制"两类接口，插件写一次。启动时测一次设备能力（有没有 WebGPU / WebGL2、粗测帧时），选定档位后固定（不做自适应画质）。
- **一个页面一个 GPU 上下文**，用裁剪区画多张图（实验室里撞到过浏览器的上下文数量上限）。
- 粒子和重复标记用实例化；重的模拟放 worker 或 GPU。
- **文字不进几何**：正文、标签、公式不转成轮廓，由浏览器的文字引擎用系统字体画（实现：2D 画布的 `fillText`，按设备实测字宽排版；见第 5 节和第 15 节）。

## 5. 文字与字体：用系统字体 【已定方向】

**能用。**办法是不再自己解析字体文件画轮廓，而是交给浏览器的文字引擎：

- **正文、标签、说明**：2D 画布的 `fillText`（已实现；读屏用的 DOM 镜像是下一步），字体栈
  - 黑体：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", sans-serif`
  - 宋体：`"Songti SC", "STSong", "SimSun", "Noto Serif CJK SC", serif`
- **数学公式**：保留 MathJax（自带的拉丁数学字体很小），构建时把课里的公式排好缓存。
- **需要字形形状的效果**（液态代数、光粒成字、语义缩放）：在设备上把系统字体画到画布，再算 SDF（实验室 `lib/sdf.js` 已验证），按页缓存。

代价，以及怎么处理：

| 代价 | 处理 |
|---|---|
| 不同系统字形和字宽不同（PingFang 和微软雅黑宽度不一样） | 排版永远在设备上按实测字宽算；栏宽留 8% 余量；lint 查溢出 |
| 部分安卓没有中文宋体 | 宋体回退到黑体，可以接受 |
| doctor 在 Linux 上跑，截图用 Noto CJK，和 Mac 不同 | 像素基准按平台存；关系类检查（不重叠、不溢出、对比度）与平台无关 |
| 画轮廓的 Manim `Write`（逐笔画出）不能用于系统字体 | 换成我们自己的出现方式（墨的扩散、成形），符合"做我们自己的" |
| Manim 方言的 golden 测试依赖 Tinos/Arimo | 只在方言层保留这些拉丁字体，主站不用 |

结果：中文用户不再下载 1.6 MB 字体，首屏更快；字永远清晰、可选中、读屏能读。

## 6. 写课接口（给 agent 读的那一层）

### 6.1 一张图长什么样

以 `mpc/shift_tail.ts` 为例，从约 120 行降到 35 行左右：

```ts
export default figure({ params: { N: int(3, 12, 8) } }, ({ N }) => {
  const d = shift_tail_data(N);
  const plane = plot({ x: [5.8, 9.2], y: [0.6, 2.25], x_label: 'p', y_label: 'v' });
  const xf = plane.region(terminal_set, { role: 'noun:terminal-set', label: tex('\\mathcal X_f') });
  const plan = plane.path(d.plan, { role: 'predicted' }), tail = plane.path(d.plan.slice(1));
  const next = plane.path([d.plan.at(-1), d.next], { role: 'noun:terminal-set' });
  const steps = column(beside(plane), [
    t('1. 时刻 k 的计划，终点落在终端集里', '1. the plan at time k ends in the terminal set'),
    t('2. 到 k + 1：保留它的后半段', '2. at k + 1: keep its tail'),
    t('3. 末尾补一步刹车', '3. append one braking step'),
  ]);
  return script(reveal(plane, xf), reveal(plan, steps[0]), reveal(tail, steps[1]), reveal(next, steps[2]), hold());
});
```

没有坐标、没有颜色、没有 `.name`、没有手工换行；手机排版、标签位置、字号都不用写。

### 6.2 写课的规矩（lint 强制）

- 课和图里**不出现**十六进制颜色、像素或场景坐标（数据坐标除外）、字号、手工换行。
- 文字一律 `t('中文', 'English')`，中文写原生的中文。
- 每个东西有 `id`；能被讲到的东西有 `says`。
- 一张图必须有 `examples`（参数样例，含边界情况），每个样例都跑检查。

### 6.3 agent 读什么

- **一页参考**（约 300 行），从代码自动生成：每种原件一段说明、一个例子、一张截图。
- **目录**：`npm run catalog -- 分布` 按含义查现成的东西、图块、插件（AI 用同一份）。
- **最近的变化**：每次升级生成一条给机器读的变更记录，开工前读。
- `describe(figure)` 打印屏幕上有什么，改别人的图之前先看它。

### 6.4 对第 2 节每一条排版问题的回答

| 问题 | 新系统怎么解决 |
|---|---|
| P1 手机上字 5–7 px、点不到 | 文字按真实字号用系统字体画（画布按 CSS 尺寸 × 设备像素绘制）；最小字号 12 px、点击区 44 px 由引擎保证，lint 查 |
| P2 手机下面空半屏 | 图按可用高度排版（规则 `fit: available`），不再锁 16:9 |
| P3 该上下排的并排 | `row` 在手机上自动变 `column` |
| D1 图例压图、标签压线 | 图例默认在数据区外；标签避让 |
| D2 标签和东西没关系 | 一切文字 `attach` 到它说的东西上；单位贴在数字后 |
| D3 空间分配不对 | 按 `primary` / `secondary` 分面积；一个点的图降为小图或并进主图 |
| D4 名词颜色乱 | 写角色不写颜色；同一个名词全站一种颜色，lint 查 |
| D5 四层小字 | 说明只有一个通道：页面里图旁或图下；画布里只留贴附在东西上的标签；脚注合并为一条 |
| D6 字体字号混用 | 图里只用三档字号；字体只来自外观表 |
| G1 页面卡片与问答框 | 属于 `present` 的页面 CSS，单独列为第 12 节的一项改造 |

## 7. 构建时烘焙 【已定】

**什么烘焙**：确定、贵、而且不随学生操作变化的计算。例如训练轨迹、长时间的模拟、大数据的预处理、公式排版。

**规则**：
- 烘焙的结果只在采样点上是真的。**绝不在采样点之间插值冒充真值**：滑块只能停在烘焙过的点上，或者现场计算。
- 可交互且便宜的：运行时算。可交互且贵的（流体）：GPU 实时算，并提供 2D 降级版。
- 烘焙产物是带版本的数据文件（输入参数 + 代码版本的哈希作为文件名），放在构建产物里，按需加载，有体积预算。
- 输入或代码变了才重烘；doctor 校验烘焙产物和现场重算一致（抽样）。
- 文字排版不烘焙（因为系统字体各设备字宽不同）。

## 8. 插件

### 8.1 新增一种东西

```ts
define_kind('soap_film', {
  props: { rings: [ring, ring] }, role: 'thing',
  draw2d: (g, s) => …,          // 必须：2D 画布上的画法（也是降级版）
  drawgpu: soap_film_gpu,       // 可选：WebGL2 / WebGPU
  hit: (s) => catenoid_outline(s),
  says: (s) => t('两环之间的皂膜', 'a soap film between two rings'),
  checks: [breaks_at_catenoid_limit],
  examples: [{ h: 0.9 }, { h: 1.3 }],
});
```
注册后自动进入目录、文档、doctor 和 AI 的目录，不改内核。同样的约定用于：图块（几种东西的组合）、排版插件（树、力导向图、时间轴）、手势（输入指针流，输出语义事件）、模拟、数据资源。

### 8.2 成熟度：实验 → 预览 → 稳定

新东西先进"实验"，样张页和目录里能看到，课可以主动选用；审阅通过后升为"稳定"，才进入 AI 的默认目录。

### 8.3 逃生口

任何图都可以自己画（原始 2D 画布或 GPU 着色器），条件是守住边界合约：交出框、露在外面的部件的 `id` 和角色、`says`、不变量、性能预算、2D 降级版。缺一项 doctor 判失败。

### 8.4 防膨胀

- 三次原则：同一种东西在三门课里出现，才提升为共享插件；进内核更严。
- 按需加载：一节课只下载它用到的插件。
- doctor 统计每个插件的使用量，长期为零的退役。
- 一个东西一个文件，插件按目录自动发现，没有需要手改的中央清单。

## 9. 外观层与每日升级

- **外观表是数据**（`@mathnim/look`）：颜色和名词颜色、字号三档、间距、角色→材质、意图→动效（含减弱版）、排版规则（断点、标签距离、最小字号和点击区）、品味 lint 的规则。
- **新选项只加不改**：默认值必须让输出和昨天一样。
- **改名、删除**：别名 → codemod 自动改写所有课 → doctor 清点剩余用量 → 为零才删。
- **变化对照表**：每次升级，doctor 全量对比，只列变了的图，前后并排，标出是哪条改动引起的，按"有意 / 意外"分类。Lucas 批准后才成为新基准。
- **预览通道**：`?look=next` 用明天的外观看真实的课；线上学生只看稳定版；部署只在 Lucas 说的时候。
- 每一版外观对应一个 git 提交，随时可退回。

## 10. AI 接入

- **Manim 方言**：manim-web 运行在内核上，`Scene.play(Create(x))` 翻译为脚本的一步，`always_redraw` 转为派生值。老的 67 个场景不改就能跑；翻译不了的老场景保留旧路径，用现有 golden 测试兜底。
- **图的数据描述**：AI 输出"用哪些东西、什么关系、什么脚本"的结构化数据，经同一份 schema 校验后直接渲染，不能弄坏排版。
- **材质动作**：导师的动作就是学生能做的操作（`set`、`raise_water`、`point_at`、`roll_from`……），只能指向注册表里存在的 id，服务器校验，每个动作进历史牌堆。
- 目录、API 摘要、schema 全部从注册表生成，从不手写。

## 11. 不做

- 预渲染首帧；自适应画质【已定】。
- 通用约束求解器【已定】。
- 物理引擎、模型和场景编辑器、通用 3D 引擎、通用图表库（需要时在插件里写最小版本）。
  3D 只提供最小视图：相机、深度、拾取（化学分子、机械臂、地球仪要用）。
- 用 Rust/WASM 写内核（只允许个别插件内部使用）。
- 站点界面（导航、底栏、岛）走内核：继续用 CSS 和 DOM，但读同一份外观表。
- 设计台只做外观表的数值面板和对单张图的覆盖，不做编辑器。

## 15. 实现记录（2026-11-03）

第 1、2 阶段已做，第 3 阶段做了一部分；量出来的结果和取舍见 `docs/design/ENGINE-REPORT.md`，写图的参考见
`packages/engine/README.md`。和上面设计不同的地方：

- **文字画在画布上**（`fillText` + 系统字体），不是 DOM。原因：一张图的标签要参与避让、要能导出视频、要在 node 里被
  doctor 检查，画在同一张画布上最简单；字宽在设备上实测，所以排版仍然是"按真实字体排"。读屏用的 DOM 镜像（`describe()`
  已经给出每个东西的位置和意思）留到下一步。
- **WebGPU 先自测再用**：拿到设备后先画一个 4×4 的画布读回来，不对就退回 WebGL2；软件实现的 GL（SwiftShader、llvmpipe）
  当作没有 GPU，走 CPU 档（半分辨率算场再平滑放大）。无头浏览器里 WebGPU 能拿到设备但画不出来，自测正好拦住了。
- **手机有自己的组合**：`fig.layout(宽屏, { phone })`，同一批东西换一种排法（比如把拖动的面板放到它改变的那张图正下方）；
  没写手机组合的图，行自动变列。
- 排版里加了三条规则（都来自检查发现的问题）：读数放不下时按字号表降一档；`optional()` 的旁注在放不下时让位；
  向量平面 `fill: true` 时保持单位长度相等并填满格子。
- 第 3 阶段里已做：角色与品味 lint、注册表、GPU 场（WebGPU / WebGL2 / CPU 三档）。没做：玻璃、液态代数、套索的移植，
  Manim 方言接到内核上（现在两条路并行：`make_player` 按图的种类选播放器）。
